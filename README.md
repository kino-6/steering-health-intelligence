# Steering Health Intelligence

電動パワステ(EPS)の**「故障と判定される手前の兆候」に価値があるか**を、公開情報だけで検証した個人研究のリポジトリ。

- **性格**: 個人の事業仮説研究であり、所属組織の業務ではない。**公開情報のみを使う**(内部情報・内部資料は使わない、入手経路も作らない)。最上位ルールは [AGENTS.md](AGENTS.md)
- **成果物**: 事業計画ではなく、**再現できる技術実証・検証の作法・文書群**という資産
- **セッション復帰**: [Memory.md](Memory.md)(現在地・読み順・観測台帳・禁止事項)
- **文書索引**: [docs/INDEX.md](docs/INDEX.md) / **進行表**: [Plan.md](Plan.md)

---

## 結論(先に3行)

1. **技術としては成立する。** 捕まえるべき現象は実在し、捕まえる仕組みは作れ、その情報は部品メーカーにしか取れない。そして**「故障未満の兆候」には実際に故障に先行する情報が乗っている**ことを、実個体約1,700万台で確認した(最大24.1倍)
2. **ビジネスとして「成立する」とは主張しない。** 成立し得る形(誰が・なぜ・どの通り道で払うか)は公開情報で組み上がったが、最後の一問(選定で有利か、あって当然のタダ要求か)は内部情報なしには閉じない。**ただし「今は金になるが時限の窓である」ことは、競合の行動・規制・先例という外部証拠だけで論証できる**
3. **個車の故障予測(残寿命・交換時期の予告)はKill済み。** 事前登録した合格基準に対し実証モデルが未達だった事実をそのまま残してある。以後の主張は「群統計の記述」と「不足の検出」までに限る

## 1. 技術として成立するか → **成立する**

証拠は5段で連鎖している。各段は独立のデータ源で、いずれも公開データのみ。

| # | 主張 | 数字 | データ源 | doc |
|---|---|---|---|---|
| ① | **現象は実在する** — 「故障コードが残らないのに一瞬アシストが抜ける」 | Ford 15V-340(米)、GM 17V-414(約1秒の喪失と突然の復帰、米)、Vauxhall Corsa D(英)の**3つの独立市場**で同じ故障ファミリー | リコール一次文書・TSB・車検統計 | [127](docs/127_steering_predictive_diagnostics_target_case_public_evidence.md) [129](docs/129_steering_predictive_diagnostics_public_case_crosscheck.md) [151](docs/151_high_rate_model_crosscheck.md) |
| ② | **捕まえる仕組みは作れる** — 60秒の走行データから故障判定に遠い微小変化を検出 | 誤検出6.7%で9割検出できる限界は**応答遅れ0.4秒 / 効き15% / 定常ずれ0.05 m/s²**。検出**できない**領域(遅れ0.1秒、効き2%)も同じ精度で報告 | comma.ai 公開走行log(MIT) | [144](docs/144_synthetic_sensitivity_results.md) [139](docs/139_log_sign_extraction_demo.md) |
| ③ | **外からは見えない** — だから部品内部を見る位置に独占性がある | 米国の苦情126万件を総ざらいしてもEPS系の前兆はほとんど見えない(PR-AUC 0.355 = 無情報の3.2倍にとどまる) | NHTSA 苦情DB / リコール台帳 | [143](docs/143_recall_detection_results_v2.md) |
| ④ | **偏在は車種×年式に集中する** | 英国車検**2,800万件**で操舵系不合格率は車齢3年0.11%→20年で約40倍。15,626モデル中**上位10モデルで不合格の50%**(Corsa単独16.6%)。ただし原因は「欠陥」と「用途起因の摩耗」の2型に分かれ、切り分けには故障モードが要る | 英国DVSA MOT(OGL v3.0) | [148](docs/148_dvsa_mot_denominator_verification.md) [149](docs/149_concentration_ev_and_japan.md) [151](docs/151_high_rate_model_crosscheck.md) |
| ⑤ | **閾値未満の兆候には、故障に先行する実情報が乗る**(本研究最強の実証) | 車検2年分を車両IDで連結した約**1,700万個体**。前年に「不合格未満の記録」だけが付いた個体の翌年操舵系不合格率は、記録なしの**最大24.1倍**(車齢4-7年: 0.43% → 10.32%) | 英国DVSA MOT 2024/2025連結 | [150](docs/150_advisory_precedence_verification.md) |

### ⑤ の副次発見がこの研究の核心

**若い車では「兆候のみ」の群の方が「不合格になった」群より翌年の故障率が高い**(10.32% vs 7.55%)。
不合格は車検に通すため**修理される**が、兆候(advisory)は**放置される**からである。つまり——

> 不合格未満の観察情報は、現在の実務で**最も予測力があり、かつ最も行動につながっていない層**である。

これは本研究の価値仮説(「fault未満の情報の層を作れば価値がある」)の、これ以上ない実証的な言い換えになっている。
制度差としても観測できる: 英国は兆候層を記録・公開している(使ってはいないが)。日本のOBD検査はDTCの1bit判定で、**兆候層が制度上存在しない**([149](docs/149_concentration_ev_and_japan.md))。

### 渡っていない橋(誠実な限界)

- **「小さな変化が見える」ことと「その変化が故障の前触れである」ことは別。** 後者はEPS内部信号については壊れる前後の実車データが要り、それは公開されていない。⑤は**検査員の目視観察**の予測力であって、ECU内部信号の予測力ではない。ただし「閾値未満の観察に予測情報が乗る」ことが推測から実証に変わったため、類推の土台は変わった
- ②の感度は「60秒1本」での**床**の値。実運用は繰り返し回数で設計するため実力はこれより細かい方向にしか動かない。逆に定常ずれが見えすぎることは「路面の傾きや積載でも引っかかる」ことを意味し、単発で騒がず状況(電圧・温度)を添える設計に戻る
- ⑤には生存の偏り(廃車・輸出された個体の除外)と介入差(不合格群は直される)が混ざる

## 2. ビジネスとして成立するか → **「成立する」とは主張しない。ただし判断は下せる**

### 2-1. 本研究が閉じた問い([145](docs/145_final_conclusions_and_interpretations.md))

成立し得る形は組み上がった: **誰が**(自動車メーカー)、**なぜ**(誤診による無駄な交換の実費+売った後も監視を求める国際規格の流れ)、**どの通り道で**(既存の受注競争と診断コンテンツの開発費)払うのか。
だが最後の一問「この機能は選定で有利になるのか、あって当然のタダの要求なのか」は商談の中でしか答えが出ない種類のものであり、内部情報を使わない方針のため**ここで問いを閉じる**。「内部を見れば分かる」を次の一手として掲げない。

### 2-2. それでも外部証拠だけで言えること([146](docs/146_business_framework_and_roadmap.md))

**判断1: 今は金になる。ただし時限の窓であり、いずれ「あって当然」になる。**

- **競合が現に商品化している**(支払い意思の最も硬い証拠)。操舵大手Nexteerは2025年にMotionIQ/Healthを発表し量産開発中。企業は売れない物に量産開発の人員を割り続けない
- **買収という形の支払い証拠。** Boschは予測整備ソフト会社(Uptake)を買収して予測診断を製品ライン化し、ZFも車両健全性監視を商品化している
- **規制が需要を強制形成している。** ISO 21448の運用段階(2022年)とUNECEの流れ。規制起点の需要は「発生するか」ではなく「いつ標準要求になるか」の問題
- **先例は3類型に整理できる。** 型A 法規化でタダ化(排ガス診断=OBD。ただし診断機器・診断コンテンツの市場が生まれ、実装実績を持つ供給者が回収した)/型B 有償化に成功(コネクテッド診断・遠隔監視)/型C 差別化→標準装備(運転支援)。安全・診断系は「移行期に差別化として働き、標準化後は実装実績を持つ者が供給側に残る」を繰り返している

→ **事業の要諦は「窓が開いている間に実装実績を作り、標準化後はコンテンツ・作法・物量で回収する側に回る」こと。**

**判断2(自説の修正): 本研究が「空席」と呼んだ席は、空席ではなくなりつつある。**
Nexteer MotionIQ/Healthが、部品内部の健全性監視という席にまさに座りに来ている。ただし**この席は部品ごとに分かれており**、他社から見えるのは他社製品の内部だけである。「概念としての空席」は埋まりつつあるが、「サプライヤ製品の席」はそのサプライヤにしか埋められない。

**値付けは開発費型が最も通りやすい**(車種ごとの診断コンテンツ開発費に載せる=既存の商流)。単価上乗せ型は窓が開いている間だけ、継続サービス型は車両ヘルス基盤の成熟待ち。

**この判断の誤り条件**(外から組み立てた判断だから書ける):

- 競合製品(MotionIQ等)の縮小・撤退が観測される → 支払い意思の見立てが誤り
- OEMが健全性監視の内製を相次いで宣言する → 部品側の席という見立てが誤り
- 規制の監視要求が実装を伴わない紙の要求に緩む → 窓そのものが幻

## 3. Kill済み・禁止する主張(蒸し返さない)

- **個車の故障予測(RUL・交換時期予告)はKill済み。** 実証モデルv2は事前登録した合格基準(precision≥0.5 かつ recall≥0.3)に対し 0.48 / 0.26 で未達。**基準を超えるまで数字をいじらず、不合格をそのまま残した**([143](docs/143_recall_detection_results_v2.md))。これにより2025年以降のリコールデータによる再検証が、汚れていない3回目の試験として意味を持つ
- **禁止する主張**: 故障予測・余寿命・交換時期 / 原因断定 / 安全保証 / 保証費削減効果 / EPS無罪論 / OEM・モデルの設計優劣の断定
- **公開による反応測定は禁止**(AGENTS.md 6条)。実務者の反応を測る設計は内部情報の流入経路を作ることと不可分のため。公開・発信はユーザの明示指示がある場合のみ
- **内部情報を次アクション・再開条件にしない。** 内部依存の論点は「ここで問いを閉じる」で終える(境界の記録: [123](docs/123_steering_predictive_diagnostics_power_monitor_program_question_sheet.md)、[138](docs/138_business_model_definition.md))
- 過去にKillした仮説を、名前だけ変えて再提案しない。一覧は [docs/61](docs/61_llm_kill_knowledge_base.md) と [data/llm_kill_knowledge_base.tsv](data/llm_kill_knowledge_base.tsv)

## 4. この研究が残したもの

- **再現できるスクリプト群と技術者向けレポート**(誰が実行しても同じ数字が出る)
- **検証の作法**: 合格基準の事前固定、過去で学び未来で試す評価、**不合格の記録**
- **言ってはいけないことを機械的に止める仕組み**(原因断定・交換判断・無罪主張を拒否するガード。[132](docs/132_steering_predictive_diagnostics_payload_replay_demo.md))
- **公開データの地図**: 何がどこまで見え、どこから先が見えないかの実測

## 8. 書き方と運用のルール

詳細は [AGENTS.md](AGENTS.md)。要点だけ:

- **判断を先に、根拠を箇条書きで、日本語を優先**する。造語・商品名・略称・phase名より先に、自然言語で「何を判断しているのか/誰のどの業務の話か/何が分かれば進み、何が分かれば止まるのか/既存業務・既存診断と何が違うのか」を説明する
- 提案は **市場需要 → 未解決の痛み → 仮説 → 解決策 → 買い手/利用者 → 初期提供物 → 検証方法 → Kill条件** の順で書く
- 結論は必ずEPSサプライヤの立場(何を売るか/何ができるか/何を言ってはいけないか)に帰着させる
- **ブランチ運用**: `research/bosch-motion-domain-ai`(作業)→ `main`(集約)。`public-snapshot` は公開用で、履歴なしの単一スナップショット方式(`git commit-tree main^{tree} -p public-snapshot`)。公開前に、追跡ファイルへのPII・認証情報・ローカルパス・キャッシュ混入がないことを確認する
