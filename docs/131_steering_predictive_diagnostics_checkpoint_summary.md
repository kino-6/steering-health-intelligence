# Steering Predictive Diagnostics Checkpoint Summary

## まず、IDを使わずに言う

このテーマで検証してきたのは、次の1つの仮説である。

> 電動パワーステアリング(EPS)は、「故障判定(故障コード)にはならなかったが、一瞬だけ普段と違う状態になった」ことを、いま、どこにも残していないことが多い。
> 例えば「一瞬の電圧低下でアシストが細った」「受け取っている外部信号が一瞬無効になってフォールバックに入りかけた」という事実である。
> この事実を、原因を断定しない短い「状態説明」として部品側で残せるようにすれば、修理の空振り・部品の無駄交換・原因切り分けの長期化を減らせる。
> それはEPSサプライヤの売り物(固定スコープの技術assessment)になり得るか。

2週間の検証を経た現在の答えは、次である。

> **仮説は、公開情報だけで裏付けが取れた。**
> 「症状はあるのに故障コードがない」車両群はリコール是正手順に公式に存在し(Ford)、診断データを何も読まずに全車再プログラムした是正も実在し(GM)、無効な外部信号のせいで直らないgear交換が繰り返されたこともOEM自身が公式文書に書いていた(GM)。しかも2021年の車でも「電圧低下が部品内部故障に見える故障コードとして残る」誤帰属が続いていた(Ford)。
> つまり、この穴は実在し、埋めた場合の価値の形(=OEMが事後に人手で書いているservice文書を、部品がruntimeで機械的に出す)も公開文書そのものが証明している。
> 残っている確認は「サプライヤの現行製品では既に解決済みでないか」「社内のどの部署が実際に使うか」という**実行段階の内部確認だけ**である。

## 検証のストーリー(時系列)

1. **観点補正**(docs/119): 「診断資料を作ること」から「実行時の状態説明が価値になるか」へ問いを直した
2. **候補の絞り込み**(docs/120〜122): 電源監視を第一、通信入力妥当性を第二とし、最小の状態説明(payload)と判定条件を設計した
3. **既存技術との突き合わせ**(docs/125): 「既存の仕組みでは残せない」は不正確と判明。AUTOSAR標準は残す設定余地を持つ。真の差分は「閾値未満のevent」「機能影響との同時性」「再発の追跡」という設計選択の穴にある、と言い直した
4. **市場の痛みの実在確認**(docs/127): 「症状あり・コードなし」の車両群がリコール是正の公式経路になるほど存在した(Ford 15V-340)
5. **判定ゲートの組み替え**(docs/129): 「サプライヤ製品で確認しないと判定できない」を、「市場に出た実車両の是正実務で何が読まれたか」に組み替え、公開一次文書で判定を閉じた。判断材料は故障コードの有無という1bitだけで、є項目の soft context は実務に存在しなかった
6. **第二候補も同じ手法で確認**(docs/130): 無効な外部信号→操舵警告→直らないgear交換の連鎖をOEM公式文書で確認。事後に人手で書かれたservice文書が、提案しているpayloadと同一の構成だった
7. **SOTIF枝の整理**(docs/126、128): プロセス支援商品はNo-Go。部品側の観測をSOTIFの市場監視へ渡す形だけを、入口条件付きで温存
8. **故障予測は一貫してKill維持**: いつ壊れるかを当てる方向には戻っていない

## 残っている確認(すべて実行段階・内部資料条件)

公開情報でできる仮説検証は完了した。以下は「内部資料を使える条件になった場合」の実行項目としてのみ保存する。

1. **サプライヤの現行製品設定の確認**: 公開実例(2011〜2021年)で確認した穴が、サプライヤの現行世代では既に塞がれていないか。確認用の質問シート15問は docs/123 に作成済み(program固有欄は空欄)
2. **社内の使い道確認**: 診断企画・品質改善・顧客技術説明のうち2部署以上が、この状態説明を自分の成果物に使うと言うか
3. **通信入力妥当性のみ**: security側の標準機構(IdsM)との役割分担を1段落で書けるか
4. **SOTIF枝の入口(KQ1)**: SOTIF由来の「故障未満の機能低下の記録・報告」要求が、部品側RFQ/安全要件に実際に来ているか

## Rule Check

この区切り判定では、[AGENTS.md](../AGENTS.md) の次を適用する。

1. `Market Demand First`: 修理の空振り・誤交換・切り分け長期化という実在の痛み(公式文書で確認)から始めている
2. `Natural Language First`: 結論をIDなしで先に書き、ID対訳表を付けた
3. `EPS Supplier Lens`: 売るもの=固定スコープassessment、実施するもの=状態説明の設計、言ってはいけないこと=下記
4. `Steering Predictive Diagnostics Value Rule`: 診断資料でなく実行時の状態説明を本体にしている
5. `Mandatory Rule Check Before Stop / Kill / Archive`: 凍結(SPD002)とKill維持(故障予測)に再開条件と理由を明記した
6. 内部事実不足を主Kill理由にしていない。むしろ判定ゲートの組み替えで公開情報のみの検証を完了した

## 言ってはいけないこと(全成果物共通・変わらず)
