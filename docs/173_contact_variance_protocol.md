# 173. 「変動は水準に先行するか」の検証プロトコル(実行前に固定)

**このドキュメントは、SOReDDの値を見る前にコミットする。** [docs/140](140_recall_detection_protocol.md) / [docs/161](161_pmsm_model_validation_protocol.md) / [docs/165](165_precursor_protocol.md) と同じ作法。

## 何を確かめるか

[docs/168](168_transfer_reduces_to_spec.md) と [docs/172](172_contact_degradation_route.md) が立てた問い。

> **A''**: 接点界面の劣化において、**接触抵抗の変動(不安定性)は、水準の上昇に先行するか。**

先行するなら、断続故障族に対する監視指標は**水準ではなく変動**であり、
[docs/121](121_steering_predictive_diagnostics_power_monitor_case.md) の payload が持つ `recurrence` の設計根拠になる。
先行しないなら、水準を見るしかなく、[docs/172](172_contact_degradation_route.md) が引いた文献の「膝型」により**先行時間は短い**。

## 対象(実行前に固定)

- データ: SOReDD(DOI 10.18419/darus-2785、**CC BY 4.0**)。101ファイル、電磁リレーのrun-to-failure
- 各ファイルは1個体。`metadata` に総サイクル数、`contactResistance` に [時刻, 抵抗] の時系列を持つ
- **選別規則**: `metadata.lastEvent` を持つ個体(=終端事象に到達した個体)のうち、
  `contactResistance` のサンプル数が **1,000点以上**のもの。**全数を使う。上限は設けない**
- 抵抗値が `NaN` のレコード、時刻が `NaN` のレコードは除外する

## 指標(実行前に固定)

各個体の寿命を**10等分の窓**に切り、窓ごとに次を出す。

1. **水準** `L_k` = 窓 k の抵抗の中央値
2. **変動** `V_k` = 窓 k の抵抗の**四分位範囲 / 中央値**(ロバストな相対ばらつき)

**ベースラインは各個体の第1窓**とする([docs/163](163_per_unit_baselining.md) の個体基準。母集団基準は使わない)。

- `l_k = L_k / L_1`
- `v_k = V_k / V_1`

## 判定基準(実行前に固定)

| # | 基準 | 閾値 |
|---|---|---|
| **C1 先行性** | 変動が基準比 **+50%** を超える最初の窓 `k_v` が、水準が基準比 **+10%** を超える最初の窓 `k_l` より**早い**(`k_v < k_l`) | **対象個体の過半で成立** |
| **C2 先行幅** | `k_l − k_v` の中央値(寿命の何割ぶん先行するか) | 閾値なし。**測定値を報告** |
| **C3 膝の確認** | 水準が基準比+10%を超える窓 `k_l` の位置(寿命に対する割合) | 閾値なし。**測定値を報告**。文献の「膝型」と整合するか |

**閾値の根拠**: 水準+10%は [docs/165](165_precursor_protocol.md) の+5%より緩く、抵抗が数十mΩ→Ω級まで動く現象に対して控えめに置いた。
変動+50%は、変動指標が水準指標より本来ノイジーであることを見込んで厳しく置いた。**変動側に有利な設定にしていない。**

**不成立の場合の扱い**: 窓数(10)、閾値(+50% / +10%)、指標(IQR/中央値)を結果を見てから変えない。
不成立ならそのまま記録する。**v2は作らない**——[docs/166](166_precursor_results_v1.md) で1回だけ指標変更を許した前例があるが、今回は**プロトコル欠陥が見つかった場合に限る**と先に決める。

## 成立した場合に言えること

> 接点界面の劣化では、**抵抗の変動が水準の上昇に先行する**。
> したがって断続故障族に対する部品側の監視指標は、水準ではなく**変動または発生率**であるべきである。

これは [docs/121](121_steering_predictive_diagnostics_power_monitor_case.md) の payload と [docs/155](155_window_recurrence_verification.md) の k-of-N 判定則の設計根拠になる。

## 不成立の場合に言えること

> 変動は水準に先行しない。接点劣化の監視は水準を見るしかなく、
> 文献の膝型軌跡により**先行時間は短い**。断続故障族に対する早期警告の価値は限定的である。

これは事業判断に効く。**早期警告が売り物にならないなら、[docs/146](146_business_framework_and_roadmap.md) 第1層の価値は「予告」ではなく「説明」に寄る**——
もっとも本研究は既に故障予測をKillしており([docs/143](143_recall_detection_results_v2.md))、状態説明に寄せてある。整合はしている。

## 言えないこと(先に固定)

1. **リレーは自動車コネクタではない。** 主機構はアーク侵食と膜形成であり、frettingの微摺動とは異なる。
   言えるのは「**接点界面劣化において変動が水準に先行するか**」という機構レベルまで
2. **EPSのコネクタで同じ順序が成り立つとは言わない**
3. 故障予測([docs/143](143_recall_detection_results_v2.md))へは戻らない。窓の位置は既知の寿命に対する割合であり、予測対象ではない

## Rule Check

- 公開データのみ(CC BY 4.0)。値を見る前に選別規則・指標・閾値・禁止事項を固定した
- **閾値を変動側に有利に設定していない**ことを明記した(変動+50% vs 水準+10%)
- 不成立の場合に事業判断がどう動くかを、先に書いた
- 転移の限界(リレー ≠ 自動車コネクタ)を、成立した場合の主張より先に置いた
