# ULC008 部署別レビュー深掘り

## 結論

ULC008は、現時点では **社内レビュー用sampleとしてContinue** である。

ただし、売り物として進める段階ではない。
公開proxyだけでは、低速、大舵角、凹凸、EPS内部状態、DTC、交換結果が同一車両・同一時刻で揃わない。
したがって、ULC008で主張できるのは「駐車場相当の使用負荷classを先に分類できる可能性がある」までである。

最初に見せるべき部署は、製品企画と診断企画である。
製品企画に刺されば、用途別のEPS価値説明に残る。
診断企画に刺されば、DTCだけでは説明しにくい低速・駐車・凹凸contextの補助説明に残る。

どちらにも刺さらなければ、ULC008は止める。

## 何を判断しているか

判断しているのは、駐車場走行でEPSが壊れるかではない。

判断しているのは、次のような使われ方を、EPSサプライヤの業務判断に使えるclassとして扱えるかである。

> 低速で大きく操舵し、駐車場や市街地の凹凸・段差・路面外乱が重なる使われ方。

このclassは、故障原因ではない。
残寿命でもない。
交換時期でもない。

業務上の意味は、以下である。

- 製品企画: どの用途でEPSの低速取り回し価値を説明するか
- 診断企画: DTCだけでは説明しにくい使用contextを補助できるか
- 品質改善: field issueを使用条件別に読み直す入口になるか
- 評価企画: 既存評価が駐車場相当の使用条件を代表しているか

## Evidence Boundary

現時点で使える材料は、強いものと弱いものが分かれている。

強い材料:

- 低速・高操舵要求の公開proxy windowはRepo内で抽出済みである。
- [data/low_speed_high_steering_proxy_summary.tsv](../data/low_speed_high_steering_proxy_summary.tsv) では、公開走行データからcandidate windowを231件抽出している。
- [data/low_speed_high_steering_proxy_windows.tsv](../data/low_speed_high_steering_proxy_windows.tsv) には、低速・高操舵要求の上位windowがある。
- KGL003、KGL005、KGL008は、それぞれ速度/運転状態、操舵要求、路面凹凸proxyの材料になる。

弱い材料:

- 凹凸proxyと操舵proxyが、同一dataset・同一車両・同一時刻で揃っているわけではない。
- EPS内部信号、assist state、limit state、motor current、temperature、DTC、freeze frame、交換結果は公開proxyから見えない。
- 既存評価、既存診断、既存顧客説明に同じ整理があるかは未確認である。

したがって、ULC008は実証済みの予測ではなく、社内レビュー用の仮説sampleである。

## 出力の形

ULC008で出すべき出力は、予測スコアではなく、使用context labelである。

| 出力 | 内容 |
|---|---|
| Usage class | 駐車場走行で低速・大舵角・凹凸が重なる使われ方 |
| Evidence snippets | 低速、大舵角、操舵頻度、凹凸/振動proxyの根拠 |
| Department view | 製品企画、診断企画、品質改善、評価企画での使い道 |
| Confidence | 公開proxy上の確からしさ。EPS内部状態の確からしさではない |
| Forbidden claims | 故障原因、残寿命、交換時期、内部stressを断定しない |

この出力を `usage-context classifier` と呼ぶなら、必ず先に上の自然言語説明を書く。
英語名だけを先に出さない。

## 製品企画向けの判断

製品企画にとっての問いは、次である。

> この使用負荷classは、用途別のEPS価値説明に使えるか。

たとえば、都市配送、駐車操作が多い車両、狭い市街地、駐車場内の低速移動が多い用途では、低速取り回し、操舵の自然さ、違和感の少なさ、路面外乱下の体感説明が価値になり得る。

ただし、これは「故障しにくい」と言う話ではない。
製品企画で使える表現は、以下に限定する。

言ってよいこと:

> この用途では、低速・大舵角・凹凸が重なる使用条件が多くなり得る。そのため、低速取り回し時の操舵感や路面外乱下の体感説明を、製品価値として整理できるかを見る。

言ってはいけないこと:

> この用途ではEPSが壊れやすい。

> このclassから交換時期が分かる。

> このclassを使えば保証費を下げられる。

製品企画でProceedする条件は、用途別の価値説明に使えることである。
「なるほど、でも既存カタログや既存RFQ回答で十分」と言われるなら、この方向は弱い。

## 診断企画向けの判断

診断企画にとっての問いは、次である。

> DTCやfreeze frameだけでは説明しにくい低速・駐車・凹凸contextを、補助説明として使えるか。

診断企画で価値が出るのは、DTCを増やすことではない。
また、故障予測をすることでもない。

価値が出る可能性があるのは、次のような場面である。

- 警告やDTCがないが、ユーザが駐車時の操舵感や音を訴える
- DTCはあるが、発生時の使用contextが分からず説明が荒くなる
- 路面外乱、段差、低速操舵、駐車操作が混ざり、EPS異常と外乱由来の体感を切り分けにくい

診断企画でProceedする条件は、既存DTC / freeze frame / extended dataだけでは同じ説明が難しいことである。
逆に、既存データで車速、操舵角、assist state、temperature、電圧、DTC発生条件、freeze frameが十分に残り、同じ説明ができるならULC008は止める。

## 最小信号契約

ULC008を社内レビューに出す場合、最低限この信号・情報を分けて書く。

| 種類 | 例 | 扱い |
|---|---|---|
| 公開proxyで見える | 車速、操舵角または操舵要求、操舵頻度、路面凹凸/振動proxy | 仮説sampleの根拠 |
| 公開proxyで見えない | EPS内部電流、assist state、limit state、temperature、DTC、freeze frame、交換結果 | 断定禁止 |
| 社内確認が必要 | 既存評価条件、既存DTC項目、既存freeze frame項目、既存顧客説明文 | Proceed/Kill判断 |

この分離ができない場合、ULC008は危ない。
公開proxyで見えないものを見えた扱いにすると、すぐに故障予測や原因断定へ滑る。

## 部署別レビュー質問

作成した質問表は [data/pvc001_ulc008_department_review_questions.tsv](../data/pvc001_ulc008_department_review_questions.tsv) である。

特に最初に聞くべき質問は、次の4つである。

1. 製品企画: このclassは用途別のEPS価値説明に使えるか
2. 製品企画: 既存カタログ、RFQ回答、技術説明と何が違うか
3. 診断企画: DTC / freeze frameだけで同じ説明ができるか
4. 診断企画: 顧客説明に使うと原因断定に見えないか

この4問のうち、1と3がNoなら止める。

## Kill Gate

ULC008は、次のどれかで止める。

- 製品企画が用途別価値説明に使えない
- 診断企画が既存DTC / freeze frameで十分に説明できる
- 凹凸や駐車操作が原因だと読まれる
- 既存評価scenarioの言い換えにしかならない
- OEM保証DB、fleet data、service outcomeがないと価値が出ない

## 次アクション

次にやるべきことは、外部調査を増やすことではない。
まず、ULC008を以下の2枚に分ける。

1. 製品企画向け: 用途別価値説明に使えるかを見る1枚
2. 診断企画向け: DTC / freeze frameだけでは説明しにくいcontextかを見る1枚

この2枚で、製品企画と診断企画のどちらにも刺さらなければ、PVC001はかなり弱い。
逆にどちらか片方だけでも強く刺されば、次に品質改善または評価企画へ広げる。

## EPSサプライヤとしての言い方

言ってよいこと:

> 低速・大舵角・凹凸が重なる使用条件は、EPS内部状態を示すものではない。ただし、駐車場相当の使用負荷classとして整理すれば、製品企画や診断企画で、用途別の価値説明や使用contextの補助説明に使える可能性がある。

まだ言ってはいけないこと:

> 駐車場走行や凹凸路でEPSが壊れる。

> このclassから残寿命、交換時期、保証費削減、安全性が分かる。

> 公開proxyからEPS内部stress、thermal limit、assist limitation、DTC不足を断定できる。
