# 322. 事前登録 — 検定数を絞ると、検出は残るか

## なぜこれを次に置くか

[docs/321](321_enrolment_length_results.md) が出した関係式は `ライン時間 = 検定数 ÷ 目標誤報率` である。
**目標を動かさずにライン時間を縮める唯一の手は、検定数を減らすことしかない。**

| 検定数 | 内訳 | 1 件/時 のライン時間 |
|---|---|---|
| 16 | 8 チャネル × 2 検出器 | 16 時間 |
| 4 | 2 チャネル × 2 検出器 | **4 時間** |
| 2 | 1 チャネル × 2 検出器 | **2 時間** |

**だが [docs/286](286_common_mode_results.md) の 8/8 検出は 8 チャネル全部を束ねて得たものである。**
**絞って残るかは測っていない。**

## 問い

**採用チャネルを N 本に絞ったとき、検出は何件残り、誤報はどうなるか。**

## 最重要の制約 — どのチャネルを残すかは健全データだけで決める

**故障データを見てから「よく効いたチャネル」を選ぶのは、保留データで選んで保留データで測ることである**
（[TROUBLES.md](../TROUBLES.md) T13）。実車の出荷ラインには故障データが無い。

**したがって順位は、出荷時に手元にある量だけで付ける。**
[docs/280](280_fingerprint_interval_results.md) の採否判定に使う `cv_shift`——**保留した健全区間が出荷時基準値からどれだけ外れたか**——の昇順とする。
**これは健全データのみから決まり、故障を一切見ていない。**

## 手順

データ: 実インバータ（[docs/286](286_common_mode_results.md) と同じ。正常前半で登録、正常後半で誤報、故障 8 件で検出）。

1. `scripts/eps_health_recorder.py` の `enrol` をそのまま使う。**同相除去も閾値の出し方も変えない**
2. 採用チャネルを `cv_shift` の昇順に並べ、**上位 N 本だけを残す**。N = 1, 2, 3, 4, 6, 8
3. N ごとに `n_tests = 2N` として**閾値を較正し直す**（[docs/294](294_unit_level_false_alarm.md) の作法）
4. 保留した正常後半で誤報、故障 8 件で検出を数える
5. **同じ表に、その N での 1 件/時 のライン時間 `2N` 時間を書く**

## 事前に決める判定

| | 基準 |
|---|---|
| **G1** | **N = 1（ライン 2 時間）で検出が 8/8 のまま** → 絞ってよい。ライン時間の問題は解ける |
| **G2** | 8/8 を保つ**最小の N**。その `2N` 時間が、この設計が要求できるライン時間である |
| **G3** | 各 N での保留正常の誤報件数。**検出と同じ表に書く**（[TROUBLES.md](../TROUBLES.md) T28——片側だけ報告しない） |

**G1 が外れても G2 が 2 か 3 なら「4〜6 時間まで縮む」と書く。**
**どの N でも 8/8 が壊れるなら、`cv_shift` の順位が検出に効くチャネルを選べていないということであり、
それは「出荷ラインでは選べない」という結論になる。**そのときは選べない理由を書く。

## この事前登録が外れる条件

- 故障は**人為的に導入した開放・短絡・過温度であり、劣化ではない**（R12 未達）。**8/8 は劣化の検出率ではない**
- 実インバータ 1 台・10 Hz・28 分。**率ではなく存在証明**
- `cv_shift` の昇順という順位付けは**私が決めた**（[TROUBLES.md](../TROUBLES.md) T2）。
  健全データのみから決まる量ではあるが、**これが最良の順位である根拠は無い**
- N の刻み {1,2,3,4,6,8} も私が決めた
