# 340. 訂正 — docs/317 の 6/6 は、凍った軸が生んだ数字だった

**[docs/317](317_changepoint_results.md) を取り下げる。**傾きの変化による検出は、**実劣化で 0/6 である。**

## 何が壊れていたか

累積ストレスの軸を、`scripts/boundary_vs_refresh.py` の `series()` がこう作っていた。

```python
ref = float(np.median(op[:n1 // 2]))          # run 1 前半の中央値
stress = np.cumsum(np.maximum(op - ref, 0.0))
```

**試験機は run ごとに設定温度を 10 °C ずつ下げている**（[docs/199](199_pulse_thermal_results.md) が特定済み）。
したがって **run 1 が最も熱い。**基準を run 1 の中央値に置くと、**run 2 以降の超過はすべて 0 になる。**

| 素子 | 基準 | run1 の軸の伸び | run2〜7 の伸び |
|---|---|---|---|
| Test_8 | 153.5 °C | 3752.0 | **0.0** |
| Test_9 | 152.5 | 4220.5 | **0.0** |
| Test_10 | 155.6 | 3835.3 | **0.0** |
| Test_11 | 149.0 | 2668.1 | **0.0** |
| Test_12 | 150.4 | 3057.5 | **0.0** |
| Test_14 | 151.5 | 2796.6 | **0.0** |

**軸は run 1 の途中で止まり、以後まったく動かない。**

## 何を計算していたのか

傾きの最小二乗解の分母は `w·Σx² − (Σx)²` で、**x が一定なら数学的に 0 になる。**
倍精度では 0 にならず、桁落ちの残りが出る。

| 区間 | \|分母\| の中央値 | `w·Σx²` の大きさ | 比 |
|---|---|---|---|
| run 1 | 2.58e+12 | 1.74e+13 | 1.5e−01 |
| run 2〜4 | 3.74e+01 | 5.63e+13 | **6.6e−13** |
| **run 5〜7** | **1.97e+02** | 5.63e+13 | **3.5e−12** |

> **検出が起きていた run 5〜7 では、分母は倍精度の丸め誤差そのものである。**
> **丸め誤差を丸め誤差で割った値を、傾きと呼んで閾値に掛けていた。**

## 直した結果

基準を run 1 の中央値から、**記録全体の下位 5 パーセンタイル**（休止時の温度に相当）に変えた。

| | docs/317（凍った軸） | 訂正後 |
|---|---|---|
| 検出 | 6/6 | — |
| **run 4 の誤検知** | **0** | **16,794〜39,757 件/時** |
| G1 | 6/6 PASS | **0/6 FAIL** |
| G2（水準では落ちる 3 素子） | 3/3 PASS | **0/3 FAIL** |

**傾きの変化による検出は成立しない。**

## なぜ気づけなかったか

**軸そのものを一度も見ていない。**検出率と誤検知だけを見て、6/6 と 0 件が同時に立ったことを成果として報告した。

> **軸が動いているかを確かめていれば、実行する前に分かった。**

[TROUBLES.md](../TROUBLES.md) T1（試験機の操作を対象の性質と取り違える）の **6 回目**である。
1〜5 回目は観測量の側で起きた。**6 回目は軸の側で起きた。**
そして新しい型 T41 として、**回帰の分母が縮退していないかを確かめる**規則を登録した。
