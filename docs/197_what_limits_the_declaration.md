# 197. 宣言を縛っているのは測定ではなく仮定だった

[docs/196](196_eps_health_element.md) が残した2件を詰めた。1件は数値になり、**1件は自分の主張を弱める結果になった。**

実行: `python3 scripts/capability_declaration_limits.py` / 数表: [data/capability_declaration_limits.tsv](../data/capability_declaration_limits.tsv)

## (B) 宣言している粒度は「分解能」であって「確度」ではなかった

これは自分の主張を弱める結果である。**先に書く。**

capability の式は熱抵抗 Rth が寿命を通じて一定であることを仮定している([docs/192](192_str_capability_rule_protocol.md) 仮定B)。
Rth が k 倍に増えた場合、実際の能力は解析的に決まる:

```
C_true = C_declared / sqrt(k)      楽観の量 = sqrt(k) - 1
```

| Rth の増加 k | 楽観の量 | 粒度0.081%の何倍 | 粒度1.005%の何倍 |
|---|---|---|---|
| 1.01 | 0.50% | 6倍 | 0.5倍 |
| 1.02 | 1.00% | **12倍** | **1.0倍** |
| 1.05 | 2.47% | 30倍 | 2.5倍 |
| 1.10 | 4.88% | 60倍 | 4.9倍 |
| 1.20 | 9.54% | 118倍 | 9.5倍 |

**仮定の誤差が宣言粒度に並ぶのは、Rth がわずか 0.16% 〜 2.0% 増えた時点である。**

> **したがって [docs/193](193_str_capability_rule_results.md) / [docs/195](195_capability_rule_second_mechanism_results.md) の「宣言粒度 0.08〜1.0%」は、
> 測定の分解能であって、capability 値の確度ではない。**
> 確度は Rth 仮定に支配されており、その仮定は検証されていない。

### 誤差がどこまで大きくなりうるか — データから両端を出した

R_on はそれ自身が接合部温度の計器である。出荷時は損失がほぼ一定なので、
そこで当てた `dR_on/dT_package` は R_on の接合部温度に対する固有係数とみなせる。
**その後の正規化後の上昇が全部ダイアタッチ側の劣化によるものだったと仮定すると**、
同じパッケージ温度における接合部温度の上昇は `ΔTj = ΔR̂ / a` で決まる。

| 個体 | 終端の ΔR̂/R | a [Ω/°C] | **全部が熱由来だった場合の ΔTj** |
|---|---|---|---|
| Test_8 | 44.5% | 0.01095 | **76.3°C** |
| Test_9 | 24.8% | 0.00990 | 45.9°C |
| Test_10 | 26.2% | 0.01276 | 41.2°C |
| Test_11 | 17.8% | 0.01101 | 30.0°C |
| Test_12 | 15.7% | 0.00961 | 30.4°C |
| Test_14 | 30.3% | 0.00910 | 62.2°C |

- **一方の端(k = 1、熱由来ゼロ)**: 宣言は正確である
- **もう一方の端(全部が熱由来)**: 接合部はパッケージ読みより **30〜76°C 熱く**、能力は宣言よりずっと悪い

**このデータで両端を分けることはできない。**[docs/189](189_five_limits_tested.md) ② が試みて失敗した分離そのものである。
試験機がフランジ側から加熱するため、素子自身の熱経路を取り出せない。

## この結果が主張をどう動かすか

| 主張 | 変化 |
|---|---|
| **故障が立たないまま能力が縮む窓は実在する**(問2) | **強くなった。**誤差の向きは楽観側なので、実際の低下は**測定値以上**である。窓の存在はより確か |
| **終端で能力が 7〜17% 落ちている**([docs/193](193_str_capability_rule_results.md)) | **「7〜17%」は下限であって値ではない。**Rth も劣化していれば低下はもっと大きい |
| **宣言粒度 0.08〜1.0%** | **「分解能」に格下げ。**確度ではない。**この言い換えを以後すべての記述で守る** |
| **capability の値を出せる**(問1) | **弱くなった。**値は出るが、確度は未検証の仮定に依存する。**「値を出せる」と「値が正しい」は別である** |

## 埋まらないと確定したこと

**Rth の劣化量は公開情報では決まらない。**

- 直接測定は失敗した([docs/189](189_five_limits_tested.md) ②、試験機の熱構成)
- 上限は出せた(全部熱由来なら ΔTj = 30〜76°C)が、真値の位置は決まらない
- **これは EooC シートで OEM/統合側が k を入れる欄になる。**部品側は `C_true = C/sqrt(k)` という形だけを渡す

**「分からない」から「形は渡せる、値は入れてもらう」に変わった。**これが今回の前進である。

## Rule Check

- **(B)は自分の主張を弱める結果である。(A)より先に書いていない点だけ構成上の都合だが、(B)の節の冒頭で先に宣言した**
- 「粒度」を「分解能」に言い換える訂正を、全ドキュメントに適用する対象として明示した
- 上限(ΔTj 30〜76°C)を出したが、**真値を推定していない。**両端を出して「分けられない」と書いた
- 誤差の向きが問2を強め、問1を弱めることを、都合で選ばずどちらも書いた
