# 196. SOTIFに部品側として参加する要素 — 作って動かした

**EPS実機の劣化データは公開されていない。しかし機構を共有する公開データはある。**
[docs/193](193_str_capability_rule_results.md) / [docs/195](195_capability_rule_second_mechanism_results.md) で
2機構に成立した capability 決定則を、**実際に部品側の要素として組み、動かした。**

実行: `python3 scripts/eps_health_element.py` / 記録: [data/eps_health_element_run.tsv](../data/eps_health_element_run.tsv)

## 作ったもの

SOTIF(EooC)に部品側として参加するには、**実行時に「いま自分がどれだけの操舵能力を出せるか」を、粒度つきで宣言する要素**が要る。3つの部分からなる。

| 部分 | 中身 |
|---|---|
| **① 出荷時指紋** | 健全と分かっている時点で1回だけ採る個体固有値。温度係数・正規化後の基準値・基準動作点・**指紋を採った動作点の範囲**・出荷時粒度 |
| **② 実行時推定** | 観測 → 動作点正規化 → capability。パワー段 `C=√(R_base/R(t))`、巻線 `C=H(t)/H(0)` |
| **③ 宣言** | 値・粒度・**有効性**を同時に出す。正規化できない条件では**値を出さずに拒否する** |

**③の拒否が要になる。** SOTIFは「故障していないのに機能が足りない」を扱うので、
**自信をもって間違った値を出す要素は、何も出さない要素より悪い。**

## 動いた

パワー段(NASA MOSFET 6個体)、巻線(KAIST PMSM)。抜粋:

```
Test_8  指紋: 係数 0.01095 Ω/°C, スパン 144.6-155.0°C (10.3°C), 粒度 0.0812%, 24バイト
   run 1  T=155.0°C   C=0.9998 ±0.0008  ok    範囲内
   run 4  T=139.3°C   C=0.9903 ±0.0012  ok    外挿5.3°C、粒度 x1.51
   run 6  T=138.6°C   C=0.8875 ±0.0013  ok    外挿6.1°C、粒度 x1.59
   run 7  T=123.8°C   --               拒否   指紋スパンの外側20.8°C

指紋: H 0.98689, f0 200.0Hz, 粒度 0.1448%, 12バイト
   severity  0.00%   C=1.0000 ±0.0014  ok
   severity 21.69%   C=0.9518 ±0.0101  ok
```

拒否の経路も実際に発火する。動作点を基準から50%ずらすと巻線側が拒否、
指紋スパンの3倍外へ出すとパワー段が拒否した。

## 作って初めて分かったこと

### 1. 設計の律速は「出荷時指紋をどの範囲で採ったか」だった

これが最大の発見である。**指紋のスパンは約10°C。ところが運用中に動作点は20〜31°C動く。**

結果として、**劣化が現れる run 4〜7 は全部スパンの外側**である。つまり要素は
**最も知りたい期間を、ずっと外挿しながら**宣言している。

| | |
|---|---|
| 厳密に「スパン外は拒否」とすると | **劣化期間の宣言が全部消える。**要素が役に立たなくなる |
| 外挿を許し、外挿距離に比例して粒度を膨らませると(設計判断D3) | 粒度が **1.46〜2.07倍**。低下量の方がずっと大きいので実用になる |
| それでも2倍を超えると拒否 | **Test_8 の run 7(終端)が拒否された。6個体中1個体、最も知りたい最後の点を失った** |

> **したがって出荷時指紋には要求が立つ——「動作点を1点で採るのでは足りない。運用で動く範囲を掃引して採る」。**
> **数値化した([docs/197](197_what_limits_the_declaration.md)): 動作点は指紋の幅の1.7〜3.0倍を動く。**
> これは公開データを解析していただけでは出てこない。**要素として組んだから出た要求である。**

### 2. 個体基準のコストは 36バイト

パワー段24バイト + 巻線12バイト = **1個体あたり36バイト**(float32で9個)。

[docs/193](193_str_capability_rule_results.md) は、母集団閾値では健全な個体を誤警報し(Test_10)、
そもそも値を出せないことを示した。**その差を埋めるのに要る記憶は36バイトである。**
不揮発領域の確保がこの機能の障害になることはない。

### 3. 2機構は掛け算で合成される(宣言。検証していない)

トルクは平均相電流に比例し、熱上限は最大相電流を抑える。両者は同じ式の**別々の因子**に効く:

```
T_max = H(t) * I_limit(R_on(t))   =>   C = C_巻線 × C_パワー段
```

| パワー段 | 巻線 | 合成 C | 粒度 |
|---|---|---|---|
| Test_14 run 1 | 健全 | 0.9987 | 0.66% |
| Test_14 run 7 | 健全 | 0.8760 | 1.19% |
| Test_14 run 7 | severity 21.69% | **0.8337** | 1.43% |

> **この合成は検証していない。**両機構を同時に持つ公開個体が存在せず、2つの流れは別のハードから来ている。
> **設計判断として宣言するだけである。**両者が同じ上限を奪い合う構造なら `min()` が正しく、そちらが保守側である。

## SOTIFへの参加形式として、何が揃い何が空欄か

| 要求 | 状態 |
|---|---|
| 実行時に capability を値で出す | **揃った。**要素が動く |
| その値の粒度を宣言する | **揃った。**0.08〜1.0%(機構により) |
| 宣言できない条件を宣言する | **揃った。**動作点が指紋スパン外/基準周波数外 |
| 前提(仮定)を宣言する | **揃った。**EooCシートG節、[docs/195](195_capability_rule_second_mechanism_results.md) |
| 出荷時プロセスへの要求 | **揃った(本文書で新規)。**指紋は運用動作点範囲を掃引して採ること |
| **どこまで縮んだら機能不足か** | **空欄。**車両レベル安全目標からの配分であり、部品側では決まらない(EOOC033) |

**空欄は1つだけである。**そしてそれは公開情報の不足ではなく、**役割分担上そこにある空欄**である。

## 限界(緩めない)

- **どちらのデータもEPSではない。**機構は共有するが、ハードは違う。この一行を消さない
- **巻線側が覆うのは層間短絡だけである**([docs/201](201_motor_second_fault_and_vibration_results.md))。コイル間短絡には相電流が効かず、加速度計が要る
- **パワー段側の観測量は能動領域の動作点抵抗であり、オン抵抗ではない**([docs/199](199_pulse_thermal_results.md))。
  要素は動くが、パワー段側の C は**劣化指標**であって能力比ではない。巻線側は影響を受けない
- **合成則は検証していない。**1個体で両機構を持つ公開データが無い
- **MOSFETは加速試験。**実車の時間軸に対応しない
- **層間短絡は人工的に作られている。**自然劣化ではない
- **巻線側は1機体4段階。**統計ではない
- **Rth一定の仮定は楽観側。**[docs/189](189_five_limits_tested.md) ② で直接測定に失敗している

## Rule Check

- **「実機データが無いので越えられない」で止めなかった。**類似機構の公開データで組める範囲を組んだ
- **外部に見せる・売るを次アクションにしていない**(AGENTS.md ルール0、2026-08-25追加)
- 6個体中1個体で終端の宣言を失ったことを、成功例と同じ表に書いた
- 合成則を「検証していない設計判断」と明示し、成立したかのように書かなかった
- 作って初めて出た要求(指紋スパン)を、解析結果と区別して書いた
