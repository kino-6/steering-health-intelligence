# 182. 事業判断の更新 — 「タダ化するか」に公開証拠で答える

## 何を更新するか

[docs/145](145_final_conclusions_and_interpretations.md)(2026-07-09)の事業判断はこうだった。

> **判断: 本研究は「成立する」と主張しない。**
> 最後の一問は答えを出さない——「この機能は選定で有利になるのか、**あって当然のタダの要求**なのか」。
> この問いは商談の中でしか答えが出ない種類のものであり、**ここで問いを閉じる**。

**その後、この一問に直接効く公開証拠が3つ出た。** 商談を覗くのではなく、外から組み立てる([AGENTS.md](../AGENTS.md) 7条)。

## 更新後の判断

**「成立する」とは依然として主張しない。ただし閉じ方を変える。**

> **「タダ化する側」か「有償が残る側」かは、公開の構造証拠で類型判断できる。
> 現時点の証拠は『有償の差別化余地が残る側』を指す。ただし誤り条件を添える。**

## 根拠1: 競合は名前を付けて製品化し、量産投入した

Nexteer MotionIQ/Health は**独立した製品名を持ち、ソフトウェアスイート**(Control / Dev / Health)の一部として発表され、量産に載った([docs/178](178_sotif_straight_answer.md))。

**当然の無償機能であれば、名前を付けてスイートに束ねて発表しない。** 製品化の形そのものが、有償として扱われている証拠である。

**ただし限界**: 価格も契約形態も公開されていない。**「有償として扱われている」までであり、「いくらで売れている」は分からない。**

## 根拠2: 規制は「結果」を義務化し、「方法」を開けている

これが最も効く。

| 規制 | 義務づけているもの | 規定していないもの |
|---|---|---|
| EU 2022/1426 ISMR | フィールド証拠の収集、故障の報告、**ライフタイムにわたる安全管理プロセス**(部品の摩耗を例示) | **部品レベルの劣化指標** |
| UN ADS GTR(2026-06採択) | 監査可能なライフサイクルSMS、継続的性能監視、重大事象の報告 | **部品レベルの劣化には言及なし** |

**義務は結果(監視して報告し、ライフタイム管理する)であって、方法(何をどう測るか)ではない。**

## 根拠3: 歴史の類型 — 何がタダ化し、何が有償で残ったか

[AGENTS.md](../AGENTS.md) 7条が挙げる判断材料そのものである。

| 類型 | 例 | 結果 |
|---|---|---|
| **機能そのものが法規で義務化された** | ESC(UN R140 / FMVSS 126)、TPMS(UN R141 / FMVSS 138)、eCall(EU 2015/758) | **標準装備化・タダ化**。差別化にならない |
| **結果だけが義務化され、方法が開いている** | 監視・報告・ライフタイム管理の義務(本件) | **方法で差別化する余地が残る** |

**分岐点は「規制が機能を指定したか、結果だけを指定したか」である。**

ESCは「横滑り防止装置を付けろ」という機能の指定だった。だから全車に付き、差別化が消えた。
本件の規制は「監視して報告しライフタイムで管理せよ」という**結果の指定**であり、**何を測るかは書いていない**。

したがって現時点では**「有償の差別化余地が残る側」の類型に属する。**

## 誤り条件(これが観測されたらこの判断は間違い)

7条が求めるとおり、明示する。

1. **部品レベルの劣化指標が、規格または規制で具体的に規定される。**
   → **点検済([docs/183](183_autosar_capability_channel.md))。一部は既に踏まれていた。**
   アクチュエータが能力(capability)をADSへ報告する**枠組みはAUTOSAR VMCで標準化済み**であり、
   操舵にも `STR capability information` が定義されている。**インターフェースの発明では差別化できない。**
   ただし**capability値を劣化からどう導くかは規格に無い**(仕様に degradation / wear / thermal の語が0件)。
   **残る誤り条件は「capability決定則(観測項目・閾値・時間分解能)が規格化されること」**であり、監視対象はAUTOSARの将来リリース
2. **OEMが監視内容を自ら仕様化し、全サプライヤに同一要件として課す。**
   → 実質的に1と同じ効果になる
3. **競合が同等機能を無償バンドルとして提供し始める。**
   例: MotionIQ/Health が単独の値付けを止め、SbW製品への標準添付になる
4. **ADS普及が想定より遅く、対象車両数が事業として成立しない規模に留まる**
   → **点検済([docs/184](184_ads_deployment_reality.md))。西側では既に踏まれている。**
   Mercedes は Drive Pilot を停止(2026-01)、BMW は Personal Pilot L3 を終了(2026-04)、Honda も終了。
   理由は高コスト・限定ユースケース・弱い需要。中国のみ商用展開(2025-12認可、**指定区間・50〜80km/h**)。
   **規制の存在と需要の量は別である。**類型判断(有償側)は量の話とは別なので維持されるが、
   **需要の主たる根拠はSOTIF/ADS規制からOEMの品質・保証の経済性へ戻す**

**1と2は「方法が閉じる」経路、3は「価格が崩れる」経路、4は「量が足りない」経路である。**

## 何が変わって、何が変わらないか

| | 旧([docs/145](145_final_conclusions_and_interpretations.md)) | 新 |
|---|---|---|
| 「成立する」と主張するか | **しない** | **しない**(変わらず) |
| その理由 | 「商談の中でしか答えが出ない」 | **「公開証拠で類型判断はできる。現時点は有償側。ただし誤り条件つき」** |
| 問いの扱い | 閉じる | **閉じたまま。ただし内部情報を要求せずに一段踏み込んだ** |

**「成立する」に上げないのは、類型判断が成立の証明ではないからである。**
類型は「この種の機能は有償で残りやすい」を言うだけで、**この製品が売れることを言わない。**

## この更新が [docs/145](145_final_conclusions_and_interpretations.md) を否定しないこと

docs/145 は「内部情報を使わない方針のためここで問いを閉じる」と書いた。**その判断は正しかった。**
今回踏み込めたのは、**問いの立て方を変えたから**である。

- 旧: 「この機能は**この商談で**有利になるか」→ 内部依存。**閉じたままでよい**
- 新: 「この**種類の機能**は、規制と歴史の類型から見て有償で残る側か」→ **公開情報で答えられる**

**内部依存の問いを、公開で答えられる問いに置き換えた。** これが7条の言う「外から組み立てる」である。

## Rule Check

- 公開情報のみ。競合は公式リリース、規制は一次条文、類型は公知の法規事実
- **内部依存の問い(商談での有利不利)は閉じたまま**にし、置き換えた問いで答えた
- **誤り条件を4つ、経路別に明示した**(方法が閉じる / 価格が崩れる / 量が足りない)
- 「成立する」へ上げなかった。**類型判断は成立の証明ではない**ことを明記した
- 競合の価格・契約が不明であることを、根拠1の直後に限界として書いた
