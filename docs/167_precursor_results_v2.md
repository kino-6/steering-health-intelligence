# 167. 前駆指標の検証結果 v2(成立)

## 判定

**事前登録([docs/166](166_precursor_results_v1.md) のv2プロトコル)の全基準を、6デバイス中6デバイスで満たした。**

| 基準 | 閾値 | 結果 |
|---|---|---|
| **A1' 先行性** | 6デバイス中4以上 | **6/6 PASS**。兆候は最終runの**1〜2段階前**に出る |
| **A2' 単調性** | 6デバイス中4以上で ρ≥0.8 | **6/6 PASS**。全デバイスで **ρ = 1.000** |
| **B1' 個体基準の安定性** | 測定値を報告 | **0.09% 〜 0.75%** |

数表: [data/mosfet_precursor_v2.tsv](../data/mosfet_precursor_v2.tsv) / 実行: `python3 scripts/mosfet_precursor_v2.py`

## 最も重要な数字: 個体基準は温度を除けば桁違いに安定する

| | 温度を除く前(v1) | **温度を個体ごとに除いた後(v2)** |
|---|---|---|
| 健全期の個体基準の変動幅 | 6.8% 〜 14.3% | **0.09% 〜 0.75%** |
| 兆候発生時の逸脱量 | — | **+3.6% 〜 +30.3%** |
| **兆候 / ノイズ の余裕** | — | **約20倍 〜 300倍** |

**個体基準が不安定に見えていた原因は経年ではなく温度だった。** 温度をデバイスごとに1次で除くだけで、
健全期の基準は **0.1〜0.8%** に収まる。その上に、故障の1〜2段階前から **15〜30%** の逸脱が乗る。

Test_14 の例:

| run | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|
| T_pkg [°C] | 152.6 | 147.7 | 142.4 | 137.7 | 135.0 | 134.6 | 133.9 |
| R_on [Ω] | 1.873 | 1.815 | 1.781 | 1.754 | 2.070 | 2.192 | 2.265 |
| **Δ(温度除去後)** | +0.26% | −0.49% | +0.24% | +1.13% | **+19.3%** | **+26.1%** | **+30.3%** |

温度係数は 0.0091 〜 0.0128 Ω/°C とデバイスごとに異なる。**個体ごとに推定する必要がある**([docs/163](163_per_unit_baselining.md) の個体基準)。

## 何が証明されたか

> **部品内部の電気量には、hard failure に先行する情報が乗る。**
> 実部品・実故障・同一個体の連続追跡で、6デバイス中6デバイスで確認した。
> 先行の幅は run 単位で1〜2段階分であり、逸脱量は健全期のノイズの20〜300倍である。

[docs/164](164_position_summary.md) が「本丸」としていた未証明Aが、**機構レベルで埋まった**。

これまでの証拠との位置関係:

| 証拠 | 観測対象 | 主張したい対象への近さ |
|---|---|---|
| [docs/150](150_advisory_precedence_verification.md) 24.1倍 | 車検の**検査員の目視観察** | 遠い(人が見た所見) |
| [docs/162](162_pmsm_model_validation_results.md) | PMSMの**段階的severity**(実測だが故障に至っていない) | 中間(故障前の段階だけ) |
| **本ドキュメント** | 部品内部の**電気量**、健全→**実故障**まで連続 | **最も近い** |

## そしてこれは docs/163 の製品設計そのものである

v2 でやったことは、[docs/163](163_per_unit_baselining.md) が「標準対策」として挙げたものの組み合わせである。

| docs/163の対策 | v2での実装 |
|---|---|
| ① 個体基準(EOL指紋) | 各デバイスの run 1〜3 から温度係数とベースラインを推定 |
| ③ 動作点正規化 | 温度を1次で除去 |

**この2つを組み合わせるだけで、兆候/ノイズ比が 20〜300倍になった。** 製品設計の妥当性が、実部品・実故障で裏づけられた。

さらに: 回帰に使ったのは **run 1〜3 のみ**である。実運用に置き換えると、
**出荷時+初期稼働で係数を取れば足りる**ということであり、[docs/163](163_per_unit_baselining.md) の対策①②の実装形と一致する。

## 言っていないこと(先に固定したものを維持)

1. **これはEPSではない。** ディスクリートパワーMOSFETの熱ストレス試験台である。
   言えるのは「**部品内部の電気量に故障先行情報が乗る**」という機構レベルまで
2. **故障予測ではない。** run番号は実験で振られた既知の進行であり、予測対象ではない。
   [docs/143](143_recall_detection_results_v2.md) のKillは動かさない
3. **加速試験である。** run 単位の先行幅は、実車の暦時間に換算できない
4. 温度以外の交絡(供給電圧、デューティ)は除いていない

## v1からの経緯(隠さず記録)

- **v1は不成立**だった([docs/166](166_precursor_results_v1.md))。A1が3/6、A2が0/6
- 原因はプロトコルの欠陥2件——導通ゲートの書き忘れ、温度整合窓の誤設計
- **v1の判定は不成立のまま維持**し、v2を実行前にコミットしてから走らせた
- v2では**指標を1回だけ変え、v3は作らないと事前に宣言**した。今回それを守れた(1回で成立した)

## 残る弱点

1. **EPSへの転移が未証明。** MOSFETで成り立つことが、EPSのアシストモータやインバータで同じ幅で成り立つとは言えない
2. **run 4 の扱い。** 回帰は run 1〜3 で打ち切ったが、run 4 の Δ は 0.01〜1.6% と小さく、劣化はまだ乗っていないように見える。
   もし run 4 に既に劣化があれば、回帰窓が汚染されていないという保証はない
3. 6デバイスは同一ロット・同一試験条件である。ロット間ばらつきは未測定

## Rule Check

- 公開データのみ(NASA = パブリックドメイン)
- v2を実行前にコミットし、初期run範囲・閾値・禁止事項・**v3を作らないこと**を先に固定した
- v1の不成立を判定として維持し、原因が分かった後も書き換えていない
- 成立した場合に言えることの範囲(機構レベルまで)を、実行前に固定したとおりに守った
- 故障予測Killを動かしていない
