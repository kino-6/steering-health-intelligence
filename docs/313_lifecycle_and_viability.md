# 313. ECU は何を記録し、時間が進むと何を報告し、それは成立するのか

> **ユーザ指摘(2026-09-04)**: 「ECU は何を記録して、時間が進んでどのような報告を SOTIF としてレポートし、
> それが技術的、ビジネス的に成立するのか？ それに回答せず、作業レポートに終始しているように見える。」
>
> **そのとおりである。**[docs/305](305_sotif_participation.md) は条項の対応表であって、時系列の動作でも、成立性の判断でもなかった。

> **層別の内訳は [docs/318](318_unit_ledger.md) に分けた。**不揮発は誤報率で、通信は名乗ってよい内容で決まる。
> 指紋はその後 **56 バイト/チャネル = 448 バイト**になった（[docs/317](317_changepoint_results.md)）。

## 1. ECU が持つもの（全部で 384 バイト + 記録）

| いつ | 何を | 大きさ |
|---|---|---|
| **出荷時に 1 回** | チャネルごとの指紋: 傾き・基準値・床・掃引した動作点範囲・閾値・較正できた誤報率・採否 | **48 バイト × 8 チャネル = 384 バイト** |
| 運用中、常時 | 5 秒の回るバッファ（速い側）と、分の連続平均（遅い側）。**どちらも揮発でよい** | 数百バイト |
| 事象が起きたとき | 逸脱・粒度・動作点 3 つ・確度・キーオンからの経過秒・事象の長さ・旗・有効性 | **30 バイト/件** |
| 累積 | **累積ストレス**（アシスト稼働時間・積算電流・積算熱）。駐車中は進まない | 数バイト |

**保持期間 397 日ぶんの記録:**

| 誤報の水準 | 397 日の件数 | 不揮発の必要量 |
|---|---|---|
| 設計値 1 件/時 | 9,528 件 | **0.27 MiB** |
| 実インバータで較正できた 17.6 件/時 | 167,693 件 | 4.80 MiB |

**車載マイコンの不揮発領域として、どちらも障害にならない。**

## 2. 時間が進むと何が起きるか

### 出荷時（ライン end-of-line）
動作点を掃引して 384 バイトを書き込む。**掃引が足りないと、後で黙る時間が増える**——
速度軸で 1 走行分の 7〜35 倍が要る（[docs/227](227_filling_spec_blanks_results.md)）、温度は直線 1 本が 100 °C 持つ（[docs/263](263_temperature_span_results.md)）。
**この段で、その個体が「どの範囲なら答えられるか」が決まる。**

### 納車〜数か月（累積ストレスが小さい）
毎回のキーオンで、5 秒窓と連続平均が回る。**ほとんどの時間は何も出ない。**
動作点が掃引範囲の外に出たら「宣言しない」を返す。**実車では、1 走行分の指紋なら時間の 65〜81% が「宣言しない」になる**
（[docs/229](229_recorder_simulation_results.md)）。**掃引を広げれば 1% 未満。**

### 累積ストレスが進む（数年）
**指紋の有効範囲は累積ストレスで数える。暦時間ではない**（[docs/312](312_stress_axis_results.md)）。
毎日 30 分の車と 4 時間の車では、同じ暦日数でも進み方が 8 倍違う。**駐車中は進まない。**
**有効範囲を超えたら、逸脱を出すのをやめて「宣言しない」に切り替える**——
外挿すると誤報が桁で増えるため（[docs/309](309_slow_refusal_results.md): 0 → 41,528 倍）。

### 事象が起きた日
運転者は「ときどきハンドルが重い」と感じる。**現場の主要な型は、走り出して 20 分ほどで始まり、
エンジンを切るまで戻らない**（苦情 1,697 件のうち 622 件が明示、[docs/251](251_field_timescale_results.md)）。
記録器は 30 バイトを不揮発に書く。**「キーオンから 1,200 秒、逸脱 3.15、粒度 0.21、キーオフまで持続」。**

### 入庫した日
今日は診断機が **2 値**しか読めない——コードあり（Assy 交換）／コードなし（ソフト更新して返す）。
**134.6 万台の交換可否が、この 2 値だけで決まっている**（[docs/190](190_assembly_replacement_meaning.md)）。
**そして「コードなし」で返される側に、原因不明・再現せずが 5.0 倍書かれている**（[docs/185](185_misdiagnosis_quantified.md)）。

**記録器がある車では、3 つ目の答えが読める**——
**「コードは立っていないが、この個体は 4 月 12 日の走行開始 20 分後から、自分の基準から 3.15 だけ離れた状態がキーオフまで続いた。粒度は 0.21。動作点は範囲内だった」。**

**これは診断ではない。**どの部品が壊れたかも、あと何 km 持つかも言わない。
**言うのは「その瞬間、部品の中で何が観測されていたか」だけである。**

### 車検・年次点検
397 日の保持は、英国車検の受検間隔の 90 パーセンタイル（[docs/227](227_filling_spec_blanks_results.md)）。
**前回の点検以降の事象が、必ず 1 回は読める。**

## 3. 技術的に成立するか

| 成立するもの | 数字 |
|---|---|
| 実装 | 384 バイト + 30 バイト/件、電流測定 8 ビット。**車載マイコンで足りる** |
| 導入された故障を捕らえる | 実インバータ 8 条件で 8/8、正常時の誤報 0 |
| 共通原因を除く | 同種チャネルの差分で、暖機由来の誤報が 75.6% → 0% |
| 標準化された宛先がある | AUTOSAR VMC の操舵アクチュエータ能力報告（[docs/183](183_autosar_capability_channel.md)） |

| **成立しないもの** | **数字** |
|---|---|
| **本物の劣化で確実に鳴る** | 半導体 6 個体で **2〜5**。閾値の取り方で動く（[docs/299](299_bank_results.md)・[309](309_slow_refusal_results.md)） |
| **誤報 1 件/時** | 較正できたのは個体単位で **281 件/時**。登録データが 17 倍足りない（[docs/294](294_unit_level_false_alarm.md)） |
| **劣化の量を出す** | コンデンサ 23 個体で部分的。**応力水準をまたがない（12.6 倍）**（[docs/306](306_capacitor_regression_results.md)） |
| **アシスト低下 % を出す** | **できない。**教師データが公開に無い（[docs/291](291_model_gap.md)） |
| EPS 実機での検証 | **無い** |

> **技術的な結論: 「記録して報告する」は成立する。「劣化を確実に捕らえる」は成立していない。**
> **記録器が確実に出せるのは、逸脱そのものより「今この条件は答えられる範囲の中か」の宣言である。**

## 4. ビジネス的に成立するか

**部品側の費用**

| 項目 | 量 |
|---|---|
| 不揮発領域 | 0.27〜4.8 MiB（397 日） |
| RAM | 数百バイト |
| 演算 | 直線 1 本の残差、5 秒窓の平均と最大、連続平均。**機械学習は使わない**（検出では線形で足り、記憶容量が 86〜19,110 倍になる。[docs/290](290_ml_comparison_results.md)） |
| センサ追加 | **無し。**相電流・DCバス・温度・ゲート駆動は既にある |
| **出荷時の工程** | **掃引が要る。**1 走行分の 7〜35 倍の速度範囲、100 °C の温度範囲。**ここが唯一の実費** |

> **BOM への追加はほぼ無い。**費用は**出荷時の掃引工程**に集中する。

**便益の規模（公開記録から）**

| | |
|---|---|
| 操舵系リコール（2010 年以降） | 715 件 / **2,459 万台** |
| うち EPS | 181 件 / **1,099 万台** |
| うち Assy 交換を含む是正 | 120 件 / **434 万台** |
| **ECU 内部記録だけで交換可否が決まった** | **134.6 万台** |
| 「コードなし」側の原因不明・再現せず | **5.0 倍** |

**便益の金額は出せない。**保証費の内訳も、誤診 1 件あたりの費用も公開されていない
（[docs/189](189_five_limits_tested.md) 限界⑤）。**部品単価 × 台数を掛けることもしない**——
リコールの交換は欠陥が確認された正しい交換であり、無駄ではない。

> **ビジネス的な結論: 費用はほぼ出荷時の掃引工程だけ。便益の金額は公開情報では出せない。**
> **言えるのは、この記録が入る決定点の規模（134.6 万台）と、その決定が今 2 値であることまでである。**
> **「保証費を N% 減らす」は主張しない**（[docs/225](225_recorder_specification.md) 5 章）。

## 5. 何をすれば成立に近づくか

| 足りないもの | 何が要るか |
|---|---|
| 誤報 1 件/時 | 出荷時の登録を **17 倍**長くする。**工程時間の設計判断** |
| 劣化で確実に鳴る | **同型 20 個体以上の run-to-failure。**手元は 6 個体 |
| アシスト低下 % | **内部量と機能出力（トルク）の同時測定。**産業用電動機データが唯一の候補 |
| EPS での検証 | EPS 実機。**公開データに無い** |

## Rule Check
- ユーザの 3 つの問い（何を記録するか／時間が進むと何を報告するか／成立するか）に、節を分けて答えた
- **技術的に成立しないものを、成立するものと同じ大きさの表で書いた**
- **便益の金額を出さなかった。**規模と、決定が 2 値であることまでに留めた
- 費用が出荷時の掃引工程に集中することを、唯一の実費として名指しした
- 外部の相手を前提にした行為を次の一手にしていない（[AGENTS.md](../AGENTS.md) 0 条）
