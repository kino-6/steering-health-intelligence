# 343. 事前登録 — 仮想パワーモジュールで、検出限界と時間を測る

## ユーザ指摘(2026-09-09)

> 「いま持ち込めるのは記録と換算だけで、検出と時間は持ち込めません」
> **「過去何度か記述しましたが、仮想のパワーモジュールを前提におけないの？」**

**置ける。置いていなかった。**[docs/338](338_virtual_circuit_results.md) で出力への影響には仮想回路を使いながら、
**検出と時間には使わず、実素子 6 個で測れないことを「持ち込めない」と書いた。**
[TROUBLES.md](../TROUBLES.md) T38 と同じ型である。

## 実素子 6 個では測れないこと

| | 理由 |
|---|---|
| 検出限界 | **劣化の開始時刻も速度も分からない。**「2〜5/6」は当たり外れの数であって、限界ではない |
| 誤検知率 | 保留した健全区間が **0.07 時間**しかない（[docs/321](321_enrolment_length_results.md)、測定の床 14 件/時） |
| 時間 | 加速係数が無い |

**仮想モジュールなら、3 つとも真値が既知になる。**

## 仮想パワーモジュールの定義

[docs/338](338_virtual_circuit_results.md) の回路に、**時間変化と個体差を足す。**

| 項目 | 値 | 出所 |
|---|---|---|
| 個体数 | **200** | 統計を出すための数。私が置いた |
| R_on の温度係数 | 実素子の実測から（+0.0082 前後、個体差 ±10%） | [docs/333](333_power_module_model_results.md) |
| 測定ノイズの床 | 実素子の実測比から | [docs/331](331_assist_capability_results.md) の健全期散らばり 0.6% |
| **健全期の漂流** | **実素子の健全 run から測った大きさ**（ランダムウォーク） | run 1〜4 の残差 |
| **劣化の速度 D** | **振る。**健全期の漂流に対する比で 0.5〜32 倍 | **私が置く** |
| 劣化の開始時刻 | 各個体でランダム | 私が置く |
| 温度プロファイル | 走行と駐車を繰り返す。振幅と周期を振る | 私が置く |

**実測から取るのは、温度係数・ノイズ床・健全期の漂流の 3 つだけである。**残りは私が置く。

## 手順

1. 200 個体を生成し、半分は健全のまま、半分は途中から劣化させる
2. 各個体を `scripts/eps_health_recorder.py` に通す（出荷時登録 → 運用）
3. **劣化速度 D を振り、D ごとに検出率と誤検知率を出す**
4. **真値が既知なので、検出時点の出力低下も出せる**（[docs/338](338_virtual_circuit_results.md) の換算）
5. 時間は、**劣化速度 D をそのまま時間軸のパラメータとして扱う。**
   「D がこの値なら、検出は出力が X% 落ちた時点」と書く

## 事前に決める判定

| | 基準 |
|---|---|
| **Z1 検出限界** | 誤検知を保留健全群で 1 件/時 以下に保ったまま、**検出率 90% を達成できる最小の D** |
| **Z2 その時点の出力低下** | Z1 の D で、検出時点の出力低下の中央値 |
| **Z3 実素子との整合** | 実素子 6 個の D を同じ定義で測り、**Z1 の限界の上か下かを言う** |

- **Z1 が存在しないなら**（どの D でも 90% に届かないなら）、**この観測量では検出できないと結論する**
- **Z3 で実素子が限界の下にあるなら**、「2〜5/6 だったのは劣化が遅すぎたから」と言える
- **Z3 で実素子が限界の上にあるなら**、実装か観測量に別の問題がある

## この事前登録が外れる条件

- **個体数 200、D の範囲、温度プロファイル、開始時刻の分布は私が置いた**（T2・T35）
- **健全期の漂流をランダムウォークで模した。**実素子の漂流がその形とは限らない
- **仮想であることが結論の限界である。**「仮想モジュールでは検出できる」は
  「実 EPS で検出できる」を意味しない。**言えるのは、どれだけの速度なら検出できるかという設計値だけ**
- 実測から取る 3 つの量も、単体 MOSFET 6 素子・1 試験機のものである
