# Recall Detection Model: Results (v1)

## 結論(事前登録基準に対する判定)

事前登録プロトコル([docs/140](140_recall_detection_protocol.md))を実行した。判定は次のとおり。

> **事前登録した成功基準(凍結操作点でprecision≥0.5かつrecall≥0.3)には届かなかった(precision 0.39 / recall 0.17)。**
> したがってプロトコルの言い方に従い、「群レベル早期識別は本特徴量セット(v1)では実用シグナルとして不成立」と報告する。
> 一方で、**識別信号そのものは明確に存在する**: テストera PR-AUC 0.315(無情報基準0.110の2.9倍)、ROC-AUC 0.783。そして既存の手作りルール(docs/136)をテストeraに適用するとprecision 0.14 / recall 0.02であり、学習モデルはこれを大幅に上回った。

## 実行条件(プロトコルどおり)

- データ: NHTSA苦情フラットファイル全件(126万件がMY2005-2022スコープ)+リコール台帳(操舵系campaign 537件)
- ユニット: cohort=車種×年式、生涯苦情50件以上 → 3,163 cohort
- 学習: event 2013-2018(陽性182 / 計1,255)、テスト: event 2019-2024(陽性119 / 計1,077)。テストは1回だけ実行
- 特徴量6種はT=event−6ヶ月時点、届出日≤Tの苦情のみ
- モデル: 標準化ロジスティック回帰(numpy、決定的)

## 判明した最大のデータ品質問題

**陽性cohortのマッチ率が21%しかない**(台帳2,006件中、苦情側と結合できたのは414件)。
原因は事前登録リスク2のとおり、リコール台帳と苦情DBのMODELTXT表記揺れ(完全一致のみ使用)+活動下限。
つまり本評価は「名前が綺麗に一致した部分集合」での評価であり、マッチング改善はモデル以前の最大の改善余地である。

## Rule Check

1. 事前登録(docs/140)を実行前にコミットし、基準未達をそのまま報告した(`成功/失敗の言い方`条項の履行)
2. テストeraは1回だけ評価し、閾値・係数は学習eraで凍結した
3. 個車予測・原因断定・OEM批判には使っていない。係数と誤差を公開した
4. 内部情報ゼロ(公開フラットファイル2本のみ)

## 次の改訂候補(v2として事前登録し直してから実行する)

1. **モデル名マッチングの改善**(最優先): 正規化(トリム番号除去、"SILVERADO 1500"等の系列統合)でマッチ率を上げる。ラベル自体の穴を塞ぐ話であり、特徴量いじりより先
2. rel_makeの再設計(共線性の解消: shareからの直交化)
3. EPS系campaign限定のサブセット評価(今回未実施のまま残した補助解析)
4. モデルBへの並行着手(波形側の合成劣化感度)

いずれも「テストeraをもう一度見る」ことになるため、**v2プロトコル改訂を先にコミットしてから**実行する(テストの汚染を履歴で管理する)。
