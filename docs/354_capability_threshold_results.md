# 354. 能力の閾値は置ける。予想は 2 つ外れ、外れ方は良いほうだった

[docs/353](353_capability_threshold_protocol.md) の事前登録を実行した。**追加取得ゼロ。**

> **Y3 成立、Y1・Y2 は外れた。**
>
> **「能力が 5% 落ちたら知らせてほしい」は、そのまま逸脱の閾値に翻訳できる。**
> 翻訳に要るのは `slope`・`intercept`・`floor` の 3 つだけで、**すべて出荷時基準値 56 バイトの中にある。**
> 能力 0.95 を課すと逸脱の閾値は **0.79〜0.90 床**に収まり、**検出は 6/6。**
>
> **私は個体の信号対雑音 `S` が 3 倍以上ばらつくと予想したが、1.14 倍しかばらつかなかった**（7.3〜8.3）。
> **ばらつかないので、共通の能力閾値がほぼ共通の逸脱閾値になる。**翻訳で失うものが小さい。

実行: `python3 scripts/capability_threshold.py` / 数表: [data/capability_threshold.tsv](../data/capability_threshold.tsv)

## 翻訳の式

基準温度 `T` で `R0 = slope·T + intercept`、ノイズを `g = floor` として

```
C(d) = √( R0 / (R0 + d·g) )        d(C) = S · (1/C² − 1)        S = R0 / g
```

**`S` はその個体の信号対雑音である。**3 つとも出荷時基準値に入っているので、
**ECU は追加情報なしに `d(C)` を出せる。**

## 能力を揃えたとき（C = 0.95 を全個体に課す）

| 素子 | S | 逸脱の閾値 | 健全窓 | 誤検知 | 件/時 | 検出 |
|---|---|---|---|---|---|---|
| Test_8 | 7.3 | 0.79 床 | 203 | 0 | 0.0 | 成立 |
| Test_9 | 7.6 | 0.82 床 | 182 | 0 | 0.0 | 成立 |
| **Test_10** | 7.3 | 0.79 床 | 180 | **64** | **256.0** | 成立 |
| Test_11 | 8.3 | 0.89 床 | 185 | 0 | 0.0 | 成立 |
| Test_12 | 8.3 | 0.90 床 | 188 | 0 | 0.0 | 成立 |
| Test_14 | 7.9 | 0.85 床 | 189 | 0 | 0.0 | 成立 |

**逸脱の閾値は 0.79 から 0.90 床の間に収まる。**`S` がほぼ同じだからである。

**Test_10 だけが 256 件/時 鳴る。**この素子は出荷時の当てはめが壊れており、
**傾きの符号が負である**（[docs/333](333_power_module_model_results.md)）。
物理的にありえないので、**採否判定の符号チェックで落ちる個体である。**

## 誤検知を揃えたとき（同じ健全区間で 1 件/時 に較正する）

| 素子 | 逸脱の閾値 | 能力に直すと |
|---|---|---|
| Test_8 | 0.31 床 | 0.9791 |
| Test_9 | 0.33 床 | 0.9788 |
| **Test_10** | **4.08 床** | **0.8004** |
| Test_11 | 0.33 床 | 0.9805 |
| Test_12 | 0.32 床 | 0.9810 |
| Test_14 | 0.21 床 | 0.9871 |

**Test_10 を除くと能力の閾値は 0.9788〜0.9871（幅 0.008）に収まる。**
**Test_10 を入れると 0.8004〜0.9871（幅 0.187）に散る。**

## どちらを揃えるべきか

| 揃えるもの | 逸脱の閾値の幅 | 能力の閾値の幅 | Test_10 |
|---|---|---|---|
| **能力**（C = 0.95） | **0.79〜0.90 床** | 0 | 誤検知 256 件/時 |
| 誤検知率（1 件/時） | 0.21〜4.08 床 | 0.8004〜0.9871 | 閾値が 4.08 床まで開く |

**能力を揃えるほうが、逸脱の閾値が狭い帯に収まる。**
誤検知率を揃えると、壊れた個体を救おうとして閾値が 4.08 床まで開き、
**その個体だけ 20 倍鈍い検出器になる。**

## 前に書いた 0.09 は、閾値の幅ではなかった

**本レポートに「警報が出た時点の能力は 0.887〜0.980 で、幅は 0.09」と書いた。訂正する。**
あれは**警報が出た run での能力**であり、**閾値そのものを能力に直した値ではない。**
run は試験段階ごとに 1 点しかないので粗く、run 間の飛びがそのまま幅になっていた。
**閾値を能力に直すと、5 素子で 0.9788〜0.9871（幅 0.008）である。**

## 判定

| | 予想 | 結果 |
|---|---|---|
| **Y1** | `S` の最大/最小 ≥ 3 倍 | **外れ。1.14 倍**（7.3〜8.3） |
| **Y2** | 誤検知の最大/最小 ≥ 10 倍 | **外れ。**5/6 個体が 0 件で、**比の分母が 0 になり倍率が定義できない** |
| **Y3** | 検出 6/6 | **成立** |

**Y2 は「外れた」というより「測れなかった」である。**倍率を判定基準に置いたのが誤りで、
**分母が 0 になりうる比を事前登録した**（[TROUBLES.md](../TROUBLES.md) T41 と同じ形）。
件数そのもので書くべきだった。

## 残る限界

- **`C = 0.95` に根拠は無い。**受け手が言いそうな値として私が置いた（[TROUBLES.md](../TROUBLES.md) T35）
- **健全区間は最短 0.250 時間。4 件/時 より細かい率は区別できない。**「誤検知 0」はそれ以上を意味しない
- **`S` が揃ったのは、同じ型番を同じ試験機で回した 6 素子だからかもしれない。**個体差の母集団ではない
- 翻訳の式は**導通損だけを見ており、熱が拘束する側の式である**（[docs/338](338_virtual_circuit_results.md)）。
  バス電圧が拘束する条件では当てはまらない
- **run は 7 点しかない。**検出「6/6」は率ではなく実例である

## Rule Check
- **外れた予想 2 つを、成立した 1 つと同じ表に書いた**
- **外れ方が良いほうだったことを、そう書いた**（置けないのではなく、置ける）
- **本レポートに書いた 0.09 が別の量だったことを、訂正として書いた**
- **分母が 0 になりうる比を事前登録した誤りを、自分の誤りとして書いた**
- **`C = 0.95` を私が置いたことを明記した**
