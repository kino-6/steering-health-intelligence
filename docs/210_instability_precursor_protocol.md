# 210. 不安定さは水準の変化に先行するか — 事前登録

**結果を1つも見る前に書き、単独でコミットする。**

## なぜこれをやるか

[docs/207](207_mot_cause_breakdown_results.md) / [docs/209](209_mot_nonhydraulic_results.md) で、
**外部観測が断続故障の前駆を捉えられない**ことが6系統目まで確定した。
残るのは部品内部だが、**公開データに「出たり消えたりする故障」が存在しない。**
KAISTの層間短絡は人工的な恒久短絡であり、点きっぱなしである。

**しかしデータの見方を変えていない。**
docs/165〜209 は一貫して**中央値**(run毎の median、20秒窓の基本波振幅)しか使っていない。

> **断続故障とは、物理的には「不安定さ」である。**
> 接触が微妙になった部品は、平均値がずれる前に**ばらつきが増える。**

**記録ごとのばらつきは一度も見ていない。**NASA MOSFETは1 runあたり定常記録が5,191〜18,351点あり、
これまでその**中央値1つ**に潰していた。

## 問い

> **劣化が進むとき、観測量の「ばらつき」は「水準」より先に動くか。**

先に動くなら、**不安定さを見る監視は、水準に閾値を置く監視より早い。**
それは [docs/185](185_misdiagnosis_quantified.md) が測った「再現しないから原因不明で返される」問題に、
機構の側から直接対応する。

## 測るもの(実行前に固定)

対象は NASA PCoE MOSFET、7 run 揃った6デバイス([docs/165](165_precursor_protocol.md) と同一)。

各 run について、導通ゲート([docs/166](166_precursor_results_v1.md))を通した定常記録から:

```
残差   r_k = R_on,k − (a · T_pkg,k + b)      a, b は run 1〜3 で当てた個体固有の温度モデル
水準   L   = median(r_k)                      これまで見てきた量
ばらつき V = median(|r_k − median(r_k)|) / median(R_on,k)     ロバストな相対分散
```

**ばらつきは温度正規化した残差に対して測る。**生の R_on のばらつきには run 内の温度変動が入るためである。
中央絶対偏差(MAD)を使うのは、記録数が run によって 5,191〜18,351 と3倍以上違うためである。

各量を run 1〜3 の平均と標準偏差で基準化し、**基準の3σを超えた最初の run** を発火点とする。

## 判定基準(いま固定する)

| # | 基準 | 閾値 |
|---|---|---|
| **D1 ばらつきは増えるか** | Spearman ρ(run, V) ≥ 0.8 | **6デバイス中4以上** |
| **D2 ばらつきは水準に先行するか** | V の発火 run ≤ L の発火 run | **6デバイス中4以上** |
| **D2b 厳密に先行するか** | V の発火 run < L の発火 run | **6デバイス中3以上** |
| **D3** | 両者の発火 run と余裕を報告 | **閾値なし** |

- **D2 が落ちたら、不安定さは先行しなかったと書く。**この研究の主張から「不安定さを見る」を外す
- **D2 が通り D2b が落ちた場合は「同時であって先行ではない」と書く。**同着を先行と読み替えない
- 閾値比較は `scripts/lib_discipline.py` の `passes()` を使う([docs/205](205_sign_free_deviation_results.md) の浮動小数点事故の再発防止)
- **v2は作らない**

## 副次(判定にしない、報告のみ)

KAIST PMSM の20秒窓を2秒×10に割ったときの、**ばらつきの severity 依存**。
**人工的な恒久短絡なので不安定さが増える理由は無い**が、増えるなら記録する価値がある。
[docs/204](204_sign_free_deviation_protocol.md) で粒度の分母として計算した量を、信号として見る。

## 事前に認めておくこと

- **これはMOSFETであってEPSではない。**[docs/199](199_pulse_thermal_results.md) のとおり、
  この試験機は素子を能動領域のヒーターとして使っており、スイッチとして動かしていない
- **加速試験である。**実車の時間軸に対応しない
- **run 内の記録数が3倍以上違う。**MADで緩和するが、完全には除けない
- **ばらつきが増えても「断続故障が起きた」ことにはならない。**言えるのは
  **「水準より先に動く量がある」**までである
- **D1/D2 が通っても、EPSで同じことが起きる保証は無い**

## Rule Check

- **一度も見ていない量に手を付ける理由(断続＝不安定)を先に書いた**
- D2 と D2b を分け、**同着を先行と読み替える余地を消した**
- 落ちた場合に主張から何を外すかを先に決めた
- 浮動小数点の比較に `passes()` を使うと明記した
- KAIST側は「増える理由が無い」と先に書いたうえで報告のみとした
