# 317. 形で分けると 6/6。本物の劣化で、初めて検出と沈黙が同時に立った

[docs/316](316_changepoint_protocol.md) の事前登録を実行した。**追加取得ゼロ。**

> **G1 6/6、G2 3/3。**
> **6 素子すべてで、run 4 の誤報が 0 のまま、run 5〜7 で発火する。**
> **水準の閾値では 5 通りの手当てすべてで落ちていた 3 素子（Test_9・11・12）が、3 つとも救われた。**
>
> **本Repoで、本物の劣化に対して検出と沈黙が同時に立ったのは初めてである。**

実行: `python3 scripts/changepoint.py` / 数表: [data/changepoint.tsv](../data/changepoint.tsv)

## 変えたのは統計量だけ

指紋（run 1 前半）・残差（動作点に対する直線からの、床で割ったもの）・累積ストレス軸は
[docs/315](315_boundary_vs_refresh_results.md) の境界案と**同一**。**見る量を水準から傾きに変えた。**

```
較正区間で、残差の 累積ストレス に対する傾き a_cal と、そのばらつき s_cal を出す
運用中、直近 W 標本の傾き a_now を出す
統計量 = |a_now − a_cal| / s_cal        W は {2000, 5000, 10000} を OR
```

## 試験機の産物ではないことの確認

**run の長さが、較正区間（約 2,600 標本）と運用区間（約 12,000〜17,500 標本）で 5〜6 倍違う。**
**窓が run 境界をまたぐかどうかが変わるので、境界の産物でないかを先に確かめた。**

初発火の run 内での位置: **65% / 69% / 7% / 67% / 26% / 40%。**
**run の先頭に固まっていない。**唯一 7% の Test_10 は、毎 run の開始に過渡を持つ素子である
（[docs/273](273_power_stage_observables_results.md) が特定済み）。

## なぜ効いたか

[docs/315](315_boundary_vs_refresh_results.md) が特定したとおり:

| | 健全期の漂流 | 劣化の立ち上がり |
|---|---|---|
| 大きさ | 4 run で 0.2 床 | 1 run で 0.7〜1.5 床 |
| **形** | **傾きが一定** | **傾きが変わる** |

**Test_9・11・12 は、大きさが同じ桁だった。**だから水準では分けられなかった。
**傾きの変化を見れば、大きさが同じでも分かれる。**

## 残る限界

- **達成できた誤報率は 14〜18 件/時**（設計 1 件/時）。較正区間が 2,600 標本しかなく、
  1/108,000 の分位点は刻めない（[docs/282](282_igbt_recorder_results.md) の予算）。**「誤報 0」は「14〜18 件/時より少ない」まで**
- **Test_11 は故障 run で鳴る。先行がない**
- **s_cal は run 境界をまたぐ窓から推定している。**運用区間の窓は run 内に収まる。**この非対称は消せていない**
- ヒーター動作の 1 試験機・6 素子。**率ではなく存在証明**
- **W の格子 {2000, 5000, 10000} は仮定である**（[TROUBLES.md](../TROUBLES.md) T2）

## 仕様に足すこと

> **遅い側の判定を、水準ではなく傾きの変化にする。**
> 較正区間で残差の累積ストレスに対する傾きとそのばらつきを記録し（**指紋に 2 値追加**）、
> 運用中は直近 W の傾きとの差を、そのばらつきで割って見る。
> **健全期の単調な漂流は傾きが一定なので鳴らない。**

**指紋は 48 バイト → 56 バイト**（float32 が 2 つ増える）。**8 チャネルで 384 → 448 バイト。**

## Rule Check
- **6/6 を報告する前に、試験機の産物でないかを確かめた**（初発火の run 内位置）
- **誤報 0 を「14〜18 件/時より少ない」と読み替えた。**設計値を満たすとは書いていない
- **Test_11 に先行が無いことを、成功した 5 素子と同じ表に書いた**
- s_cal の推定が非対称であることを、消せていない限界として挙げた
