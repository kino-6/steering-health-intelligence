# 車輪側操舵ユニットの平易な深掘り

## 結論

前回までの `road wheel actuator` という書き方は分かりにくい。
ここでは、以後 **車輪側操舵ユニット** と呼ぶ。

これは、運転者がハンドルを回した力を機械的な軸で車輪へ伝える代わりに、電気信号を受けて前輪を左右に動かす部品である。
従来のラック、ギア、モータ、制御器の役割を、電子制御前提で受け持つ部分と考えるとよい。

公開情報を見る限り、この部品そのものは重要である。
Boschは、ハンドル側の部品、車輪側の部品、ソフト機能でsteer-by-wireが成り立つと説明している。
ZFは、運転者または自動運転側の操舵要求が電子的に前輪側のユニットへ送られ、そこが前輪を動かすと説明している。
Schaefflerも、車輪側操舵ユニットが機械的なつながりなしに車両を制御し、従来のステアリング機構を置き換えると説明している。

ただし、事業としてはまだ強くない。
なぜなら、この部品の異常時説明は、既に安全設計、認証、診断の既存業務にかなり含まれているからである。
VCAは、steer-by-wireでは文書、故障時の考え方、検証、安全分析が必要だと説明している。
NHTSAの公開レポートも、モータ、制御器、通信、運転者への表示、DTC候補などを扱っている。
ASAM SOVDも、ソフトウェア化した車両の診断、故障情報、ソフト更新、ログ取得を標準領域として扱う。

したがって、EPSサプライヤとしての現時点判断は次である。

> 車輪側操舵ユニットを単独の新商材にするのは弱い。残すなら、「この部品に異常が起きた時、車はどう振る舞い、運転者には何が見え、診断では何が読め、サプライヤは何を言ってはいけないか」を平易な1枚にする用途だけである。これも既存の安全資料や認証資料の要約にしかならないなら止める。

## 市場需要

市場側で起きている変化は、ハンドルと前輪の間にあった機械的なつながりをなくす車が出始めていることだ。

従来のEPSでは、電動アシストが落ちても、運転者の力が機械的につながった操舵系へ残る。
一方、steer-by-wireでは、ハンドル操作は信号になり、前輪を動かす側の部品がその信号を受けて車輪を切る。
このため、車輪側の部品に異常が起きた時の説明責任が重くなる。

公開情報から言える需要はここまでである。

- 車輪側操舵ユニットは、steer-by-wireで中心的な部品になる
- この部品は、前輪の角度、モータ、センサ、電源、通信、ソフト制御と関係する
- 異常時には、運転者への警告、残る操舵能力、診断で読める情報を説明する必要がある

ただし、公開情報だけでは、OEMがこの整理にお金を払うとは言えない。
また、対象EPSサプライヤの既存安全資料に同じ整理がないとも言えない。

## 未解決の痛み

痛みがあるとすれば、技術そのものではなく、説明が部署をまたぐことだ。

車輪側操舵ユニットで異常が起きた時、説明は1部署で閉じない。

- システム設計は、残る操舵能力と制限動作を説明する
- 安全設計は、危険状態を避ける考え方を説明する
- 診断設計は、DTCや読み出し項目で何が分かるかを説明する
- ソフト担当は、ソフト番号、設定値、更新後確認を説明する
- 顧客技術窓口は、OEMへ「分かっていること」と「断定しないこと」を説明する

この横断説明が既に自然にできるなら、新しい価値はない。
逆に、各部署の資料はあるが、OEM向けの1枚に直すと毎回時間がかかるなら、狭い価値が残る。

## 仮説

売り物にする前の仮説は、かなり小さく置く。

> 車輪側操舵ユニットの異常時について、部品境界で言えることと言ってはいけないことを、平易な日本語で1枚にする。これが既存資料の要約を超え、設計レビュー、診断設計、RFQ回答、顧客説明にそのまま転記できるなら、探索を1段だけ続ける。

ここで大事なのは、故障予測でも追加ログでもない。
「車輪側の部品として、どこまで責任を持って説明できるか」を切ることである。

## 解決策

初期に作るなら、次の1枚だけでよい。

| 見出し | 平易な中身 |
|---|---|
| 何が起きたか | 車輪を動かす側の冗長系が一部落ちた |
| 車はどうするか | 残る経路で操舵を続ける、または低速退避などに制限する |
| 運転者には何が見えるか | 警告、音、退避要求、出力制限など |
| 診断で何が読めるか | どの経路が落ちたか、発生時の速度/電圧/温度/通信状態など |
| サプライヤが言えること | 部品境界内で検知した状態、制限動作、読み出せる事実 |
| サプライヤが言ってはいけないこと | 根本原因、車両全体の安全認証、保証費削減、将来故障予測 |

この1枚が使えるなら、次に10ケースへ広げる。
使えないなら、ここで止める。

## 買い手 / 利用者

現時点で「買い手」はまだ言えない。
公開情報では予算の存在が見えないためである。

利用者としてあり得るのは、EPSサプライヤ内の次の人たちである。

- システム設計
- 安全設計
- 診断設計
- ソフト / キャリブレーション担当
- 顧客技術窓口
- 営業技術

ただし、これは推定である。
この人たちが既に同じ1枚を作れているなら、商材化しない。

## 初期提供物

商品名はまだ作らない。
初期提供物は、次の3点だけにする。

1. 車輪側操舵ユニットの異常時説明1枚
2. 公開情報で言えること / 言えないこと一覧
3. 既存の安全・認証・診断資料の要約にしかなっていないかを見る判定表

## 検証方法

内部資料を使わない方針なので、検証は公開情報だけで行う。

見ること:

- 公開サプライヤ資料から、車輪側操舵ユニットの役割を平易に説明できるか
- VCA / R79 / NHTSA / ASAM SOVDにある既存論点と重複していないか
- 1枚にした時、設計・安全・診断・顧客説明の境界が分かりやすくなるか

見ないこと:

- 対象EPSの内部DTC
- 対象EPSの安全分析
- 対象OEMのRFQ
- 既存顧客回答テンプレート

## Kill条件

次のどれかに当たれば止める。

- 1枚にしても、VCA、R79、NHTSAの要約にしかならない
- 車輪側操舵ユニット固有の説明にならず、一般的な安全説明で終わる
- 診断で何を読めるかが公開情報だけでは何も言えない
- EPSサプライヤが言えること / 言ってはいけないことの境界が明確にならない
- 利用者がシステム設計、安全設計、診断設計、顧客技術窓口のどれにも刺さらない

## EPSサプライヤとしての言い方

EPSサプライヤとして言えること:

> 機械的なつながりをなくす操舵では、車輪を動かす側の部品が、操舵機能、異常検知、残る操舵能力、運転者への警告、診断情報の中心になる。公開情報だけでも、この部品について「言えること」と「言ってはいけないこと」を1枚に整理することはできる。

まだ言ってはいけないこと:

- この整理にOEMが支払う
- 対象EPSの診断が不足している
- 対象EPSの安全分析が不足している
- 車両全体の安全認証を代替できる
- 故障予測や保証費削減につながる

次に見る最小項目:

> 「車輪を動かす側の冗長系が一部落ちた」という1ケースを、英語略語なしの日本語1枚にして、既存安全・認証資料の要約を超えるかを見る。超えなければ、この方向は止める。
