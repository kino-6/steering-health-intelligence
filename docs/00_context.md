# 00. Context

## Original Motivation

当初のテーマは、ECU故障予測を Vehicle Health Management 市場の中でどうビジネス化できるか、というものだった。

特に、EPS / ステアリング制御系ECUについて、以下のような仮説があった。

- ECUは基本的に壊れにくい
- メンテナンスフリーで成立している商品である
- そのため、エンドユーザ向けに「壊れそうです」と警告するだけではメーカーにとってコスト増になり得る
- 一方で、操舵系は壊れた場合の影響が大きい
- フリートにとってEPS故障は頻度が低すぎるが、OEMなら市場に出した全車両を巨大なfleetとして見られる可能性がある
- ただし、ECUサプライヤが市場車両ログへ常時アクセスできるわけではない

## Key Tension

この企画の難しさは、以下の矛盾にある。

```text
EPS / ECUは壊れにくい
  → 故障予測の頻度価値が低い

しかし、操舵系は壊れた時の影響が大きい
  → 安全・品質・リコール観点では価値がある

ECUサプライヤは深い内部状態を知っている
  → 診断指標は作れる

しかし、市場全体のデータはOEM側にある
  → サプライヤ単独でRisk Triageするのは難しい
```

## Working Reframe

「ECU故障予測」ではなく、以下のように再定義する。

> 操舵ECUの市場不具合解析において、DTCだけでは不足する内部状態・一時異常・使用条件を証跡として残し、OEM / Tier1間の原因切り分けと品質説明を早める。

## Terminology

| Term | Meaning |
|---|---|
| DTC | Diagnostic Trouble Code。故障診断コード。 |
| Freeze Frame | DTC発生時などの周辺状態を保存した情報。 |
| Extended Data | DTCに紐づく追加診断情報。 |
| Health Indicator | 故障判定ではなく、状態や余裕度を示す指標。 |
| Weak Signal | 明確な故障ではないが、将来の問題や調査対象になり得る弱い兆候。 |
| Risk Triage | 調査優先度を分類すること。 |
| Diagnostic Evidence | 原因解析や品質説明の根拠となる診断証跡。 |
