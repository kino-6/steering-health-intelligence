# 265. 記録器は動いた。ただしバイト数の見積もりが小さすぎた

[docs/264](264_element_v2_protocol.md) の事前登録を実行した。**追加取得ゼロ。**

> **動く。**個体基準の指紋を採り、逸脱を出し、掃引範囲の外では黙り、
> 入力を8ビットに落としても判定が一つも変わらない。
>
> **ただし [docs/196](196_eps_health_element.md) の 36バイト・27バイトは、実際に詰めたら入らなかった。**
> **指紋は48バイト、1事象は30バイト。**紙の上の掛け算で、欄を数え落としていた。

実行: `python3 scripts/element_v2.py` / 数表: [data/element_v2.tsv](../data/element_v2.tsv)

## 判定

| # | 基準 | 結果 |
|---|---|---|
| **M1** | 禁じた出力(能力値・予測・箇所)を持たない | **PASS** |
| **M2** | 指紋が36バイト以内 | **48バイト。FAIL** |
| **M3** | 掃引範囲の外で黙り、内では黙らない | **489窓/489、11窓/11。PASS** |
| **M4** | 8ビットに量子化しても判定が一致 | **500/500 = 100%。PASS** |
| **M5** | 1事象が27バイト以内 | **30バイト。FAIL** |

## M2・M5 — 紙の掛け算が欄を数え落としていた

[docs/196](196_eps_health_element.md) は指紋を「float32 × 9 = 36バイト、2機構分」と書いた。
**1機構あたり4.5個である。**実際に動く指紋が要るのは、1機構あたり**6個**である。

| 欄 | docs/196 に入っていたか |
|---|---|
| 傾き・基準値・床 | 入っていた |
| **掃引した動作点範囲の下限・上限** | **数え落としていた。**[docs/225](225_recorder_specification.md) が後から要求した |
| 指紋の版(再取得の判別) | 数え落としていた |

**「掃引した動作点範囲」は [docs/225](225_recorder_specification.md) 本文に明記してある。**
**書いてあるのにバイト数に入っていなかった。**

| | docs/196 の見積もり | 実測 |
|---|---|---|
| 指紋(動作点1次元 × 2機構) | 36バイト | **48バイト** |
| **指紋(動作点3次元 × 2機構)** | — | **96バイト** |
| 1事象 | 27バイト | **30バイト** |

**動作点3次元とは、[docs/225](225_recorder_specification.md) が挙げる速度・負荷・温度である。**
36バイトという数字は、**動作点が1つしかない場合の値だった。**

> **結論は変わらない。「容量は障害にならない」は 96バイトでも 30バイトでも変わらない。**
> **変わったのは数字であり、数字は直す。**

## M3 — 最初の検定は検定になっていなかった

**初回は範囲外の窓が500中1しかなく、100%という数字に意味が無かった。**
試験機は各runで同じ温度域を掃引するため、前半を指紋にしても後半がほぼ同じ範囲に収まる。

**指紋の掃引幅を意図的に半分に狭めて測り直した。**これは [docs/227](227_filling_spec_blanks_results.md) が
測った失敗——**指紋を狭い範囲でしか採らない**——そのものである。

| | 窓数 | 沈黙 |
|---|---|---|
| 掃引範囲の外 | 489 | **489(100%)** |
| 掃引範囲の内 | 11 | **0(0%)** |

**「宣言しない」は仕様どおりに働く。**

## M4 — 8ビットで判定が一つも変わらない

500窓すべてで、**有効性も発火の有無も一致した。**
[docs/261](261_no_data_decisions_results.md) は「8ビットで床が動かない」を示したが、
**床が動かないことと判定が変わらないことは別である。**本検定が後者を示した。

## 往復の丸め — 等値比較は誤った検定だった

初回は「詰めて戻して同じか」を**厳密な等値**で見て不成立にした。
float32はfloat64を再現しないので、**等値は検定として誤っている。**

**丸めが逸脱をどれだけ動かすかで測り直した: 最大 2.1×10⁻⁷。**発火閾値の **2.1×10⁻⁸倍**。
**判定は動かない。**

## 取り下げた実装を置いたままにしていた

`scripts/eps_health_element.py` は**能力値を出す要素**として書かれている。
その能力値は [docs/199](199_pulse_thermal_results.md) と [docs/203](203_cross_machine_replication_results.md) で
**取り下げてある。**にもかかわらずコードは残り、**答えとコードが食い違ったままだった。**

**新しい型として [TROUBLES.md](../TROUBLES.md) に T23 を立てた。**

## この実装が示さないこと

- **EPS実機で動かしていない。**NASA MOSFET 6素子を入力にした
- **M3・M4は注入と量子化による検査であり、本物の故障ではない**
- **動作点の3次元のうち、公開データが持つのは1つだけである。**
  残り2つは**欄を確保しただけで、値は入れていない**(偽の値を入れていない)
