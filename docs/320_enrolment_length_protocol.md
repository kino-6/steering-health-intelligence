# 320. 事前登録 — 出荷ラインの掃引を長くすれば 1 件/時 に届くのか

## なぜこれを次に置くか

[docs/318](318_unit_ledger.md) の 274 倍も、[docs/319](319_unit_trace.md) の「0 バイトか 1,320 バイトか」も、
**すべて 1 つの量に落ちる——較正できた誤報率が 281 件/時 で、要求の 1 件/時 に 281 倍足りない。**

[docs/282](282_igbt_recorder_results.md) の予算はこう言っている:

> 閾値は登録標本の分位点である。**k 標本は 1/k より細かい率を表せない。**

**この読みが正しければ、答えは「掃引を長くすればよい」だけで、必要な長さは計算できる。**
10 Hz・16 検定を束ねて 1 件/時 なら、1/(36,000 × 16) = **576,000 標本 = 16 時間**。
**1 台 16 時間の掃引は製造ラインに乗らない。**だから、この読みが正しいかどうかで話が変わる。

**しかし別の読みがある。**[docs/299](299_bank_results.md) は、閾値を下げると健全期の漂流が誤報になることを見ている。
**登録を長くすれば分位点は細かくなるが、長い登録はより多くの漂流を含む。**
分位点が細かくなる効果と、漂流でばらつきが広がる効果は逆を向く。

## 問い

**登録標本数 k を増やしたとき、保留した健全区間で実測される誤報率は 1/k で下がるのか、途中で頭打ちになるのか。**

## 手順

データ: NASA MOSFET 熱加速、6 素子（[docs/295](295_all_seven_runs.md) の 7 run すべて）。

1. 指紋は run 1 前半で固定（[docs/297](297_bank_protocol.md)）
2. 較正区間（run 1 後半 + run 2〜3）から、**先頭 k 標本だけ**を使って閾値を出す。
   k は **{500, 1000, 2000, 5000, 10000, 20000, 全部}**
3. **保留した健全区間（run 4）で、実際に鳴った回数を数える。**分位点の名目値ではなく実測
4. 検出は run 5〜7 での発火で見る（[docs/317](317_changepoint_results.md) と同じ、傾きの変化）
5. 統計量・窓・閾値の出し方は [docs/316](316_changepoint_protocol.md) から変えない。**変えるのは k だけ**

## 事前に決める判定

| | 予測 | 意味 |
|---|---|---|
| **H1 予算律速** | k を 40 倍にすると、実測誤報率が **1/40 の 2 倍以内**まで下がる | 掃引を長くすれば届く。**必要な長さが計算できる** |
| **H2 漂流律速** | 最大の k での実測誤報率が、1/k の予測より **5 倍以上**高いところで止まる | **どれだけ掃引しても届かない。**仕様の 1 件/時 を、登録が支えられる値に書き換える必要がある |

**H1 と H2 の間（2〜5 倍）に落ちたら、そう書く。**どちらかに寄せない。

**検出も同時に見る。**k を増やして誤報が下がっても、run 5〜7 で鳴らなくなったら意味がない。
**6 素子中いくつで鳴り続けるかを、誤報率と同じ表に書く**（[TROUBLES.md](../TROUBLES.md) T28——片側だけ報告しない）。

## この事前登録が外れる条件

- 較正区間が 6 素子で約 7,700 標本しかない。**k = 20000 と「全部」は同じになる素子がある。**
  そのときは到達した最大の k で判定し、**40 倍の比較ができなかったと書く**
- run 4 の長さは素子ごとに違う。**誤報は件数ではなく件/時 に直して比べる**
- ヒーター動作の 1 試験機・6 素子。**率ではなく存在証明**
