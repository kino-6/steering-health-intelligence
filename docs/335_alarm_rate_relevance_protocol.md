# 335. 事前登録 — 誤報率の要求は、そもそも効いているのか

## この問いを立てた理由

[docs/321](321_enrolment_length_results.md) は「1 件/時 を較正するには 1 台 16 時間かかる」と出し、
[docs/327](327_supply_tolerance_results.md) は「検定を減らして短縮する道も塞がっている」と出した。
**そこで止まっていた。**

[TROUBLES.md](../TROUBLES.md) T38 の規則を、この「不可能」に当てる。**2 つに割る。**

| | 状態 |
|---|---|
| 部品が 1 件/時 を達成できないと決まっているのか | **決まっている**（工程時間から） |
| **そもそも 1 件/時 という要求はどこから来たのか** | **私が置いた**（[docs/248](248_false_alarm_tradeoff_results.md)） |

**[docs/248](248_false_alarm_tradeoff_results.md) の L0〜L3 の格子は私が決めたもので、
その中の 1 回/時 に「実用水準」という名前を付けたのも私である。**
外部の要求ではない（[TROUBLES.md](../TROUBLES.md) T2）。

## そして受け手が読むものが変わった

[docs/334](334_capability_trace.md) で、**受け手はバスフレームから連続量を読めることが分かった。**
連続量は逸脱そのものから計算し、**閾値を通っていない。**

> **閾値が決めているのは「不揮発に 30 バイトを書くかどうか」だけではないか。**
> **劣化を読み取る能力とは無関係ではないか。**

これが正しければ、**16 時間という壁は、要らない要求のために立っていたことになる。**

## 問い

**誤報の閾値を動かしたとき、健全期と劣化期を分ける能力は変わるか。**

## 手順

データ: NASA MOSFET 6 素子 × 7 run。

1. 誤報率の目標を **1, 10, 100, 281, 1000 件/時** と振る
2. 各目標で出荷時基準値を較正し直す（閾値だけが動く）
3. 各目標について 2 つを測る
   - **A 記録の量**: run 4〜7 で不揮発に書かれる 30 バイト記録の件数
   - **B 分離の能力**: [docs/334](334_capability_trace.md) の連続量で、
     健全期（run 1〜4）と劣化期（run 5〜7）の分離を**効果量**で測る
     （差 ÷ 健全期の標準偏差）
4. **B が目標によって動くかを見る**

## 事前に決める判定

| | 基準 |
|---|---|
| **X1 記録量は閾値で動く** | A が目標 1 件/時 と 1000 件/時 で **10 倍以上**違う |
| **X2 分離は閾値で動かない** | B の最大と最小の比が **1.2 倍以内**（6 素子の中央値で） |

**X1 と X2 が両方成立したら、次のように結論する。**

> **誤報率の要求は、記憶容量の設計値であって、検出能力の要求ではない。**
> **1 件/時 に較正できないことは、劣化を読めないことを意味しない。**
> **[docs/321](321_enrolment_length_results.md) の 16 時間は、記録件数を絞りたい場合にだけ要る。**

**X2 が外れたら**（分離が閾値で動いたら）、**閾値は検出能力に効いている**ことになり、
16 時間の壁はそのまま残る。**そう書く。**

## この事前登録が外れる条件

- **効果量という測り方は私が選んだ。**別の測り方なら別の数字になる
- **1〜1000 件/時 の刻みも私が置いた**（[TROUBLES.md](../TROUBLES.md) T2・T35）
- 連続量は 50 秒ぶんをまとめたもの。**まとめる長さも私が決めた**
- 単体 MOSFET・6 素子・1 試験機。**EPS ではない。率ではなく存在証明**
- **この文書は「16 時間は要らない」と言うものではない。**
  要るかどうかが**何で決まるか**を測るものである
