# 177. SOTIF方向の判定更新 — 需要は硬くなり、席は埋まり始めた

## 判断

**1. SOTIF運用フェーズ監視の需要は、2026年6月に「規格の要求」から「世界規模の規制」へ格上げされた。**

**2. 同時に、競合(Nexteer)は既に量産投入している。** [docs/146](146_business_framework_and_roadmap.md) が「時限の窓」と呼んだものは、**開いたと同時に最初の席が埋まった**。

**3. KQ1(SOTIF由来要求が部品RFQへ降りているか)は依然として内部依存だが、構造は公開情報で閉じた。** 残る不確かさは「存在するか」ではなく「どの範囲まで降りているか」である(本文書末尾で訂正済み)。

[docs/151](151_high_rate_model_crosscheck.md) の観測台帳に登録した2項目——「規制の実装」と「競合動向」——が**両方とも発火した**。

## S1: ISO 21448 の運用フェーズ要求(公開情報で確認)

ISO 21448:2022 は市場投入後のフィールド監視を規格本文に含む。要点は次である。

> **フィールドデータは、市場投入後に未知のシナリオを発見する主たる手段である。**

SOTIF活動の目的は、未知かつ危険な領域を許容残余まで縮小することであり、そのために運用フェーズの活動が定義されている。
**一度の適合で終わらない。**

## S2: 規制は運用フェーズ監視を強制している(これが今回の最大の更新)

### EU: Implementing Regulation (EU) 2022/1426(2022-08-05 発効)

自動運転システム(ADS)の型式認証規則。柱の一つが **ISMR(In-Service Monitoring and Reporting)** である。

- 収集義務: 「フィールドにおけるADSの実運用安全性能の**証拠を得るために**製造者が収集するデータ」
- 報告義務: ADSの起動/停止、緊急動作、衝突検知、**ADSの故障(記述付き)**、**車両の故障**、最小リスクマヌーバの作動
- そして本研究にとって決定的な一文:

> 製造者は、**ADSの安全性と継続的な適合をライフタイムにわたって管理するプロセス**を持たなければならない
> (**部品の摩耗、とくにセンサ**、新しい交通シナリオ 等)

**「部品の摩耗」が条文の例示に入っている。** ただし**部品レベルの劣化指標は規定されていない**。

### 世界: UN ADS GTR(2026年6月採択)

- **2026年6月22〜26日、WP.29 第199回会合(ジュネーブ)で採択**。約10年の開発を経て
- 共同開発: **中国、EU、英国、米国、カナダ、日本**
- 内容: 製造者に**監査可能なライフサイクル全体の安全管理システム(SMS)**の構築・維持を義務づける
- 市場投入後: **継続的な性能監視**と、重大な安全事象の当局への**報告義務**
- 安全論証は「有能で注意深い人間ドライバーと少なくとも同等に安全」であることの文書化された safety case による
- 発効: 採択の約1か月後
- **部品レベルの劣化には言及していない**(EU規則と同じ構造)

### 適用の実際

| 枠組み | 拘束力 | 日本の位置 |
|---|---|---|
| GTR(1998年協定) | **非拘束のテンプレート**。各国が個別に国内法化を判断 | 参加国 |
| UN Regulation(1958年協定) | **採択されれば拘束力あり**。参加国間で相互承認 | **加盟。EUに追随する見込み** |

## S2の含意: 需要の性質が変わった

| | 従来([docs/126](126_steering_predictive_diagnostics_sotif_contribution_prospect.md), [docs/128](128_steering_predictive_diagnostics_sotif_public_signal_watch.md)) | **現在** |
|---|---|---|
| 運用フェーズ監視 | 規格(ISO 21448)の要求 | **規制の義務**。EU発効済み、世界枠組み採択済み |
| 対象 | 任意の安全活動 | **型式認証と継続適合の条件** |
| 期限 | なし | **発効済み**(EU 2022、GTR 2026-07頃) |

**「あったら良い」から「無いと売れない」へ変わった。** これは需要の硬さとして最上位の証拠である
([AGENTS.md](../AGENTS.md) 7条: 規制の時間表は公開の構造証拠)。

## S3: KQ1を外から組み立てる

規制はOEM(製造者)を名指しする。部品サプライヤへの流れは、**規格が構造として用意している**。

```
規制(EU 2022/1426 / UN ADS GTR)
   → OEMのSMS + safety case(ライフサイクル全体)
      → 部品を「文脈外で開発された要素」として組み込む
         → ISO 21448 の SOTIF-EooC(docs/128)
            = 部品側が「使われ方の前提」と「機能不足の許容発生率」を仮定として差し出す
               → その仮定の市場検証 = 運用フェーズのフィールド監視
```

**この経路の各段は、すべて公開文書で確認できる。** したがってKQ1について言えることは次に更新される。

- 旧: 「SOTIF由来要求が部品RFQに降りている公開確認はできない」([docs/128](128_steering_predictive_diagnostics_sotif_public_signal_watch.md))
- 新: **「経路は公開文書で閉じた。降りてくること自体は構造的に決まっている」**

> **訂正(2026-08-24)**: 当初ここに「未確認なのは自社プログラムへの到達時期だけである」と書いた。**誤りである。**
> 本研究は個人研究であり「自社」は存在しない([AGENTS.md](../AGENTS.md) 0条)。**構造が公開情報で閉じた時点で、この問いは終わっている。**

### ただし2つの限定(過大評価しない)

1. **対象はADS搭載車である。** 一般の人間運転車のEPSには、この義務は及ばない。**需要量はADS普及に連動する**
2. **条文が例示するのは「センサ」であって、操舵アクチュエータではない。** 摩耗の管理義務は一般論として書かれており、
   操舵系を名指ししていない。**「部品の摩耗が対象に入っている」までは言えるが、「操舵系が名指しされている」とは言えない**

> **訂正(2026-08-24、[docs/178](178_sotif_straight_answer.md))**: 本節は「席が埋まり始めた」と結論したが、
> Nexteer公式リリースを読むと**取られた席は「予知保全・フリート稼働率」であり、ISO 26262の枠内**である。
> **SOTIFへの言及は一切ない。SOTIF-EooCの席は空いている。**

## S4: 席は埋まり始めた(競合)

**Nexteer MotionIQ / Health は量産投入済みである。**

- 2025年8月11日 発表。**予知ソフトウェアとAI仮想センサで、操舵およびシャシ部品・タイヤの電気的/機械的機能を継続監視**し、
  「**問題が起きる前に予測する**」と明示
- **量産開始済み**。中国の大手NEVメーカーの量産乗用車に搭載され、世界初の完全drive-by-wireシャシ車を実現
- 同社はSbWも量産開始しており、MotionIQ は Motion-by-Wire ポートフォリオの一部

[docs/146](146_business_framework_and_roadmap.md) は「競合の実弾(継続投資・量産開発)は支払い意思の最も硬い証拠」と書いた。**その証拠が揃った。**

**両刃である。**

- **需要は実在する。** 競合が作り、OEMが買った。事業仮説は競合の行動によって裏づけられた
- **席は埋まりつつある。** 競合は量産、本研究は仮説段階。**カテゴリを作る側ではなく、RFQで仕様に応える側**になる

## S5: 判定

**SOTIF方向(=[docs/126](126_steering_predictive_diagnostics_sotif_contribution_prospect.md) option c、運用フェーズ監視への部品側インプット)の判定を、
「実施条件待ち」から「需要は確定。ただし先行者あり」へ更新する。**

| 項目 | 更新前 | 更新後 |
|---|---|---|
| 需要の実在 | 公算が補強された程度 | **確定**(規制の義務 + 競合の量産) |
| 参入の位置 | 空席 | **先行者あり**。カテゴリ創出ではなくRFQ対応 |
| KQ1 | 内部資料条件 | **経路は公開で閉じた。問いは終了** |
| 差別化 | 「部品内部の観測事実」 | **同じ。ただし対OEM基盤には効くが、対他EPSサプライヤには効かない** |

### 差別化についての正直な評価

[docs/163](163_per_unit_baselining.md) は「個体基準を書けるのはEOL検査を持つ者だけ」と結論した。これは正しいが、
**Nexteerも同じEOL検査ラインを持っている。** したがってこの論拠は:

- **対OEMプラットフォーム**: 有効(OEMは出荷前の個体に触れない)
- **対他のEPSサプライヤ**: **無効**(同じ条件を満たす)

**サプライヤ間の差別化は、EOLを持つことではなく、そこで何を測り何を宣言するかである。**
これは [docs/153](153_sotif_eooc_assumption_sheet.md) のEooC仮定シートの中身そのものであり、
[docs/155](155_window_recurrence_verification.md)(特徴量別の設計則)、[docs/167](167_precursor_results_v2.md)(先行の実測)が
その中身になりうる。**本研究が持っている資産は、まさにこの層にある。**

## 言ってはいけないこと(継承)

- 規制が「操舵系の状態監視」を義務づけている — **言わない**。義務はADSのSMSと報告であり、部品の摩耗は例示に留まる
- 競合が量産したから本研究の手法も売れる — 言わない。競合の行動は**需要の証拠**であって、本研究の商品性の証拠ではない
- SOTIF適合を証明できる — 言わない([docs/126](126_steering_predictive_diagnostics_sotif_contribution_prospect.md) の境界)

## Rule Check

- 公開情報のみ。規制は一次条文(EUR-Lex)、採択はUNECE/WP.29の公表、競合は公式リリース
- **内部依存だったKQ1を、規制→SMS→safety case→EooCという公開の経路で外から組み立てた**([AGENTS.md](../AGENTS.md) 7条)
- 自分に不利な事実(先行者が量産済み、EOL論拠は対サプライヤには効かない)を、判定に明記した
- 過大評価の2点(ADS限定、条文はセンサを例示)を、含意より先に書いた
