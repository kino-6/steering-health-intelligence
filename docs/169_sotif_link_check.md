# 169. SOTIFとの絡みの再点検(直近の実証は26262側だった)

## 判断

**[docs/167](167_precursor_results_v2.md) が実証したのは「故障の前駆検知」であり、SOTIFではない。** hard failure に至る劣化はfaultであって、ISO 26262 の領域である。ISO 21448(SOTIF)の対象は「**故障していないのに**性能限界で危険になること」であり、別物である。

**ただしSOTIFとの接点は消えない。場所が違う。** 接点は「兆候が出てから故障が確定するまでの窓」にある。

## どこがズレていたか

| | 対象 | 規格 |
|---|---|---|
| [docs/167](167_precursor_results_v2.md) が実証したこと | die-attach劣化 → ON抵抗上昇 → hard failure | **ISO 26262**(fault) |
| SOTIF([docs/126](126_steering_predictive_diagnostics_sotif_contribution_prospect.md) option c)が求めるもの | faultではない機能不足(functional insufficiency)の許容発生率と、その市場検証 | **ISO 21448** |

前駆検知そのものは価値があるが、**SOTIFの主張の根拠にはならない**。ここを混ぜていた。

## 本当の接点: 前駆窓 = SOTIF窓

[docs/167](167_precursor_results_v2.md) の Test_14 を、規格の目で読み直す。

| run | 1〜4 | **5〜6** | 7 |
|---|---|---|---|
| Δ(温度除去後) | ≤+1.1% | **+19.3% → +26.1%** | +30.3%(最終) |
| 部品の状態 | 健全 | **動作しているが特性が2〜3割ずれている** | 故障 |
| 規格上の扱い | — | **faultではない。DTCも立たない** | fault(26262) |

**run 5〜6 が接点である。** 部品は機能しているのでfaultではない。しかし特性は宣言した範囲から2〜3割外れている。
車両機能から見れば、これは**性能不足=functional insufficiency**であり、**SOTIFの主題そのもの**である。

つまり:

> **前駆窓は、26262が扱わず、SOTIFが扱う領域である。**
> faultになる前だからfault監視には掛からず、しかし性能は宣言範囲を外れている。
> ここを観測できることが、EooC仮定([docs/153](153_sotif_eooc_assumption_sheet.md))の「機能不足の許容発生率」を市場で検証する能力になる。

これは [docs/126](126_steering_predictive_diagnostics_sotif_contribution_prospect.md) option (c) の言い直しであり、**新しい主張ではない**。
今回加わったのは、**その窓が実在し、幅を持ち、観測できることの実測**である([docs/167](167_precursor_results_v2.md): 1〜2段階分、ノイズの20〜300倍)。

## SOTIFとして主張するために、まだ足りないもの

**パラメータのずれ ≠ 機能不足**である。ここが埋まっていない。

| 段階 | 状態 |
|---|---|
| 部品パラメータが2〜3割ずれる | **実証済**([docs/167](167_precursor_results_v2.md)) |
| そのずれが**機能**(操舵アシストの応答・精度)を劣化させる | **未証明** |
| その機能劣化が車両レベルで危険側に効く | **未証明。かつOEMの領域** |

3段目はOEMの安全論証の主語であり、部品側は踏み込まない([docs/126](126_steering_predictive_diagnostics_sotif_contribution_prospect.md) の境界)。
**部品側が埋めるべきは2段目だけ**である。

そして2段目は、[docs/144](144_synthetic_sensitivity_results.md)/[docs/155](155_window_recurrence_verification.md) が扱ってきた
「応答遅れ・ゲイン・バイアス」と同じ土俵にある。**パラメータのずれを、機能側の量(応答特性)に翻訳できるか**が問いになる。

## 用語の混同を防ぐための整理(以後これを使う)

| 呼び方 | 中身 | 規格 | 本研究の状態 |
|---|---|---|---|
| **fault前駆** | 故障に至る劣化の早期検知 | 26262(の運用側) | **実証済**([docs/167](167_precursor_results_v2.md))。ただしEPSへの転移は未 |
| **機能不足(functional insufficiency)** | faultではないが性能が宣言範囲を外れた状態 | **21448 = SOTIF** | 窓の実在は示せた。**機能側への翻訳が未証明** |
| 車両レベルの危険 | 上記が運転状況と重なって危険になる | 21448、**主語はOEM** | 部品側は踏み込まない |

**「SOTIFに乗る」と言ってよいのは2段目までである。** [docs/167](167_precursor_results_v2.md) の成果を
そのままSOTIFの根拠として提示しない。

## 公開データの性格についての注記

DS011(KAIST)もDS015(NASA)も、**研究・教育用に整備されたベンチマークデータ**である。
整備されたデータから何かが出るのは当然であり、それ自体は市場価値の証明ではない。

これらが果たした役割は限定的で、正確には次である。

- **機構が実在することの確認**(前駆情報は実部品の電気量に乗る)
- **設計の妥当性の確認**(個体基準 + 動作点正規化で20〜300倍の余裕が出る)

**果たしていない役割**: EPSでの成立、機能不足への翻訳、市場価値の証明。

## Rule Check

- ユーザ指摘を受け、**自分の直近の成果が主張していた規格枠と合っていなかったことを認めた**
- fault前駆 / 機能不足 / 車両レベル危険 を分離し、以後の用語を固定した
- 部品側が踏み込まない範囲(車両レベル)を明示した
- ベンチマークデータの性格(整備された学習用データ)を注記し、**市場価値の証明ではない**と明記した
