# 181. 「規制の対象はADS搭載車のみ」の精密化

## 判断

**私が [docs/180](180_eooc_sheet_all_filled.md) の限界4に書いた「規制の対象はADS搭載車のみ」は、半分しか正しくない。**

| 何の義務か | 対象 | 根拠 |
|---|---|---|
| **SOTIF内容のフィールド監視**(機能不足・性能不足) | **ADS搭載車のみ** | EU 2022/1426 ISMR / UN ADS GTR(2026-06採択) |
| **フィールド監視の組織的義務そのもの** | **全車両。2024年7月から既に義務** | UN R155(CSMS) / R156(SUMS) |

**「監視の枠組みが無いところへ新設する」のではなく、「既にある枠組みに別内容を載せる」構図である。**

## UN R155 / R156 が既に課しているもの

- **2024年7月から、UNECE市場の全新車に義務**。乗用車・バン・トラック・バスに適用
- CSMSは**設計・生産・生産後(市場)の全ライフサイクル**を対象とし、**フィールドの車両を監視**することを求める
- **サプライヤ依存関係の管理**を含む
- 2024年7月から、製造者には**攻撃の報告義務**がある

つまりOEMは既に、**全車両について「ライフサイクルにわたるフィールド監視の組織」と「サプライヤを巻き込む管理プロセス」を持たされている。**

## ただし、そのまま流用できるとは言わない

**内容が違う。** R155が求める監視はサイバー脅威・脆弱性・インシデントであり、部品の劣化ではない。
データ経路が存在する保証も無い(CSMSの監視は脅威インテリジェンスと脆弱性追跡が中心で、車両側テレメトリを必ず伴うわけではない)。

**言えるのは「組織とプロセスは既にある」までであり、「データ経路が使える」ではない。**

## サイバー方向のKillは維持する

[docs/49](49_steering_ecu_cyber_kill_evidence_dossier.md) がKillしたのは以下である。

> TARAを作る商品 / SBOMを作る商品 / CVE管理商品 / **ISO 21434・UN R155/R156対応を支援する汎用商品** / 統合管理ツール

**本ドキュメントはこれらのいずれも提案していない。** 述べているのは環境の観察——
「OEM側にフィールド監視の組織的義務が既に全車両分ある」——であって、商品ではない。
**サイバー対応支援商品はKill維持。**

## 事業判断への含意

[docs/177](177_sotif_direction_update.md) は「規制が需要を硬くした」と結論したが、その硬さの内訳が分かれた。

| | 内容 | 硬さ |
|---|---|---|
| SOTIF機能不足の監視 | 本研究の主張が乗る内容 | **義務。ただしADS搭載車のみ** |
| フィールド監視の組織 | 内容は別(サイバー) | **義務。全車両。2024-07から稼働中** |

**含意は「導入の摩擦が想定より低い」ことである。**
ADS搭載車にSOTIF監視を載せるとき、OEM側は**ゼロから監視組織を作るのではない**。
既に全車両分の枠組みを回している。したがって障壁は「組織を作ること」ではなく「**内容を足すこと**」になる。

これは需要量を増やさない(ADS限定は変わらない)が、**1件あたりの導入障壁を下げる方向に働く**。

## 限界4の書き直し

**旧**: 規制の対象はADS搭載車であり、一般の人間運転車のEPSには及ばない

**新**:
- **SOTIF内容の監視義務はADS搭載車に限られる。** 需要量はADS普及に連動する
- **ただしフィールド監視の組織的義務は、UN R155/R156により2024年7月から全車両に存在する。**
  導入は「監視組織の新設」ではなく「既存枠組みへの内容追加」になる
- **内容が違うため、データ経路や仕組みの流用ができるとは言わない**

## Rule Check

- 自分が確認せずに書いた制約(限界4)を、規制の一次情報で精密化した
- **Kill済み方向(サイバー対応商品)との境界を先に確認し、明示した**。環境の観察と商品提案を分けた
- 「組織とプロセスがある」から「データ経路が使える」へ飛ばなかった([AGENTS.md](../AGENTS.md) の作法7: 測れないを無いと書かない、の裏返し——**あるものを使えると書かない**)
- 需要量は増えないことを明記した。有利な方向に読み替えていない
