# Recall Detection Model: Pre-Registered Protocol

## 位置づけ

実証モデルA(docs/139のユーザレビュー「データ収集して実証モデルを作るべき」への回答)の評価プロトコル。
**本ドキュメントはモデル特徴量の計算・学習・評価の実行前にコミットする(事前登録)。** 以後の変更はすべて「改訂」として履歴に残す。

## 問い

> 公開苦情データから計算した解釈可能な特徴量で、「このcohort(車種×年式)は後に操舵系リコールに至る」を、リコール公式報告の前に、どの精度で識別できるか。

## データ(すべて公開・取得済み)

- 苦情: NHTSA ODI complaints flat file(FLAT_CMPL、全件約200万行、2026-07取得)。使用field: MAKETXT/MODELTXT/YEARTXT/COMPDESC/LDATE(届出受理日)/CDESCR(本文)
- ラベル: NHTSA ODI recalls flat file(FLAT_RCL_POST_2010、2026-07取得)。RCLTYPECD=V(車両)かつCOMPNAMEに"STEERING"を含むcampaign

## ユニットとラベル

- ユニット: cohort = (MAKETXT, MODELTXT, YEARTXT)。MY2005〜2022
- **陽性**: 上記操舵系campaign(RCDATE≥2013)に名指しされたcohort。event日=当該cohortの**最早**のRCDATE(Part 573報告受理日)
- **陰性**: 操舵系campaignに一度も名指しされていないcohort(2010年以降の全campaign台帳に対して)
- 活動下限(両クラス共通): 生涯苦情総数≥50のcohortのみ(極小標本の除外。クラス非対称にしない)
- 陰性の擬似event日: 同一評価era内の陽性RCDATE経験分布から決定的に割当(cohort名ソート順×陽性日付ソート順の巡回)

## 時系列分割(本プロトコルの核)

- **学習: event日が2013-01-01〜2018-12-31のcohort**(陽性campaign約239件由来+同数配分の陰性)
- **テスト: event日が2019-01-01〜2024-12-31のcohort**(同約261件由来)
- 学習でチューニングした全て(係数・操作点・閾値)をテストに凍結適用。テストは1回だけ実行し、結果はそのまま報告する(悪くても)

## 特徴量(cutoff T = event日−6ヶ月。LDATE≤Tの苦情のみ使用)

1. `steer_share`: 操舵系(COMPDESCが"STEERING"で始まる)苦情÷全苦情
2. `log_steer_n`: log1p(操舵系苦情数)
3. `assist_share`: 操舵系苦情のうちアシスト喪失系キーワード(docs/137のリストを凍結使用)に合致する比率
4. `growth`: 直近24ヶ月の操舵系苦情数÷それ以前の月平均×24(比。ゼロ割はcap)
5. `rel_make`: cohortのsteer_share÷同一make・同時点の中央値steer_share(車種間の分母構成差の補正=Silverado教訓)
6. `age_at_T`: T−年式年(年)

補助解析(主指標に影響しない): lead sweep T=event−6/−12/−18/−24ヶ月、EPS系campaign(COMPNAMEにELECTRIC/ASSIST)限定のサブセット評価

## モデル

標準化特徴量に対するロジスティック回帰(numpy実装、L2弱正則化、決定的)。ブラックボックス禁止(係数を報告する)。

## 評価指標(事前固定)

- 主指標: **テストeraのPR-AUC**、およびテストeraでの precision / recall(操作点は学習eraでprecision≥0.5を満たす最小閾値として凍結)
- 副指標: ROC-AUC、lead sweep時の再現率、docs/136の手作りルール(30件+基準2倍+30%)をベースラインとして同一テストセットで比較
- 検出の意味: 「event日6ヶ月前までの公開苦情だけで陽性と識別」=公式報告に先行し得るシグナルの存在

## 既知のリスクと扱い(先に書く)

1. 届出日が現DBで保存されている前提(docs/136と同じ)
2. リコール台帳のMODELTXTと苦情のMODELTXTの表記揺れ→大文字化・trim後の完全一致のみ。**一致率を報告し、落ちた陽性は除外として明記**(補正マッチングはしない)
3. アシスト系キーワードはFusion/Silverado(いずれも学習era事例)で開発済み→軽微なリーク源として明記
4. 「リコール=真のラベル」の限界: リコールは規制・社会プロセスの結果であり、未リコールの真の不具合cohortが陰性に混じり得る(precisionの過小評価方向)
5. 苦情には分母(稼働台数)がない→比率・相対特徴で部分補正(docs/134と同じ)

## 成功/失敗の言い方(先に固定)

- テストPR-AUCが陰性率ベース(無情報)を明確に上回り、凍結操作点でprecision≥0.5かつrecall≥0.3なら「公開苦情による操舵系リコール前識別は実用的シグナルとして成立」と言う
- 満たさなければ「群レベル早期識別は本特徴量セットでは不成立」とそのまま報告する(それも成果)
- どちらでも、個車の故障予測・原因断定・特定OEM批判には使わない
