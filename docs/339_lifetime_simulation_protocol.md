# 339. 事前登録 — 加速試験の run を、実車の時間軸に載せる

## 何が足りていないか

ここまでの結果は**すべて run 単位**である。「故障の 2 run 前に検知」と書いてきたが、
**1 run が実車の何に相当するかを一度も書いていない。**

## 変換係数は公開データでは決まらない

加速試験の 1 run を実車の何時間に換算するかは、劣化機構の活性化エネルギーと
実車の温度履歴で決まる。**どちらもこの研究の公開データには無い。**

**データが無い中での判断:** 換算係数を推定しない。**読み手の入力として残す。**
出す数字は**要素自身の単位**にする（[docs/261](261_no_data_decisions_results.md)・[docs/263](263_temperature_span_results.md) と同じ形）。

> **「何年で検知するか」ではなく、「どれだけの累積ストレスで検知するか」を出す。**
> **累積ストレスを年に直すのは、応用の物理を持っている側の仕事である。**

## 手順

データ: NASA MOSFET 6 素子 × 7 run。

1. 各素子の累積ストレスを、[docs/312](312_stress_axis_results.md) と同じ定義で出す
   （パッケージ温度の基準超過分の積算）。**単位は °C·時間**
2. 次の 3 点での累積ストレスを、素子ごとに出す
   - 出荷時基準値を採り終えた時点（run 1 前半の終わり）
   - **検出器が最初に反応した時点**（[docs/317](317_changepoint_results.md)）
   - 故障直前（run 7 の終わり）
3. **記録器を時間軸に沿って走らせ、次を累積で出す**
   - 不揮発への書き込み件数（30 バイト × 件数）
   - 判定を出せた時間の割合
   - アシスト能力の推移（[docs/334](334_capability_trace.md) と同じ計算）
4. **読み手が年に直すための換算表を付ける。**
   「実車が平均 `ΔT` °C 超過で年 `H` 時間走るなら、検知は `S/(ΔT·H)` 年後」

## 事前に決めて報告すること

**判定は置かない。数字を出すことが目的である。**ただし読み方を先に固定する。

| | 何を出すか |
|---|---|
| **Y1** | 検知時点の累積ストレス。**素子間のばらつきを併記する** |
| **Y2** | 検知から故障までの累積ストレス。**警告から故障までの余裕がどれだけ個体に依るか** |
| **Y3** | 不揮発の使用量が、[docs/318](318_unit_ledger.md) の見積り（30 バイト/件）とどれだけ違うか |

- **Y2 の素子間のばらつきが 3 倍を超えるなら**、「余裕は個体ごとに大きく違う」と書く
- **Y3 が [docs/318](318_unit_ledger.md) の見積りと 2 倍以上違うなら**、その見積りを直す

## この事前登録が外れる条件

- **累積ストレスの定義（基準超過分の積算）は私が置いた**（[docs/312](312_stress_axis_results.md)、[TROUBLES.md](../TROUBLES.md) T2）。
  別の定義なら別の数字になる
- **試験機は run ごとに設定温度を 10 °C 下げている**（[docs/199](199_pulse_thermal_results.md)）。
  累積ストレスはその軌跡を含む。**実車の温度履歴とは形が違う**
- **換算係数を出さない。**「何年」は書かない。書けば T2 の再発である
- 単体 MOSFET・6 素子・1 試験機。**EPS ではない。率ではなく存在証明**
