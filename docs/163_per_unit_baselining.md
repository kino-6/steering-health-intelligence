# 163. 個体ばらつきへの標準対策と、それが決める供給境界

## 判断

**1. 標準対策は存在する。中心は「母集団基準」ではなく「個体ごとの基準」である。**

**2. そして [docs/155](155_window_recurrence_verification.md) / [docs/158](158_sotif_eooc_monitor_demo.md) の較正設計は、この点で誤っていた。** 母集団(program内の中央値・MAD)を基準にしていたが、それは [docs/162](162_pmsm_model_validation_results.md) が「成立しない」と結論した個体間の横断比較である。**訂正する。**

**3. 個体ごとの基準を書けるのは、EOL検査ラインを持つ者だけである。これは能力の主張ではなく構造の話であり、供給境界を決める。**

## 標準対策(公開の実務として一般的なもの)

個体ばらつきを包含する方法は、条件監視の実務として確立している。

| # | 対策 | 中身 | 本研究での位置 |
|---|---|---|---|
| 1 | **EOL指紋(出荷時の個体基準)** | 出荷検査時に、その個体の健全時signatureを記録して保存する | **中心対策。**以後の判定は「その個体の出荷時」との比較になる |
| 2 | **運用中の学習(learned values)** | 稼働初期に自分の基準を学習し、以後の逸脱を見る。EPSでは既に一般的(トルクセンサオフセット学習、舵角センタリング)。公開のサービス情報にも「部品交換後は較正が必要」と現れる | 1の補完。交換部品・経年に対応 |
| 3 | **動作点ゲート/正規化** | 速度・負荷・温度を限定した窓でのみ評価する | 本研究は既に実装済み(励起ゲート・速度ゲート、[docs/144](144_synthetic_sensitivity_results.md)) |
| 4 | **比で見る指標** | 逆相比 I2/I1 のように、振幅そのものではなく比を見て共通変動を打ち消す | 本研究は既に採用([docs/161](161_pmsm_model_validation_protocol.md)) |
| 5 | **温度・経年補償** | 基準を温度と稼働時間の関数として持つ | **未着手。**[docs/162](162_pmsm_model_validation_results.md) が残した弱点そのもの |

つまり**3と4は既にやっており、1と2が抜けていた**。抜けていた結果が、母集団基準という誤った較正設計である。

## docs/155 / docs/158 の較正設計の訂正

| | 旧(誤り) | 新 |
|---|---|---|
| 基準の取り方 | program内の**母集団**の中央値・MAD | **その個体の出荷時**(EOL指紋)+運用初期の学習 |
| 比較の性質 | 個体間の横断比較 | 同一個体の時間変化 |
| 成立するか | **しない**([docs/162](162_pmsm_model_validation_results.md): 同じ健全機でもセットアップ差でUが2〜8倍動く) | **する**([docs/162](162_pmsm_model_validation_results.md): 同一個体の短時間ゆらぎは最大9.5%、故障の効きはその15〜31倍) |

[docs/158](158_sotif_eooc_monitor_demo.md) の逸脱率4.96%も、この誤りの影響を受けている。あれは「母集団から外れた個体の率」であり、
**「各個体が自分の出荷時から外れた率」ではない**。公開データは同一個体の時系列を持たないため、
**現時点のデータでは正しい方の率を出せない**。ここは埋められない欄として残す。

## これが決める供給境界(事業判断)

個体ごとの基準を書くには、**その個体を出荷前に測る必要がある**。

- **EPSサプライヤはEOL検査ラインを持っている。** [docs/64](64_kaggle_pre_shipment_predictive_quality_deep_dive.md) で扱ったEOL検査データは、まさにこの工程のものである
- **OEMのvehicle health基盤・remote diagnostics platformは持っていない。** 出荷済みの車両からしか観測できず、個体の健全時基準を後から作ることはできない
- 車両側で運用中に学習する方法(対策2)はあるが、**学習期間中に既に劣化していた個体は健全基準を汚染する**。出荷時点の基準にはならない

したがって:

> **個体ばらつきを包含した状態監視は、EOL検査を持つ部品サプライヤにしか構成できない。**
> これは「サプライヤの方が優れている」という主張ではなく、**基準を書ける時点が出荷前にしかない**という時間順序の話である。

[docs/146](146_business_framework_and_roadmap.md) 第1層(状態説明機能を組み込んだ製品仕様をRFQ差別化+診断コンテンツNREとして売る)は、この境界の上に乗る。
競合の手法先行([docs/128](128_steering_predictive_diagnostics_sotif_public_signal_watch.md): Boschの定量SOTIF特許)に対しても、手法ではなく**基準を書ける位置**が差分になる。

## 2つのスレッドがつながった

これまで別物として扱ってきた2つが、同じ工程を指していた。

- [docs/63](63_kaggle_supplier_owned_data_pdca.md)〜[docs/65](65_pre_shipment_quality_screening_proxy_demo.md): **出荷前**の品質予兆検知(EOLで落ちる個体を早く見つける)
- [docs/153](153_sotif_eooc_assumption_sheet.md)/[docs/162](162_pmsm_model_validation_results.md): **出荷後**の状態監視(EooC仮定の市場検証)

**同じEOL検査が、品質スクリーニングと個体基準の書き込みを兼ねる。** 追加の工程を作らずに、出荷後の機能の前提を出荷前に仕込める。

## 言ってはいけないこと(継承)

- EOL指紋があれば故障を予測できる — **言わない**([docs/143](143_recall_detection_results_v2.md) のKill維持)
- 個体基準があれば安全を保証できる — 言わない
- OEMには作れない — 「作れない」ではなく「**出荷前の測定点を持たない**」と事実で言う

## 検証されていないこと

1. **EOL指紋の実在性**: 実際のEPS EOL検査で、本研究が使う量(相電流不平衡・応答特性)が記録されているか。**これは内部資料の領域であり、ここで問いを閉じる**
2. **経年・温度による個体内変動**([docs/162](162_pmsm_model_validation_results.md) の残る限界)。測ったのは1台の短時間ゆらぎだけで、経年の変動は未測定。**個体基準の有効期間が分からない**
3. 学習方式(対策2)が汚染された個体をどう扱うか

## Rule Check

- **自分の直近の設計([docs/155](155_window_recurrence_verification.md)/[docs/158](158_sotif_eooc_monitor_demo.md))の誤りを、指摘を受けて訂正した**
- 標準対策は公開の実務知識として記述し、特定の内部実装を根拠にしていない
- 供給境界の主張を「能力の優劣」ではなく「**測定できる時点の順序**」という構造で述べた
- EOL指紋の実在確認は内部資料の領域として**問いを閉じ、次アクションに置いていない**
- 故障予測Killを動かしていない
