# 300. 同期は EIS ではない。同期の単位は「電圧群」ではなく「記録器」だった

[docs/298](298_eis_sync_protocol.md) の事前登録を実行した（サブエージェントによる。手順・基準は不変）。**追加取得ゼロ。**

> **E1 不成立、3 群とも。**発火から最寄りの EIS 測定までは最短 1.8 日・中央値 11.3 日で、
> ランダム対照（5.5 日）より**遠い**（比 2.07。基準は 0.10 以下）。
> **理由はカレンダーにある**——EIS は 2014-12-16 の次が 2015-02-17 で、**2 か月の空白**があり、
> 23 個体中 16 個体の発火（02-02〜02-25）がその空白に落ちる。EIS の挿入では説明できない。
>
> **E3 で分かったこと**: ES12 と ES14 の `Serial_Date` は **77,241 点すべて同一**である。
> 2 群は同じ記録器で同時に記録されている。「別の試験なのに同じ標本番号で鳴る」（[docs/284](284_method_verification_results.md)）は、
> **別の試験ではなく同じ記録器の同じ時刻**だった。同期の単位は群ではなく記録器である。

実行: `python3 scripts/eis_sync.py` / 数表: [data/eis_sync.tsv](../data/eis_sync.tsv)

**同じ記録器の個体は同じ壁時計時刻に鳴り、記録器が違えば時刻も違う。**
[docs/284](284_method_verification_results.md) の「ES12 と ES14 が約 6,350 で一致」は ES12/ES14 間だけの話で、ES10 とは一致していない——訂正。

## 見つかった構造（h5py の表示。EIS 側）

- `EIS_Reference_Table` (4×73): 日付・開始・終了・累積試験時間。**列 67（12-16）と 68（02-17）の間が空白**
- 各個体 `EIS_Measurement/{Header, Data, ColumNames}`、Header は EC-Lab の ASCII で "Acquisition started on" を持つ（これが時刻）
- EIS 時刻: ES10 2,981 / ES12 2,921 / ES14 2,933 個。過渡記録の期間内はそれぞれ 888 / 879 / 881
- 過渡記録は 2014-11-17 開始、`Initial_Date`（10-01）より 47 日遅い。ES10 の `Serial_Date` は 1 箇所逆行する

## 次の候補（E3）

**記録器側の事象**——取得ソフトの再起動、ファイル切り替え、較正。
[docs/294](294_unit_level_false_alarm.md) は時間ギャップだけを見た。**ES10 の逆行 1 箇所と、サンプル間隔の変化点は未確認。**
それでも「劣化を捉えた」証拠にはならない点は変わらない——同一記録器の個体が同時刻に鳴る限り、個体の事象とは言えない。

## 答えないこと
- 同期の原因そのものは未解明。**候補が「群」から「記録器」に絞れただけ**
- EC-Lab PC と過渡記録 PC の時計ずれは未知。ただし判定を覆すには日単位のずれが要る
