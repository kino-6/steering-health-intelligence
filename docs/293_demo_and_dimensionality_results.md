## D2 — 関係だけを壊した5つの故障

**周辺分布を一切変えず、関係だけを壊す。**2つの作り方を使った。

| 壊し方 | 対象 | 単変量(記録器) | 多変量(Isolation Forest) |
|---|---|---|---|
| 値の入れ替え | Ia ↔ Ib | **検出** | 検出 |
| 値の入れ替え | T1 ↔ T2 | **検出** | 検出 |
| 時間順の破壊 | Idc(同種なし) | **検出** | 検出 |
| 時間順の破壊 | Vdc(同種なし) | **検出** | 検出 |
| 時間順の破壊 | Vd(同種なし) | **検出** | **取り逃す** |

**最後の行が示すとおり、多変量の方が取り逃した場合すらある。**

### なぜ単変量が検出できたのか

**記録器が見ているのは、チャネルの値そのものではない。**

```
逸脱 = |実測 − (傾き × 動作点 + 基準値)| / 床
```

**動作点に対する直線からの残差である。**
**時間順を壊せば、値の分布は変わらなくても、動作点との対応が壊れ、残差が広がる。**

**同種チャネルがある量では、さらに差分が入る。**入れ替えは差分の符号を反転させる。

> **したがって「単変量」という前提が違っていた。**
> **1チャネルあたり、動作点(1変数)と同種チャネル(0〜2変数)を見ている。**

### それでも取り逃すもの(構成できなかった)

**次の条件をすべて満たす故障は、原理的に取り逃すはずである。**

1. 各チャネルの周辺分布が変わらない
2. **各チャネルの、動作点に対する関係も変わらない**
3. 同種チャネルとの差分も変わらない
4. **チャネル同士の関係だけが変わる**

**この4条件を同時に満たす構成を作れなかった。**
**したがって「取り逃すものが無い」ではなく、「取り逃すものを構成できなかった」である。**

## D1 — 宣言しない割合は、この台では意味を持たない

| 掃引幅 | 宣言しない割合 |
|---|---|
| ×1(そのまま) | **0.2%** |
| ×2 | 0.0% |
| ×5 | 0.0% |

**基準(10%超なら指摘のとおり)を満たさない。しかしこの数字は信用できない。**

**この試験機は回転数を 10 rad/s で一定に保つ設計である。**
**動作点がほとんど動かないので、指紋の範囲から出ようがない。**

> **「特定の状況にしか効かない」という指摘は、実車ではそのとおりである。**
> **対策は [docs/227](227_filling_spec_blanks_results.md) が出している——掃引幅を速度軸で7〜35倍広げる。**

## D3 — 搭載時に出るもの

**出荷時**: 8チャネルを採用、指紋 384バイト、較正できた誤報 17.6 件/時。

**運用(正常60秒 → 半ブリッジ1の下側短絡)**:

```
[   60s] 逸脱   3.15 (粒度 100.4) 事象    5s  速い側 / 遅い側
[   65s] 逸脱   3.13 (粒度 100.4) 事象   10s  速い側
[   70s] 逸脱   3.38 (粒度 100.4) 事象   15s  速い側
[   75s] 逸脱   3.16 (粒度 100.4) 事象   20s  速い側
```

**運用フェーズへ送る1件(30バイト)**:

| 欄 | 値 |
|---|---|
| 逸脱 | **3.15**(この個体の床の倍数) |
| 宣言粒度 | **100.4**(出荷時の床) |
| 有効性 | 宣言する |
| 動作点 | 507.0 |
| キーオンからの経過時間 | **60秒** |
| 持続 | 継続中(キーオフまで続けば確定して書き出す) |
| **載せないもの** | **能力値・予測・故障箇所・余寿命**(`forbidden output` 検査が止める) |

**この30バイトが、SOTIFの運用フェーズ(13章「観測すべき事柄」)への入力である**
([docs/267](267_sotif_conformance_results.md))。

**そして逸脱3.15が「アシストが何%落ちたか」を意味しないことは、
[docs/291](291_model_gap.md) が書いたとおりである。**
**この30バイトは、モデルではなく観測である。**
