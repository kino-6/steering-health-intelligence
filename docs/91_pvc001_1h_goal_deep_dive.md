# PVC001 1h Goal Deep Dive

## 結論

PVC001は、まだ外販商品ではないが、次の1枚sampleを作って社内検証する価値はある。

一番よい入口は、「駐車場走行で、低速・大舵角・凹凸が重なる使われ方」を先読みするsampleである。
これは `ULC008` として扱う。

このsampleは、EPSが壊れるか、いつ交換すべきかを当てるものではない。
見るべきことは、車両や用途が、EPSにとって厳しい使われ方に入りやすいかを、製品企画、診断企画、品質改善、評価企画に転記できるかである。

現時点の判断は **Conditional Continue** である。
続ける条件は、EPSサプライヤ内の少なくとも2部署が、このclassを自分たちの業務判断へ使えると言えることである。

## 何を判断しているか

判断しているのは、公開proxyからEPS故障を予測できるかではない。

判断しているのは、公開proxyから、次のような使用負荷classを先読みまたは分類する価値があるかである。

- 低速で大きな操舵を繰り返す
- 渋滞や市街地でstop-startと反復操舵が重なる
- 荒れた路面で操舵入力が重なる
- 駐車場走行で低速・大舵角・凹凸が重なる

作成した作業表は [data/pvc001_four_class_deep_dive.tsv](../data/pvc001_four_class_deep_dive.tsv) である。

## 1枚sample

### タイトル

駐車場走行で低速・大舵角・凹凸が重なる使われ方を先に分類できるか

### 市場需要

ドライバーやサービス現場では、駐車時や低速取り回し時の操舵感、音、振動、違和感が問題として表に出やすい。
EPSサプライヤ側では、その違和感がEPS故障なのか、路面や操作条件による体感なのかを、いきなり原因断定せず説明できる材料が欲しい。

### 未解決の痛み

公開情報や顧客説明では、低速操舵、駐車操作、凹凸路、振動、警告、DTC、部品交換が混ざりやすい。
しかし公開proxyだけでは、EPS内部状態、assist state、thermal limit、DTC、freeze frame、交換結果は見えない。

そのため、必要なのは故障予測ではなく、まず「この使われ方は、EPSに厳しい使用負荷classに入る可能性がある」と自然言語で分類することである。

### 仮説

公開proxyから、低速、大舵角、操舵頻度、路面凹凸または振動proxyを組み合わせると、駐車場相当の使用負荷classを作れる可能性がある。

このclassがあれば、EPSサプライヤは、製品企画、診断企画、品質改善、評価企画で同じ言葉を使って議論できる。

### 解決策

初期提供物は、以下の4列を持つ1枚sampleである。

| Column | 内容 |
|---|---|
| 使用負荷class | 駐車場走行で低速・大舵角・凹凸が重なる使われ方 |
| 公開proxy | 低速、大舵角、操舵頻度、凹凸/振動proxy |
| 業務での使い道 | 製品企画、診断企画、品質改善、評価企画での使い道 |
| 禁止主張 | 故障原因、残寿命、交換時期、内部stressを断定しない |

### 買い手 / 利用者

最初の利用者は外部顧客ではない。
EPSサプライヤ内の以下の部署である。

| 部署 | 使える可能性 | 判定 |
|---|---|---|
| 製品企画 | 用途別にEPSがどんな使用条件にさらされるかを説明する | Strong |
| 診断企画 | DTCだけでは説明しにくい低速・駐車・凹凸contextを補助する | Medium |
| 品質改善 | field issueを使用条件別に読み直す入口にする | Medium |
| 評価企画 | 既存評価が駐車場相当classを代表しているか確認する | Medium |
| 顧客技術説明 | 故障原因を断定せず、使用条件の可能性を説明する | Strong but risky |

### 検証方法

1. ULC008のsampleを製品企画に見せ、用途別価値説明に使えるか確認する
2. 診断企画に見せ、DTC / freeze frame / extended dataだけで同じ説明ができるか確認する
3. 品質改善に見せ、field issueを使用条件別に見直す入口になるか確認する
4. 評価企画に見せ、既存HILS/bench/vehicle評価に相当条件があるか確認する

### Kill条件

次のどれかに当たれば止める。

- 既存評価scenario名の言い換えにしかならない
- DTC / freeze frame / extended dataで十分に説明できる
- 製品企画が用途別価値説明に使えない
- 品質改善がOEM保証DBやfleet dataなしでは使えない
- 顧客説明に使うと、故障原因や残寿命の断定に見えてしまう

## Deepened Points

### 1. ULC001はPVC001の土台になる

Repo内には、公開走行データから低速・高操舵要求windowを抽出した既存材料がある。
[data/low_speed_high_steering_proxy_summary.tsv](../data/low_speed_high_steering_proxy_summary.tsv) では、低速条件と操舵要求proxyからcandidate windowを231件抽出している。

これはEPS故障や劣化兆候を示さない。
しかし「低速・高操舵の使われ方をproxy windowとして抽出できる」という意味では、ULC001の土台になる。

### 2. ULC003は独立候補ではなくcontextでよい

stop-startと反復操舵は、都市配送、市街地、渋滞という用途説明には効く。
ただし、単独では都市走行一般論になりやすい。

したがってULC003は独立商品ではなく、ULC001やULC008に「都市/渋滞context」を足す役割に置く。

### 3. ULC004は品質改善と顧客説明で価値が出る

荒れた路面と操舵入力の組み合わせは、体感、異音、振動、違和感の説明に向いている。
ただし、路面分類だけでEPS状態が分かるとは言えない。

価値が出るのは、路面外乱と操舵要求が重なったときに、EPS異常と誤認しない説明境界を作る場合である。

### 4. ULC008は初回sampleに最も向く

駐車場走行は、低速、大舵角、凹凸、音、振動、操舵感が重なりやすく、非専門家にも分かりやすい。
その一方で、「駐車操作が原因」と読まれやすい危険も大きい。

したがって、ULC008は初回sampleに向くが、禁止主張を必ず同じ画面に置く必要がある。

## What Changed

前回は、PVC001を「使用負荷classの先読み」として残すところまでだった。
今回の深掘りで、次のように変えた。

- 最初に見る4件を ULC001 / ULC003 / ULC004 / ULC008 に固定した
- ULC008を初回1枚sampleの中心にした
- ULC003は独立候補ではなく、ULC001/ULC008のcontextへ下げた
- ULC004はPVC002として独立させず、PVC001の中核sub-classへ統合する方向にした
- 既存の低速高操舵proxy抽出結果を、ULC001の部分支援材料として再利用した

## Still Weak

まだ弱いのは、以下である。

- 公開proxyだけでは、同一車両・同一時刻で低速、大舵角、凹凸、診断結果が揃わない
- EPS内部信号、assist state、thermal state、DTC、freeze frame、交換結果は見えない
- 既存評価や診断仕様に同じ整理がある可能性をまだ潰せていない
- 製品企画、診断企画、品質改善、評価企画の実ユーザ反応は未確認

## Stop / Continue Judgment

PVC001は **Continue** だが、次の作業で刺さらなければ止める。

次に作るべきものは、ULC008を中心にした1枚sampleである。
そのsampleを、製品企画、診断企画、品質改善、評価企画の4部署に見せる想定で書く。

Continue条件:

- 4部署のうち2部署以上に、業務判断へ転記できる使い道がある
- 「故障予測」ではなく「使用負荷classの先読み」として説明できる
- 既存評価・診断仕様の単なる言い換えではない

Stop条件:

- 4部署のどこにも刺さらない
- 既存評価scenarioやDTC/freeze frameで十分と言える
- 顧客説明に使うと原因断定や責任転嫁に見える

## EPSサプライヤとして言えること

言ってよいこと:

> 公開proxyだけではEPS内部状態や残寿命は分からない。ただし、低速・大舵角・凹凸・stop-start・路面外乱を組み合わせると、EPSに厳しい使用負荷classを先に分類する余地はある。このclassが、製品企画、診断企画、品質改善、評価企画に使えるかを検証する。

まだ言ってはいけないこと:

> 使用負荷classからEPS故障、残寿命、交換時期、保証費削減、安全性を予測できる。

> 駐車場走行や低速高操舵が故障原因である。

> 公開proxyからEPS内部stress、thermal limit、assist limitation、DTC不足を断定できる。
