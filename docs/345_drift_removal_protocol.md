# 345. 事前登録 — 同種チャネルが無い量から、健全期の漂流を消せるか

## なぜこれを次に置くか

[docs/344](344_virtual_module_detection_results.md) が問題を 1 つに絞った。

> **検出は劣化の速さの問題ではない。健全期の漂流が同じ閾値を越えるからである。**
> **足りないのは観測量ではなく、漂流を消す手立てである。**

同種チャネルとの差分はその手立ての 1 つだが（誤報 75.6% → 0%、[docs/286](286_common_mode_results.md)）、
**同種チャネルを持たない量には使えない**（DC バス電圧、[docs/327](327_supply_tolerance_results.md)）。

**仮想モジュールなら真値が分かるので、どの手立てが効くかを測れる。**

## 問題の形

健全期の漂流は**ランダムウォーク**、劣化は**傾き一定の増加**として模してある（[docs/343](343_virtual_module_detection_protocol.md)）。

> **1 本の系列から、ランダムウォークと直線の増加を分けられるか。**

**これは既知の難問である。**分けられないなら「分けられない」と書く。

## 試す手立て（3 つ。実行前に固定する）

| | 手立て | 中身 |
|---|---|---|
| **M1** | 水準の閾値（基準） | いまの実装。[docs/344](344_virtual_module_detection_results.md) で 12〜39 件/時 |
| **M2** | 基準値の定期的な採り直し | 直近 K 窓で基準を採り直す。K = 60 / 180 / 360 窓 |
| **M3** | 2 つの時間尺度の差 | 短い窓の平均 − 長い窓の平均。短 60 窓 / 長 360 窓 |

**M2 と M3 の窓長は私が置いた**（[TROUBLES.md](../TROUBLES.md) T2・T35）。

## 手順

1. [docs/343](343_virtual_module_detection_protocol.md) と同じ 200 個体を作る。
   **劣化速度は実素子の実測値 D = 9.6 に固定する**（[docs/344](344_virtual_module_detection_results.md)）
2. 各手立てで、出荷時登録（1 時間）から閾値を決め、運用 2 時間で判定する
3. **検出率と、健全群の誤検知（件/時）を出す**
4. **[TROUBLES.md](../TROUBLES.md) T41 の検査を先に通す。**
   M3 の差分が、劣化区間で実際に動いているかを確かめてから閾値に掛ける

## 事前に決める判定

| | 基準 |
|---|---|
| **W1** | 誤検知 **1 件/時 以下**を保ったまま、検出率 **90% 以上** |
| **W2** | W1 を満たす手立てが無いなら、**誤検知が最小の手立てとその値**を報告する |
| **W3** | どの手立ても M1（基準）より悪くないか。**悪化するものがあれば、そう書く** |

**W1 を満たす手立てが 1 つも無い場合、「1 本の系列では漂流と劣化を分けられない」と結論する。**
**そのときは、同種チャネルを持たない量には検出を載せないという設計判断になる。**

## この事前登録が外れる条件

- **漂流をランダムウォークで模したことが、結論を決めてしまう。**
  実素子の漂流が別の形（たとえば温度に紐づく可逆な変動）なら、別の手立てが効きうる
- 窓長・個体数・登録時間・劣化速度は私が置いた
- **3 つ以外の手立てを試さない。**当たるまで探すのは事後の探索である（[TROUBLES.md](../TROUBLES.md) T17）
- 仮想である。**実 EPS で同じとは言えない**
