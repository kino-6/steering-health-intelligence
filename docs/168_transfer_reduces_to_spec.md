# 168. 残る転移(A')は、ほぼ製品規格の問題に還元される

## 判断

**内部回路に絞れば、MOSFET→EPSの転移は大部分が gain / offset の違いであり、それは研究課題ではなく製品規格の決めごとである。ただし1点だけ還元できないものが残る。**

| 転移で変わるもの | gain/offsetに還元されるか | 根拠 |
|---|---|---|
| 温度係数・感度・ベースライン絶対値 | **される** | v2は個体ごとに a, b を推定する構造。同一型番6個体でも a は 0.0091〜0.0128 Ω/°C(**約40%ばらつく**)が、6/6で成立した |
| 測定点(デバイス端子 vs シャント) | **される**(規格事項) | 何をどの分解能で測るかは、RFQで要求する仕様である |
| 動作点の分布(定常熱サイクル vs 実走行) | **される**(規格事項) | ゲートとk-of-N判定則は既に設計済み([docs/155](155_window_recurrence_verification.md)) |
| **標的故障族が単調な観測量を生むか** | **されない** | 後述 |

## gain/offset に還元される理由

[docs/167](167_precursor_results_v2.md) の手法は、**個体ごとに温度係数とベースラインを推定してから残差を見る**。
つまり **gain と offset は最初から未知として扱い、初期runで同定している**。

決定的なのは、同一型番・同一ロットの6デバイスですら **温度係数が40%ばらついていた**ことである。
それでも6/6で成立した。**gain のばらつきに対して、手法は既に頑健である**ことが実測で示された。

したがって「別のデバイス、別の実装だから gain が違う」は、**この手法にとって新しい問題ではない**。
[docs/155](155_window_recurrence_verification.md) の「手法は移る、閾値は移らない」、[docs/163](163_per_unit_baselining.md) の個体基準と、同じことを言っている。

**残るのは「何を、どの動作点で、どの分解能で測り、初期同定の窓をどう取るか」であり、これは [docs/153](153_sotif_eooc_assumption_sheet.md) のEooC仮定シートに書く内容そのものである。**
つまり**調べる対象ではなく、宣言する対象**である。[docs/146](146_business_framework_and_roadmap.md) 第1層(RFQ差別化 + 診断コンテンツNRE)の中身になる。

## 還元されない1点: 標的故障族が単調な観測量を生むか

ここだけは規格では決まらない。

| | 機構 | 観測のされ方 |
|---|---|---|
| **MOSFET die-attach**([docs/167](167_precursor_results_v2.md)で実証) | 接合部の劣化 → 熱伝達悪化 → 抵抗上昇 | **水準が単調に上がる** |
| **EPSコネクタのfretting corrosion**(本研究の標的、MKT007〜010) | 微摺動摩耗 → 接触面の酸化 → 接触抵抗上昇 | **断続的な接触不良として現れる** |

機構としては**同類である**——どちらも界面劣化による抵抗上昇であり、類推は強い。
しかし公開記録が一貫して記述するのは「**断続的なアシスト喪失**」「**断続的または完全な失陥**」であり、
なめらかな抵抗上昇ではなく**散発的なイベント**として顕在化する。

**したがって問いはこうなる。**

> fretting は、機能影響が出る前に**単調に測れる量**を生むか。
> 生むとすれば、それは抵抗の**水準**ではなく、微小ドロップアウトの**発生率**ではないか。

これは gain/offset ではなく、**指標の種類が違う**という話である。

### ただし設計は既にそれを織り込んでいる

[docs/121](121_steering_predictive_diagnostics_power_monitor_case.md) / [docs/122](122_steering_predictive_diagnostics_power_monitor_payload_sample.md) の payload は、
**key cycle recurrence(再発頻度)** を最初から含んでいる。水準ではなく**回数を数える**設計である。

[docs/155](155_window_recurrence_verification.md) の k-of-N 判定則も同じ思想である。

つまり **アーキテクチャは同じで、単調量が「水準」から「発生率」に替わるだけ**である。
[docs/167](167_precursor_results_v2.md) が実証した構造(個体基準 + 動作点正規化 + トレンド)は、そのまま使える。

## 残る未証明の最終形

[docs/164](164_position_summary.md) の A' を、次に置き換える。

> **A''**: EPSコネクタのfretting劣化は、機能影響が出る前に**単調な発生率の上昇**として観測できるか。

これは公開情報では埋まらない可能性が高い。実部品のfretting run-to-failure データが要る。
**ただし探していない。** [docs/159](159_public_dataset_reinventory.md) の2軸(用途軸/部品軸)に、
**「コネクタ・接点の劣化」という第3の軸**を足して棚卸しし直す価値がある。次の候補として記録する。

## Rule Check

- ユーザ指摘(内部回路に絞ればgain/offsetと製品規格の問題)を検証し、**大部分は正しい**と判定した
- 還元されない1点(標的故障族の観測のされ方)を切り分け、**規格で決まらないものを規格の話に混ぜなかった**
- 既存設計(payloadのrecurrence、k-of-Nの判定則)が既にそれを織り込んでいることを確認した
- 内部情報を要求していない。次の一手は公開データの棚卸し軸の追加である
