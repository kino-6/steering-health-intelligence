# 359. 報告書の型を、自分の思いつきではなく確立された様式に合わせる

2026-09-13 ユーザ指摘: **「レポート改善いい加減にしたいんだけど、世の中のフォーマットを調査して学んでほしい。それで再構築して」**

指摘のたびに私が見た目を作り直し、そのたびに新しい欠陥を作っていた。**型を外から借りる。**

## 調べた様式

| 様式 | 出典 | 借りたもの |
|---|---|---|
| **IMRaD** | ANSI Z39.16（1979）。1970 年代に主要誌で支配的になった（Sollaci & Pereira 2004, PubMed 15243643） | 本文の順序: 序論 → 方法 → 結果 → 考察 |
| **Nature の要旨** | Nature, "How to construct a Nature summary paragraph"（nature.com/documents/nature-summary-paragraph.pdf） | 要旨の 6 段: 分野の導入 → 背景 → 問題 → 主結果（here we show）→ 従来との違い → 意味。200 語以内、数字は最小限 |
| **試験完了報告** | ISO/IEC/IEEE 29119-3:2021 §7.4（目次を一次資料で確認） | 7.4.3 **計画からの逸脱**、7.4.7 **残るリスク**、7.4.4 完了評価、7.4.10 教訓。§5.2 の共通情報: 識別・発行者・状態・改訂履歴 |
| **試験要約報告** | IEEE 829-2008（29119-3 Annex S で対応表あり） | 要約 → 逸脱 → 網羅性の評価 → 結果の要約 → 評価 → 活動 |
| **検証報告** | ISO 26262-8:2018 §9.4.3 検証の実行と評価、§9.5 成果物（目次のみ確認。本文は有償） | 検証の実行と評価を分けて書く |
| **技術報告書の慣行（日本語）** | 技術者向けの一般的な指南（要旨・目的・方法・結果・考察・結論・参考文献・付録） | 見出しの日本語 |

## 決めた章立て

| 章 | 役割（`role`） | 中身 | 借りた様式 |
|---|---|---|---|
| 要旨 | `要旨` | 6 段の要約。数字は最小限 | Nature |
| 1 序論 | `序論` | 背景と問題、目的と範囲、章立て | IMRaD、技術報告書 |
| 2 対象と用語 | `用語` | この文書での語の意味。**造語は使わない** | ISO の 3 章の慣行 |
| 3 方法 | `方法` | 記録器のしくみ、データ構造、計算、使ったデータ、仮想の接続、検証の進め方 | IMRaD |
| 4 結果 | `結果` | 検証 1 から 8。4.1, 4.2 … と番号を振る | IMRaD |
| 5 考察 | `考察` | 成立したこと、**計画からの逸脱**、**残るリスク**、限界 | 29119-3 §7.4.3, 7.4.7 |
| 6 結論 | `結論` | 成立／不成立の 2 列、SOTIF での位置づけ | IMRaD、技術報告書 |
| 参考文献 | `参考文献` | 番号付きの一覧 | 全様式 |
| 付録 | `付録` | 仮想の全パラメータ、改訂の記録 | 29119-3 §5.2.4 |

冒頭に 29119-3 §5.2 の共通情報（識別・発行・状態・改訂）を置く。

## 検査

`check_report_json.py` の `ROLES` をこの順にし、要旨・用語・結論・参考文献は 1 個ずつを要求する。序論・方法・結果・考察・付録は小節を持てる。
番号は描画側が付けるので、見出しに手で「検証 3 —」と書かない。

## 限界

- 29119-3 と 26262-8 は目次までしか一次資料で確認していない。本文は有償
- Nature の要旨は 200 語の英語向けで、日本語ではおおむね 400 字にあたると読み替えた
- 様式は借りたが、**中身の良し悪しは様式では決まらない**
