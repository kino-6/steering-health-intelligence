# 298. 事前登録 — コンデンサ 23 個体の同期は、EIS 測定の挿入で説明できるか

> [docs/284](284_method_verification_results.md): 3 群 23 個体が同じ標本番号で鳴る。
> [docs/294](294_unit_level_false_alarm.md): 記録の時間ギャップでは説明できない。
> **同じファイルに EIS（インピーダンス測定）が同梱されている。**充放電の合間に挿入される測定なら、全個体に同時に影響しうる。

**追加取得ゼロ。** NASA Capacitor Electrical Stress、ES10 / ES12 / ES14。

## 手順（実行前に固定）

1. 各群の `EIS_Data` から、EIS 測定の**時刻**を取り出す（構造は未確認。取り出せなければそう書く）
2. 各個体の初発火の標本番号を `Transient_Data/Serial_Date` で時刻に変換する
3. 発火時刻から**最も近い EIS 測定時刻までの差**を、個体ごとに出す
4. 対照: ランダムな標本番号 1,000 個について同じ差を出し、その分布と比べる

## 判定基準（実行前に固定）

| # | 基準 | 閾値 |
|---|---|---|
| **E1** | 発火〜最寄り EIS の時間差の中央値が、ランダム対照の中央値の **1/10 以下** | 同期は EIS 由来 |
| **E2** | E1 が成立したら、EIS の前後 ±k 標本を除いて記録器を回し直し、**同期が消えるか**（同一点で鳴る組が 0 になるか） | 消えれば 23 個体が使える |
| **E3** | E1 不成立なら「未解明のまま」と書く。次の候補を 1 つ挙げる | — |

## 答えないこと
- 同期が EIS 由来でも、記録器が「劣化」を捉えた証拠にはならない。E2 のあと改めて発火の独立性を見る
