# 334. 劣化具合は連続で出る。走行時間の 98% で読める

**ユーザ指摘(2026-09-07): 「これ、Sotifに参加できるの？ 劣化具合出せてないじゃん」**

[docs/331](331_assist_capability_results.md) はアシスト能力を 3 時点でしか出していない。
[docs/333](333_power_module_model_results.md) は記録から復元できることを示したが、
**連続で読めるかは書いていない。**受け手が使うには連続で必要である。

**これは仮説の検定ではなく記述である。**合否の基準は置かない。数字をそのまま出す。

実行: `python3 scripts/capability_trace.py` / 数表: [data/capability_trace.tsv](../data/capability_trace.tsv)

## 誰が計算するのか

**要素は能力を出さない。**バスに出るのは逸脱（自分のノイズの何倍か）だけである。
能力への換算は**受け手が行う**。係数は出荷時基準値にあり、追加の記録は要らない
（[docs/333](333_power_module_model_results.md)）。

**この分担は設計判断である。**能力を名乗るのは 7 つの禁止語の筆頭であり、
[docs/199](199_pulse_thermal_results.md)・[docs/203](203_cross_machine_replication_results.md) で一度取り下げてある。
**換算の前提を置いた側が、その数字の責任を持つ。**

## SOTIF のどこに使えるか

| 条項 | 使えるか | 理由 |
|---|---|---|
| **13 運用フェーズ** | **使える** | 13.3 Topics for observation の観測対象そのもの（[docs/267](267_sotif_conformance_results.md)）。**いま 2 値しかない解像度に、連続量を与える** |
| 13.4 事象の評価 | 使える | 再現しない事象に、その瞬間の記録を与える |
| **6.5 受容基準** | **使えない（入ってはならない）** | **この量が実際の機能低下と一致することを検証していない。**導通損しか見ておらず、故障直前でも 11% しか説明できない |

**「劣化具合が出る」と「受入判定に使える」は別である。**
出るのは**導通損から計算した残存率**であって、**測ったアシスト出力ではない。**

## 残る限界

- **単調ではない。**健全 run で 1.0 を上回る点が出る（最大 1.024）
- **Test_10 のばらつきが他の 7 倍**（0.0435）。出荷時基準値の当てはめが壊れている素子で、
  傾きの符号で弾ける（[docs/333](333_power_module_model_results.md)）
- **判定を出せた割合 98% は、この試験機での値。**電源が動く実車では下がる
  （10% の変動で 96% の時間は無言、[docs/327](327_supply_tolerance_results.md)）
- **50 秒ぶんをまとめている。**まとめる長さは私が決めた（[TROUBLES.md](../TROUBLES.md) T2）
- 単体 MOSFET・6 素子・1 試験機。**EPS ではない**

## Rule Check
- **「劣化具合が出る」ことと「受入判定に使える」ことを分けて書いた**
- **単調でないこと、健全 run で 1.0 を超える点があることを、良い数字と同じ表に書いた**
- 仮説の検定ではなく記述であることを、**合否の基準を置かないと明記して**書いた
