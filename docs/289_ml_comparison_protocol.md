# 289. 事前登録 — 機械学習は、この線形の当てはめより良いのか

> **ユーザ指摘(2026-09-02): 「機械学習モデルはできたの?」**
>
> **できていない。**[scripts/eps_health_recorder.py](../scripts/eps_health_recorder.py) が使うのは
> **直線1本の当てはめ、頑健な雑音尺度、分位点の閾値、同種チャネルの差分**である。
> **学習していない。**
>
> **そして「機械学習を使わない」と決めた記録が無い。**やらなかっただけである
> ([TROUBLES.md](../TROUBLES.md) T27 と同じ空白)。**決める。**

**追加取得ゼロ。** Bacha et al. inverter PMSM(取得済み)。

---

## 制約 — 何が使えて何が使えないか

**記録器は、出荷時に故障の例を持たない。**新品の個体は一度も壊れていない。
**したがって教師あり学習は使えない。**故障のラベルが存在しない。

> **比較できるのは、正常だけで学習する手法(one-class)である。**

| 手法 | 学習に使うもの |
|---|---|
| **現在の実装(線形)** | 正常のみ。直線1本 + 分位点 |
| Isolation Forest | 正常のみ |
| One-Class SVM | 正常のみ |
| Elliptic Envelope | 正常のみ |

**深層学習は含めない。**登録データが2,147点しかなく、
**[docs/282](282_igbt_recorder_results.md) の較正予算を考えれば、パラメータ数が標本数を上回る。**
**これは能力の判断ではなく、標本数の制約である。**

---

## 手順(実行前に固定)

**現在の実装と条件を完全に揃える。**

1. 入力は**同じ8チャネル、同じ同相除去、同じ動作点**([docs/286](286_common_mode_results.md))
2. 学習は**正常運転の前半のみ**。後半は保留
3. **誤報率を揃える。**各手法の閾値を、**正常の前半で同じ誤報率になるよう**決める
4. 評価は**保留した正常後半**(誤報)と**8つの故障**(検出)
5. **窓は同じ5秒。**特徴量は各窓の平均と最大(現在の実装と同じ)

---

## 判定基準(実行前に固定)

| # | 基準 | 閾値 |
|---|---|---|
| **L1** | 同じ誤報率で、検出が **8/8 を上回る** | 上回れないなら**線形で足りている** |
| **L2** | 保留した正常での誤報が、**線形と同等以下** | |
| **L3** | 学習した手法が、**48バイトに収まるか** | 収まらなければ**部品に載らない** |

**L1が「上回れない」で終わる可能性が高い。現在の実装は既に 8/8 である。**
**その場合、比較の意味は「機械学習が要らない」ことを数値で言えるようになることである。**
**これは negative な結果だが、空白を埋める。**

## この検定が答えないこと(先に書く)

- **故障は人為的に導入されたものである。**劣化ではない。R12は未達
- **1台のみ、8チャネル、故障8件。**機械学習の利点が出る規模ではない可能性がある
- **深層学習を試していない。**標本数の制約による。**性能の判断ではない**
- **L1が通っても、部品に載るとは限らない。**L3が別に要る
