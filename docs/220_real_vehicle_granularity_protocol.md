# 220. 実車ログで個体基準法の粒度を測る — 事前登録

**結果を1つも見る前に書き、単独でコミットする。**

## なぜやるか

本研究の中心的な方法は **「個体基準 + 動作点正規化」** である
([docs/163](163_per_unit_baselining.md), [docs/167](167_precursor_results_v2.md))。
しかしこれを試したのはすべて**試験装置のデータ**である——NASA MOSFET、KAIST PMSM、インバータ試験機。

**実車で試したことが一度も無い。**

EooC仮定シートの「宣言粒度」も、現在は **0.08〜1.0%** という**実験室の数字**しか持っていない
([docs/205](205_sign_free_deviation_results.md))。

commaSteeringControl(取得済み)は**実車の操舵ログ**である。4車種・3,499ログ。
**故障ラベルは無いが、方法そのものは試せる。**

## 測るもの(実行前に固定)

各ログ(1回の走行)について、制御が有効で運転者が介入していない区間のみを使う
(`latActive == True` かつ `steeringPressed == False`)。

```
残差   e = latAccelLocalizer − latAccelDesired      要求した横加速度と実測の差
粒度   g = 3 × 1.4826 × MAD(e)                      そのログ自身のノイズ床
```

**動作点正規化**は、速度と操舵角に対する1次回帰の残差を取る形で行う。

```
e_norm = e − (a·vEgo + b·|steeringAngleDeg| + c)     係数はそのログ内で推定
g_norm = 3 × 1.4826 × MAD(e_norm)
```

**係数はログごとに推定する。**これが「個体基準」である。

## 判定基準(いま固定する)

| # | 基準 | 閾値 |
|---|---|---|
| **R1 粒度** | 車種ごとの `g` と `g_norm` の中央値を報告 | **閾値なし。EooCシートに載る実車の数値** |
| **R2 動作点正規化は効くか** | `g_norm` の中央値が `g` より **10%以上小さい** | **4車種すべてで成立** |
| **R3 逸脱の裾** | `\|e_norm\| > g_norm` の標本率と、`max\|e_norm\|/g_norm` を報告 | **閾値なし** |

- **R2が落ちたら、動作点正規化は実車データでは効かなかったと書く。**
  試験装置で効いたこと([docs/167](167_precursor_results_v2.md) の 20〜300倍)は実車に移らないことになる
- **v2は作らない**

## 事前に認めておくこと(これが最も重要)

- **`latAccelLocalizer − latAccelDesired` はEPSの測定量ではない。**
  制御器の追従誤差、路面外乱、推定誤差をすべて含む。
  **「EPSがどれだけ応答したか」ではなく「要求どおりの横加速度が出たか」である**
- **故障ラベルが無い。**逸脱が出ても、それが故障かどうかは判定できない。
  **本検証は検出能力を測るものではなく、方法の粒度を測るものである**
- **車両IDが無い。**単位は「ログ(1回の走行)」であって「個体」ではない。
  同じ車の別の走行を同一個体として扱えない
- **4車種のみ**(HONDA CR-V 2016 / AUDI Q3 2nd gen / FORD Maverick 1st gen / GENESIS G70 2018)
- **openpilot搭載車のログである。**一般の車両分布ではない
- **1ログ601行。**サンプリング間隔は列に明示が無く、`t` 列から推定する

## Rule Check

- **残差がEPSの測定量でないことを、限界の先頭に置いた**
- 「検出能力ではなく粒度を測る」と目的を限定した
- 単位が個体ではなくログであることを明記した
- R2が落ちた場合に何と書くかを先に決めた
