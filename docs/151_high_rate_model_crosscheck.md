# 高率モデルと公開不具合記録の突き合わせ(答え合わせ3例目)

## 判断

**群シグナルの上位モデルは、公開の不具合記録と対応した。ただし対応先は2種類に分かれ、この区別こそが群監視の使い方を決める。**

| 型 | モデル(検査不合格率) | 公開記録との対応 |
|---|---|---|
| **① 公知の欠陥ファミリー** | Vauxhall Corsa(9.4%、全不合格の16.6%) | Corsa D世代(2006-14)の**電動パワステコラム故障が「非常に一般的な問題」として公知**(トルクセンサ/舵角センサの故障コード、**断続的なアシスト喪失**)。加えて公式リコール複数(ステアリング中間シャフト破断、2014-15年製のラック破損、Adam/Corsaのリコール拡大) |
| **② 用途起因の摩耗** | Vauxhall Vivaro(13.1%)/Renault Trafic(12.7%)——同一プラットフォームのバン | 支配的なのは**タイロッドエンドの摩耗**(縁石・段差の累積、バンの使われ方)。「MOTで初めて気づかれる」と整備情報に明記。リコールは締付トルク1件のみで、欠陥ではなく使用条件が主因 |

未照合: Fiat 500X/Jeep Renegade(8.8%前後、同一プラットフォーム対)は今回照合していない(推測で埋めない)。

## 根拠と含意

- **群監視の答え合わせは3例目も成立**: 盲検の集計上位が、独立の公開記録(既知問題・リコール・整備実務)と対応した。Ford(米・リコール)、GM(米・リコール)に続き、英国の検査データでも群シグナルは実体を指していた
- **ただし「何かがある」までしか言えない**: 上位に来る理由は欠陥(①)とは限らず使い方(②)でもある。切り分けには中身(故障モード)を見る必要がある——モード分類が要るというdocs/137の教訓が、3例目でも同じ形で出た
- **Corsa Dの症状記述は本研究のターゲットケースそのもの**: 「断続的なパワステ喪失、トルクセンサ系の故障コード」。米国の2リコール(Ford 15V-340、GM 17V-414)と合わせ、**3つの独立市場で同じ故障ファミリー**が観測された。電動パワステの断続的アシスト喪失は、一社・一国の問題ではなく製品カテゴリの構造的な弱点である——本研究の対象選定(電源・センサ系の断続事象)の妥当性がまた一段裏付けられた

## これで能動的な公開検証は打ち止め

軸2完了により、公開データで能動的に実行できる検証はすべて消化した。以後は観測台帳(受動)のみ:

| 観測項目 | 見るもの | 意味 |
|---|---|---|
| 競合動向 | Nexteer MotionIQ/Healthの採用・拡大・撤退 | 支払い意思の見立て(docs/146判断1)の検証 |
| 将来リコールera | 2025年以降の操舵系リコール蓄積 | リコール識別モデルの汚染なし3回目試験 |
| 新興メーカーの車齢 | BYD等が車齢3年超になる頃の英国データ再集計 | docs/149判断2の再検証(スクリプト保存済み) |
| 日本のOBD検査DB | NALTECの検査データ開放の有無 | 開放されれば一級のデータ源(現在非公開) |
| 規制の実装 | ISO 21448運用フェーズ/UNECE監視要求の具体化 | 窓の開閉(docs/146)の観測 |
