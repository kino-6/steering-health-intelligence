# 178. SOTIFへの直答 — 乗るのか、何を出すのか

**これまで5回に分けて部分的な答えを出し、はぐらかしになっていた。ここで直答する。**

## 問い

**この研究の成果は、SOTIFに乗るのか。乗るなら、具体的に何をどう出すのか。**

## 答え

**乗る。出せるものは1つだけ——[docs/153](153_sotif_eooc_assumption_sheet.md) のEooC仮定シートである。それ以外は無い。**

### なぜ「1つだけ」なのか

SOTIF(ISO 21448)は「**故障していないのに**性能限界で危険になること」を扱う。故障はISO 26262の担当である。
[docs/126](126_steering_predictive_diagnostics_sotif_contribution_prospect.md) は「SOTIFに乗る」を3つに分解し、2つを落とした。

| 意味 | 判定 |
|---|---|
| (a) SOTIFプロセス支援商品(分析代行・適合支援) | **No-Go**。既存業務に持ち主がいる |
| (b) SOTIF論証への部品側証拠 | **既存業務**。安全担当が既に出している。新商品ではない |
| (c) **運用フェーズのフィールド監視への部品側インプット** | **これだけが残った** |

そして規格上、(c)を部品側が差し出す形式は **SOTIF-EooC** ただ一つである([docs/128](128_steering_predictive_diagnostics_sotif_public_signal_watch.md))。
EooCは「使われ方の前提」と「機能不足の許容発生率」を仮定として置き、OEM統合時に検証する形式である。

**つまり「SOTIFに乗る」の具体物は、EooC仮定シート以外に存在しない。**

## 今、そのシートに何が書けるか

| 欄 | 状態 | 中身 |
|---|---|---|
| **使われ方の前提** | **埋まる** | 英国車検2,800万件の分母つき分布、車齢曲線(3年0.11%→20年で約40倍)、用途2型の分離([docs/148](148_dvsa_mot_denominator_verification.md), [149](149_concentration_ev_and_japan.md), [151](151_high_rate_model_crosscheck.md)) |
| **観測できる機能不足の粒度** | **埋まる。数値で** | 特徴量別の設計で応答遅れ0.3s / ゲイン0.10 / バイアス0.10 を90%検出。設計則は4車種で一致([docs/155](155_window_recurrence_verification.md)) |
| **検出できない領域** | **埋まる** | 遅れ0.1s、ゲイン2%は見えない。左右非対称は宣言しない([docs/144](144_synthetic_sensitivity_results.md)) |
| **実測に基づく劣化signature** | **埋まる** | 巻線間短絡severity 3.35%→21.69% で相電流不平衡が健全比2.4→4.0倍。同一個体のゆらぎは最大9.5%([docs/162](162_pmsm_model_validation_results.md)) |
| **機能不足の実測** | **部分的** | 前駆窓で持続アシスト熱余裕が13〜50%喪失([docs/170](170_thermal_headroom_translation.md))。**ただし計算であって測定ではない** |
| **許容発生率の目標値** | **空欄。OEMが埋める** | 車両レベル安全目標からの配分。公開情報では原理的に届かない |
| **物理モデルによる外挿** | **空欄。検証失敗** | 事前登録基準に不成立([docs/162](162_pmsm_model_validation_results.md)) |

**シートは19項目のうち、大半が埋まっている。** これが「SOTIFに出せるもの」の全部である。

> **訂正(2026-08-24、[docs/179](179_eooc_sheet_completion.md))**: **この評価は甘かった。**
> ISO 21448 Clause 4.4.3 が要求する3点セットのうち、**triggering conditions(発現条件)が丸ごと欠けていた**。
> 旧シートは「何を観測できるか」の監視仕様であって、「どの条件で機能が足りなくなり、OEMがどう検証するか」の宣言ではなかった。
> E節(発現条件5項目)とF節(統合要求2項目)を追加し、26項目にした。

## 判定を1文で

> **部品側が出せるのは「宣言した粒度で、実測した発生率はこれだけだった」という観測値までである。
> それが許容範囲かを判定するのはOEMの領域であり、部品側は踏み込まない。**

**この境界を守ることが、SOTIFに乗る条件である。** 越えれば(a)(b)に戻り、既存業務の持ち主と競合して負ける。

## SOTIFに乗せてはいけないもの(混同の履歴)

私は5回、SOTIFと別のものを混ぜた。整理して固定する。

| 混ぜたもの | 実際は | 出典 |
|---|---|---|
| MOSFET前駆検知の実証 | **ISO 26262**(faultの前駆) | [docs/169](169_sotif_link_check.md) |
| 熱余裕13〜50%喪失 | SOTIFに翻訳できたが**計算であって測定ではない** | [docs/170](170_thermal_headroom_translation.md) |
| 「接点系にはSOTIFの窓が無い」 | **誤り**。窓は公開リコールに明記(断続・回復・再発) | [docs/176](176_correction_degradation_window.md) |
| 「需要は確定、席が埋まった」 | 需要は確定だが**席は別の席だった**(下記) | 本ドキュメント |

## 競合は、この席を取っていない

[docs/177](177_sotif_direction_update.md) で「席が埋まり始めた」と書いたが、**Nexteer MotionIQ/Health の公式仕様を読むと、取られた席は別である。**

| 項目 | Nexteer MotionIQ/Health(公式リリース) |
|---|---|
| 監視対象 | 操舵・シャシ部品・**タイヤ**の電気的/機械的機能 |
| 手法 | 予知ソフトウェア + **AI仮想センサ** |
| 主張 | 「**問題が起きる前に予測する**」 |
| 顧客価値 | **フリート稼働率、整備計画、診断時間・費用の削減** |
| 副次 | 匿名化ライフサイクルデータを製品品質・コスト削減へ |
| 準拠 | 開発プロセスが**ISO 26262 ASIL D**、ASPICE評価済 |
| **ISO 21448 / SOTIF への言及** | **なし** |

**Nexteerが取ったのは「予知保全・フリート稼働率」の席であり、ISO 26262の枠内である。SOTIFを名乗っていない。**

そして重要な含意が2つある。

1. **SOTIF-EooCの席は、まだ空いている。** [docs/177](177_sotif_direction_update.md) の「席が埋まった」は**別の席についての観察**だった
2. **Nexteerの製品は、本研究の中心主張を否定するのではなく裏づけている。**
   [docs/143](143_recall_detection_results_v2.md) が不成立としたのは「**公開苦情データによる**故障予測」であり、
   [docs/145](145_final_conclusions_and_interpretations.md) は「この情報は部品メーカーにしか取れない」と結論していた。
   Nexteerは**部品内部から**やっている。**主張どおりのことが、実際に量産で成立した**

## それでも楽観しない

- Nexteerは予知保全の席を取り、**同じサプライヤ内の資産(部品内部の観測)でSOTIF側へ横に伸ばせる位置にいる**。空席は空席のままとは限らない
- [docs/177](177_sotif_direction_update.md) の指摘は有効: **EOL論拠は対OEM基盤には効くが、対他EPSサプライヤには効かない**
- 規制(UN ADS GTR、2026-06採択)の対象は**ADS搭載車**であり、一般の人間運転車のEPSには及ばない
