# Predictive Value Next Items Deep Dive

## 結論

手持ちIDのうち、次に深掘りする価値があるものは3つに絞れる。

最初は、駐車場走行で低速・大舵角・凹凸が重なる使われ方を、製品企画向けと診断企画向けに分けて見せる。
これは `ULC008` である。

次に、荒れた路面と操舵入力が重なる使われ方を、品質改善と顧客技術説明の入口として見る。
これは `ULC004` である。

最後に、通信異常があるときにEPS故障と誤認しないための境界材料を作る。
これは `PVC004` である。

3つとも、現時点では外販商品ではない。
EPSサプライヤ内で、製品企画、診断企画、品質改善、評価企画、サイバー担当が「自分たちの判断に使える」と言えるかを見るためのサプライヤ内検証材料である。

## 何を判断しているか

判断しているのは、公開proxyからEPS故障、残寿命、交換時期を予測できるかではない。

判断しているのは、公開proxyから見える使われ方や異常contextを、EPSサプライヤの業務判断に使える形へ変換できるかである。

今回の3アイテムは役割が違う。

| Item | 役割 | 初期利用者 | 現時点判断 |
|---|---|---|---|
| ULC008 | 用途別の使用負荷classを、製品企画・診断企画で使えるかを見る | 製品企画、診断企画 | Continue as first review sample |
| ULC004 | 路面外乱と操舵入力の組み合わせを、品質改善・顧客説明に使えるかを見る | 品質改善、評価企画、顧客技術説明 | Continue as second sample |
| PVC004 | 通信異常時にEPS故障と誤認しないための境界を作れるかを見る | 診断企画、サイバー担当 | Hold as boundary artifact |

## ULC008: 製品企画向け / 診断企画向け

ULC008は、前回まで「駐車場走行で低速・大舵角・凹凸が重なる使われ方」として整理していた。
今回、それを製品企画向けと診断企画向けに分けた。

作業表は [data/pvc001_ulc008_two_department_sheets.tsv](../data/pvc001_ulc008_two_department_sheets.tsv) である。

### 製品企画向け

製品企画に見せるものは、故障や診断ではなく用途別価値説明である。

市場需要:

都市配送、駐車操作が多い車両、狭い市街地、駐車場内の低速移動が多い用途では、低速取り回しや路面外乱下の操舵感が価値説明になり得る。

仮説:

低速、大舵角、操舵頻度、凹凸/振動proxyを組み合わせると、駐車場相当の使用負荷classを作れる。
このclassがあると、EPSサプライヤは「どの用途で低速取り回し価値を説明すべきか」を整理できる。

Proceed条件:

- 既存カタログやRFQ回答にはない、用途別の使われ方説明に使える
- 「故障しにくい」ではなく「低速取り回し時の体感・説明しやすさ」として話せる
- 製品企画が、次に見たい用途や車両タイプを具体名で挙げられる

Kill条件:

- 既存の低速取り回し説明と同じで、新しい判断が増えない
- 故障しにくさ、寿命、保証費削減に寄せないと価値が説明できない
- 用途別価値に転記できない

### 診断企画向け

診断企画に見せるものは、故障予測ではなく、DTCやfreeze frameだけでは説明しにくい使用contextの補助である。

市場需要:

駐車時の操舵感、音、振動、違和感は、DTCがない場合やDTCがあっても使用contextが粗い場合に、説明が難しくなりやすい。

仮説:

低速・大舵角・凹凸という使用context labelがあれば、EPS異常と路面外乱由来の体感を混同しない説明境界を作れる可能性がある。

Proceed条件:

- 既存DTC / freeze frame / extended dataだけでは使用context説明が粗い
- 診断読み順や顧客説明境界に使える
- DTC追加ではなく、既存診断結果の読み方や説明境界として扱える

Kill条件:

- 既存DTC / freeze frame / extended dataで十分に説明できる
- DTC追加、故障予測、保証判断に寄せないと使い道がない
- 顧客説明に使うと責任転嫁や原因断定に見える

## ULC004: 荒れた路面 + 操舵

ULC004は、荒れた路面と操舵入力が重なる使われ方である。

作業表は [data/ulc004_rough_road_steering_deep_dive.tsv](../data/ulc004_rough_road_steering_deep_dive.tsv) である。

ULC004は、ULC008よりも製品企画には刺さりにくい。
一方で、品質改善、評価企画、顧客技術説明には刺さる可能性がある。

市場需要:

荒れた路面、段差、連続振動、操舵入力が重なると、音、振動、操舵感、違和感が出やすい。
サービス現場や顧客説明では、路面由来の体感とEPS異常が混ざりやすい。

仮説:

路面・振動proxyと操舵要求proxyを組み合わせると、荒れた路面で操舵入力が重なる使用負荷classを作れる。
このclassは、品質改善や顧客技術説明で、原因断定せずに使用contextを整理する入口になる。

Proceed条件:

- 品質改善が、field issueを使用条件別に読み直す入口として使える
- 顧客技術説明が、路面外乱由来の体感とEPS異常を混同しない説明に使える
- 評価企画が、既存評価の代表性やgap確認に使える

Kill条件:

- 路面分類productに流れる
- 既存NVH/耐久/評価scenario名の言い換えにしかならない
- 荒れた路面がEPS故障原因だと読まれる
- EPS内部状態、内部劣化、thermal limitを推定した扱いになる

現時点の判断:

ULC004は、次に深掘りする価値がある。
ただし、ULC008が製品企画・診断企画のどちらにも刺さらない場合、PVC001全体が弱くなるため、ULC004だけを単独で追いすぎない。

## PVC004: 通信異常context

PVC004は、通信異常があるときにEPS故障と誤認しないための境界材料である。

作業表は [data/pvc004_communication_boundary_deep_dive.tsv](../data/pvc004_communication_boundary_deep_dive.tsv) である。

市場需要:

CAN DoS、spoofing、fuzzy attack、steering wheel spoofingのような通信異常があると、EPS診断値、操舵関連signal、顧客説明、安全主張が混乱しやすい。

仮説:

通信異常contextを先に分類できれば、EPS故障と通信異常を誤認しないための診断信頼性境界を作れる。

これは汎用cyber商品ではない。
SbW安全証明でもない。
EPS品質証拠でもない。

使い道:

- 診断企画が、通信異常時にDTCやfreeze frameをどこまで信用してよいかを整理する
- サイバー担当が、既存CSMS/TARA/SOC/IDSとEPS診断説明の境界を整理する
- 顧客技術説明が、通信異常とEPS故障を混同しない禁止主張を持つ

Proceed条件:

- EPS診断説明や診断読み順に転記できる
- 汎用IDSではなく、EPS診断値の信頼性境界として扱える
- 言ってよいこと / 言ってはいけないことを明確に分けられる

Kill条件:

- 汎用IDS、CSMS、TARA、SOC運用の言い換えにしかならない
- EPS診断説明に転記できない
- SbW安全証明やEPS品質証拠として使おうとする

現時点の判断:

PVC004はHoldのまま残す。
ULC008やULC004と違い、製品価値の本線ではない。
ただし、禁止主張を作る材料としては有用である。

## EPSサプライヤとしての言い方

言ってよいこと:

> 公開proxyだけではEPS内部状態や残寿命は分からない。ただし、低速・大舵角・凹凸、荒れた路面と操舵、通信異常contextを分けて整理すれば、製品企画、診断企画、品質改善、顧客技術説明で使える可能性がある。まずはサプライヤ内レビューで既存業務との差分を確認する。

まだ言ってはいけないこと:

> 使用負荷classからEPS故障、残寿命、交換時期、保証費削減、安全性が分かる。

> 駐車操作、低速高操舵、荒れた路面、通信異常がEPS故障原因である。

> 公開proxyからEPS内部stress、thermal limit、assist limitation、DTC不足を断定できる。
