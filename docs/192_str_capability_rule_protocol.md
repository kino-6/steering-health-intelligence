「劣化から capability 値をどう決めるか」——を埋めるための規則を、実行前に固定する。

## 何を証明しに行くか

| 問い | 何が示せれば証明か |
|---|---|
| **問1. 入庫時に劣化状態が分かることに需要があるか** | 従来型の監視が「異常なし」と言っている**間に**、実現できる能力が測定可能な幅で縮んでいること。縮んでいるのに返された車が実在する([docs/190](190_assembly_replacement_meaning.md) の134万台)以上、その窓の存在が需要の存在である |
| **問2. DTC未到達の通知はSOTIFか** | 同上の窓が**実データで空でない**こと。故障は立っていないのに実現できる能力が減っている状態が、実測で観測できること |

**両方とも同じ1つの量に帰着する——「故障判定が鳴る前に、capability がどれだけ縮むか」。**

## capability の定義

AUTOSAR VMC の `STR capability` は「指定時間内に実現できる値」であり、性能の包絡線である([docs/183](183_autosar_capability_channel.md))。
EPSで持続アシストを縛るのは熱である。パワー段は接合部温度を上限以下に保たねばならない。

```
Tj - T_amb = P_loss * Rth,      P_loss ≒ I^2 * R_on   (導通損支配)
  =>  I_max = sqrt( (Tj_max - T_amb) / (Rth * R_on) )
  =>  実現できるアシストトルク  ∝  I_max  ∝  1 / sqrt(R_on)
```

個体自身の基準に対する比として:

> **C(t) = sqrt( R̂_on(base) / R̂_on(t) )**

R̂_on は個体ごとに温度正規化した導通抵抗([docs/167](167_precursor_results_v2.md) v2の方法:
基準窓で `R_on = a*T + b` を当て、run 1 の基準温度で残差を評価する)。

**比を取ると Rth・Tj_max・T_amb が消える。**

> **重大な訂正(2026-08-26, [docs/199](199_pulse_thermal_results.md))**: この文書が使った `Vds/Id` は**オン抵抗ではない。**
> 素子は能動領域にあり(供給5.61Vのうち約4.9Vを負担して13Wを捨てている)、試験機は一度もスイッチとして動かしていない。
> **`C = √(R_base/R_on)` は導通損から導いた式であり、このデータはその物理を測っていない。**
> ここでの C は**劣化指標であって能力比ではない。**個体基準の有効性([docs/167](167_precursor_results_v2.md))は観測量に依存しないので残る。

[docs/189](189_five_limits_tested.md) ② で熱抵抗の直接測定に失敗したにもかかわらず
この規則が公開データで計算できるのは、この打ち消しによる。

## 宣言する仮定(そのままEooCシートの行になる)

| # | 仮定 | 外れたときの向き |
|---|---|---|
| A | 損失は導通損支配。スイッチング損は含めない | スイッチング損が効くと C は実際より楽観 |
| B | **Rth は寿命を通じて一定** | ダイアタッチも劣化すると実際の能力は C より**速く**落ちる。**C は上限＝楽観側** |
| C | Tj_max と T_amb は基準時と評価時で不変 | 環境が厳しいと C は楽観 |

**仮定Bは安全に関わる向きである(楽観側)。宣言しないまま使ってはならない。**

## 手順(固定)

- **基準窓**: 各デバイスの run 1〜3。[docs/166](166_precursor_results_v1.md) で既に固定済みの境界を動かさない
- **宣言粒度 g**(個体ごと): 基準窓における C の標準偏差の3倍。**g 未満の変化について、この規則は何も宣言しない**
- **縮小の検出**: `C(r) < 1 - g` を満たす最初の run r。ただしそれ以降の全 run でも下回り続けること(単調持続)。
  runが7点しかないため k-of-N は使わない

## 比較対象(公平性のため3種を並べる)

個体基準の寄与だけを取り出すため、温度補償の有無で分ける。

| 監視 | 温度係数 | 判定基準 |
|---|---|---|
| **M0 素朴** | なし(生の R_on) | 母集団閾値 |
| **M1 母集団補償** | **全デバイス共通**の係数(基準窓をプールして推定) | 母集団閾値 |
| **M2 本規則** | **個体ごと**の係数 | **個体自身の基準** |

母集団閾値 = 全デバイスの基準窓をプールした R_on の `median + 3 * 1.4826 * MAD`。

**主基準は M1 との比較で取る。** M0 に勝つのは温度補償の効果であって、本研究の主張(個体基準)ではない。

## 合否基準(いま固定する)

| # | 基準 | 閾値 |
|---|---|---|
| **P1 窓の存在** | M2 が M1 より**1 run 以上早く**鳴る | **6デバイス中4以上** |
| **P2 窓が雑音でない** | M2 が鳴った run での capability 低下量が、宣言粒度 g の**3倍以上** | **6デバイス中4以上** |
| **P3 宣言できる粒度** | 全6デバイスの g を報告する | **閾値なし。これがEooCシートに載る数値** |

副次(合否にしない、報告のみ):

- 最終 run での C(故障時点で能力がどこまで落ちていたか)
- M1 / M0 が最終 run より前に一度でも鳴るか
- M2 が鳴ってから最終 run までの run 数(窓の長さ)

## 事前に認めておくこと

- **run は粗い時間分解能である。**「1 run 早い」が実時間で何時間かはこのデータからは言えない。
  窓の**存在**は示せるが、**長さを時間で**は言えない
- **デバイスは6個である。**6個で母集団閾値を作るのは統計的に薄い。母集団閾値の値そのものは
  信頼区間を持たない点推定であり、そう報告する
- **これは MOSFET であって EPS ではない。**同型の機構(パワー段の導通抵抗上昇)であることが根拠であり、
  EPS実機での確認ではない([docs/167](167_precursor_results_v2.md) と同じ限界)
- **v2 は作らない。**失敗したら失敗として記録する
