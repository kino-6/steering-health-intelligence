# 07. Market Needs and Positioning

## Core Realization

これまでの整理で重要なのは、以下である。

> 市場は「ログを増やしてほしい」とは思っていない。
> 市場が欲しいのは、不具合・保証・稼働停止・責任分界に関する意思決定を早くすることである。

したがって、以下は単体ではビジネス価値になりにくい。

- Extended Dataを増やす
- Freeze Frameを増やす
- NVM証跡を増やす
- DTC未満イベントカウンタを増やす
- AIで原因分類する

これらはすべて手段であり、利用先が定義されていない場合は「ログを増やしました」に見える。
OEMから見ると、設計コスト、ECUリソース、診断通信量、解釈責任が増えるだけに見える可能性がある。

## What the Market Actually Wants

EPS / ステアリングECUの文脈で、市場側の要求に近いものは以下である。

### 1. No Trouble Foundを減らしたい

市場から以下のような案件が返ってくる。

- EPS警告が出た
- 一時的に操舵が重かった
- 操舵違和感があった
- DTCはあるが原因が分からない
- DTCは消えており再現しない
- 返却品を調べても異常が再現しない

このとき、価値があるのは「ログが多いこと」ではない。

価値があるのは、調査不能案件を以下のように振り分けられることである。

- 電源起因の可能性
- 熱制限起因の可能性
- センサ冗長差起因の可能性
- モータ電流追従起因の可能性
- 一時的な外部条件起因の可能性
- ソフトウェア / キャリブレーション差分確認が必要
- 追加データが必要

### 2. 保証費・市場品質コストを下げたい

OEM / Tier1にとって、保証対応や市場品質対応では以下が重い。

- 原因不明案件の調査工数
- 再現試験の繰り返し
- 不要な部品交換
- サプライヤ間の責任分界議論
- 品質会議用の説明資料作成
- 次期設計へのフィードバック不足

したがって、本件の価値は故障予測精度ではなく、以下で測るべきである。

- 原因候補を何個まで絞れるか
- 初動解析時間を何日短縮できるか
- No Trouble Foundをどれだけ減らせるか
- 返却品解析の成功率を上げられるか
- OEM / Tier1間の責任分界議論を短縮できるか

### 3. DTCを「次のアクション」に変えてほしい

DTCやFreeze Frameは、それだけでは価値が弱い。

市場品質やサービスエンジニアリングが欲しいのは、例えば以下である。

- これは電源系を先に確認すべき
- 熱制限の文脈で説明できる
- センサ冗長差の履歴を見るべき
- ECU内部より車両側条件を疑うべき
- ソフトウェア / キャリブレーション版数で群比較すべき
- 追加でこのデータを取得すべき

つまり、本件の本質は「診断データの追加」ではなく、DTC発生後の調査判断を早くすることである。

## Better Positioning

従来の表現:

> Steering Diagnostic Evidence Package

これは悪くないが、まだ「ログ / 証跡を増やす」側に見えやすい。

より市場要求に近い表現:

> Steering Field Issue Triage Package

または:

> EPS No-Trouble-Found Reduction Package

ただし、`No-Trouble-Found Reduction` は価値が明確な一方で、効果保証に見える可能性がある。
初期提案では、以下がバランスしやすい。

> EPS Field Issue Triage Evidence

## Proposed Value Proposition

本件の価値提案は、以下のように置く。

> EPS / ステアリングECUの市場不具合において、DTCだけでは原因候補を絞れない、再現しない、返却品から分からない、責任分界が長引く、といった問題を減らすために、原因候補分類と次アクションに直結する診断エビデンスを提供する。

重要なのは、エビデンスそのものではなく、以下の判断を支援することである。

- どの原因候補を優先して調べるか
- ECU起因か、車両側 / 電源側 / 使用条件側か
- 返却品解析で何を見るべきか
- 追加ログや追加試験が必要か
- 品質会議でどう説明するか

## What to Build First

信号リストを先に作るより、まず市場不具合シナリオごとの処理フローを作るべきである。

必要な表:

| Field | Meaning |
|---|---|
| scenario | 市場で起きる症状やDTC |
| current pain | 現状なぜ困るか |
| current decision blocker | 何が判断できないか |
| triage decision | 早めたい判断 |
| required evidence | その判断に必要な証跡 |
| next action | 証跡から導く次アクション |
| value metric | 何で価値を測るか |

例:

| scenario | current pain | triage decision | required evidence | next action | value metric |
|---|---|---|---|---|---|
| 一時的なアシスト低下 | 再現せず原因不明 | 熱制限か電源低下か制御異常か | 電圧、温度、assist limitation state、直近イベント | 電源系点検、熱条件確認、追加ログ依頼 | 初動解析時間 |
| EPS警告後にDTCなし | 返却品で異常なし | DTC未満イベントがあったか | DTC未満カウンタ、復帰履歴、最新イベント | NTF扱いにせず条件付き再現試験へ | NTF削減 |
| センサ系DTC | 冗長差の原因が不明 | センサ劣化か一時ノイズか | 冗長差ピーク、発生回数、温度、電圧 | センサ系重点解析または外部ノイズ確認 | 原因候補数 |
| 電流追従系DTC | モータ / 制御 / 電源の切り分けが難しい | 電流追従異常の文脈を確認 | 目標電流、実電流、偏差ピーク、電圧、温度 | モータ系、電源系、制御条件を優先度付け | 再現試験工数 |

## What Not to Claim

避けるべき主張:

- EPS故障を予測できる
- 市場車両群のリスクをサプライヤ単独で監視できる
- リコール対象を自動で絞れる
- 保証判断を自動化できる
- ログを増やせば価値が出る
- AI分類が主価値である

## Current Best Framing

現時点の一番強いフレーミング:

> EPS市場不具合の再現なし・原因不明・責任分界不明を減らすための Field Issue Triage Evidence。

短く言うなら:

> DTCを、原因候補と次アクションに変える。
