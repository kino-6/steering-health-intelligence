# 21. Value of NTF / Return-Part Case Classification

## Purpose

仮に、過去20-50件のEPS返却品・市場不具合・NTF・再現不能案件を分類できたとする。

このとき何が嬉しいのかを明文化する。

結論:

> ケース分類そのものが価値ではない。価値は、品質保証・診断設計・顧客品質報告・OEM提案・事業判断の曖昧さを減らすことにある。

## What Becomes Clear

20-50件を分類できると、少なくとも次が見える。

| 見えるもの | 意味 |
|---|---|
| 解析不能の型 | 何が分からなくて止まったのか |
| DTCの効き具合 | DTCだけで進んだ案件と、進まなかった案件の差 |
| freeze frame / extended dataの不足 | 既存診断データがどこで足りなかったか |
| NTFの主要パターン | 本当に多い困りごとがどれか |
| ECU-localで補える余地 | OEMデータなしでも残せる証跡があるか |
| OEMデータ依存の境界 | サプライヤ単独では無理な領域 |
| 次期診断仕様の候補 | NVM制約内で入れる価値がある項目 |
| やらない判断 | 追加証跡を入れても価値が薄い領域 |

## Who Is Happy

### 1. Warranty / return-part analysis team

嬉しいこと:

> 返却品が正常に見える案件で、毎回ゼロから悩まなくてよくなる。

Before:

- DTCはあるが、返却品単体では再現しない
- freeze frameが読めても、調査方針に落ちない
- 電源、熱、センサ、機械負荷、使われ方のどれを疑うべきか属人的
- `NTF` として処理するしかない案件が多い

After:

- 似た過去案件の型に当てられる
- 解析不能の理由を分類できる
- `何が分からないか` を言語化できる
- 次に確認すべきデータや試験を絞れる

欲しい感情:

- 毎回ゼロから炎上しない安心
- 調査方針を説明できる自信
- `分からない` を構造化して言える納得感

### 2. Customer quality / OEM response team

嬉しいこと:

> 顧客品質報告で、断定ではなく、確認済み事実・未確認事項・追加調査方針を整えて出せる。

Before:

- 顧客から追加説明を求められる
- DTCだけでは発生状況が弱い
- 返却品単体で再現しないと説明が薄くなる
- 原因断定すると責任問題になるが、何も言わないと弱い

After:

- `確認できたこと` と `確認できていないこと` を分けられる
- 低電圧、熱、センサ、一過性異常などの調査仮説を示せる
- OEMに要求すべき追加データを具体化できる
- 顧客品質報告の質を揃えられる

欲しい感情:

- 顧客前で説明できる防御力
- 過剰に責任を引き受けない安心
- 追加調査依頼を具体的に出せる主導権

### 3. Diagnostic engineering team

嬉しいこと:

> 次期DTC / freeze frame / extended data設計で、何を入れるべきかの根拠ができる。

Before:

- 追加したい信号はたくさんあるが、NVM制約がある
- どの項目が返却品解析に効くか分からない
- OEMに診断仕様変更を提案する根拠が弱い
- 既存診断の改善が、設計者の経験頼みになりやすい

After:

- `過去50件中、何件でこの証跡があれば調査が進んだか` と言える
- 残すべき証跡に優先順位が付く
- 追加しない項目の理由も説明できる
- OEMとの診断仕様協議に持ち込める材料ができる

欲しい感情:

- 診断仕様の改善提案に根拠がある自信
- NVM制約の中で選ぶ納得感
- OEMと議論するときの手札

### 4. Supplier quality / commercial quality team

嬉しいこと:

> 責任分界やchargebackの議論で、少なくともサプライヤ側の解析努力と限界を示せる。

Before:

- 部品単体では再現しないが、顧客側は不具合扱いする
- 周辺条件の可能性を主張しても証拠が弱い
- サプライヤ責任か車両側条件かの議論が曖昧
- 解析不能がそのまま弱い立場になる

After:

- サプライヤECUで確認できる証拠と限界を分けて提示できる
- OEMデータがないと判断できない領域を明確にできる
- 今後の診断仕様改善や追加データ要求につなげられる
- `何を調べたが、何は分からない` を残せる

欲しい感情:

- 不利な断定を避けられる安心
- 交渉時の最低限の防御材料
- 次の改善に進める建設感

### 5. Business / product planning team

嬉しいこと:

> この事業仮説を続けるか、やめるか、別方向に切るかを判断できる。

Before:

- `EPS embedded evidence` が既存診断の言い換えかどうか曖昧
- 顧客が本当に困っているか分からない
- 何をデモすれば価値が伝わるか分からない
- OEM領分に踏み込みすぎている可能性がある

After:

- 追加証跡で改善し得る案件の割合が見える
- OEMデータなしで価値が出る領域と、出ない領域が分かる
- 最初の商品が、SaaSではなく設計支援・内部解析支援か判断できる
- PoCの成功条件と撤退条件が作れる

欲しい感情:

- 技術案ではなく事業判断ができる納得感
- 筋が悪いなら早くやめられる安心
- 続けるなら、最初の顧客価値を絞れる明瞭さ

## Concrete Outputs

20-50件の分類後に出すべき成果物は、単なる一覧ではない。

| Output | Why it matters |
|---|---|
| NTF / 再現不能パターン分類 | どの困りごとが多いか分かる |
| DTC sufficiency matrix | DTCだけで足りる/足りない案件を分ける |
| Missing evidence heatmap | 電源、熱、センサ、制御努力、使用条件、一過性異常の不足頻度を見る |
| ECU-local vs OEM-data boundary | サプライヤ単独で補える領域を切る |
| Top 5 evidence candidates | NVM制約内で残す価値が高い候補を出す |
| Customer-quality fact template | 顧客品質報告で使う確認済み事実・未確認事項の型 |
| Diagnostic spec proposal | 次期DTC / freeze frame / extended data改善案 |
| Kill / continue judgment | 事業仮説を続ける条件と撤退条件を決める |

## What Would Make It Valuable

分類結果に価値があると言える条件:

1. 20-50件中、一定数で `DTCはあるが解析方針が立たない` 案件がある
2. そのうち複数件で、同じ不足証跡カテゴリが繰り返し出る
3. 不足証跡の一部がECU-localで保存可能である
4. 追加候補がNVM制約内に収まる
5. その証跡が顧客品質報告や返却品解析の初動判断に使える
6. OEMデータが必要な場合でも、要求すべきデータを具体化できる

## What Would Kill The Idea

分類結果で次が見えたら、この方向は弱い。

1. NTF / 再現不能案件がほとんどない
2. 解析不能の理由が毎回バラバラで再利用性がない
3. 足りない証跡がほぼOEM側データだけである
4. 既存freeze frame / extended dataで十分だった
5. 追加証跡を残しても顧客品質報告の内容が変わらない
6. NVMや診断仕様の制約で実装余地がない
7. 品質保証チームがその分類を業務で使わない

## One-Line Value Proposition

> EPS返却品・NTF・再現不能案件を20-50件分類し、解析が止まる理由と不足証跡を見える化することで、サプライヤがOEMに丸投げせず、診断仕様改善・顧客品質報告・追加データ要求・事業継続判断に使える手札を作る。
