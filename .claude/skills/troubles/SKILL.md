# 過去トラブルの型を当てる

**2026-09-01 ユーザ指摘: 「正直人間側が指摘できない」。**
**したがってこの検査は、指摘されてからではなく、結論を書く前に自分で回す。**

登録簿は [TROUBLES.md](../../../TROUBLES.md)。**個別の事象ではなく、下の26の型を当てる。**
型のうち5つは既に2回以上起きている。

## 使うとき

- **結果文書(docs/NNN_*_results.md)を書く前**
- **ユーザに報告する前**([report](../report/SKILL.md) と併せて使う)
- **データセットを採用/除外する判断をする前**

## 検査 — 上から順に当てる

### まず最多の型から(6回。**毎回ユーザに指摘されて判明している**)

- [ ] **T14 「無い・使い切った・網羅した」と早く言い切っていないか**
  - **「無い」と書く前に、探索の軸を1つ変えてもう一度探したか。**3回とも、軸を変えたら出てきた
  - **「無い」ではなく「この軸では見つからなかった」と書いたか。**主語は探索であって世界ではない
  - **データが「使えない」と書く前に、壊れたのが導出なのかデータなのかを特定したか**
  - 過去のKill記録を、再調査を断る根拠にしていないか
  - **欠落を報告の締めにしていないか。**事実として書くのは可、締めにするのは不可(0条)
  - **「いくらか」で答えが出ないなら、「いくらであれば足りるか」に問いを裏返したか**

### 次に、機械が止められないもの(判断が要る)

- [ ] **T1 試験機の操作を、対象の性質と取り違えていないか**(過去4回)
  - 設定値の**軌跡**を全期間見たか。**そして軌跡上のどこにいるかまで合わせたか**
  - 「同じ温度」は「同じ動作点」ではない。掃引の上限が違えば、同じ値でも軌跡上の位置が違う
- [ ] **T2 自分で決めた仮定を、根拠として報告していないか**(過去2回)
  - **その数値表の軸(範囲・刻み・条件)を誰が決めたか、1行で言えるか**
  - 自分が決めたなら、**現場データか物理で検定できないか**を先に考えたか
  - できないなら、報告に「この範囲は仮定である」と書いたか
- [ ] **T4 観測量を取り違えていないか**(過去2回)
  - その量は、**名前が示すものと同じか**。分母・分子に何が入っているか言えるか
  - 記録されていない量(外部熱流・周囲温度)を、暗黙に定数と仮定していないか
- [ ] **T5 スキーマ一致を機構一致と取り違えていないか**(過去1回)
  - 「その量が記録されている」と「**その量の劣化で壊れる**」は別。配布論文の機構節を読んだか
- [ ] **T6 集計の照合が緩くないか**(過去2回)
  - 台数・件数を出す前に、**上位数件の本文を目視した**か
- [ ] **T7 適用範囲を超えて数値を持ち出していないか**(過去1回)
  - 引用した数値の**測定条件を、同じ文の中に書いた**か
- [ ] **T12 根拠なく自責していないか**(過去1回)
  - 「防げた」と書く前に、**その時点で公開されていた情報だけで判断できたか**確認したか
- [ ] **T13 誤って除外していないか**(過去1回)
  - 注意書きが**どのチャネルに掛かっているか**確認し、**実際に開いて空か見た**か

- [ ] **T15 母集団基準で較正していないか**(過去2回)
  - その基準は「**この個体の**」ものか「母集団の」ものか、文中で明示したか
  - 個体差は測定ノイズの159〜530倍、劣化変化の8.4倍ある
- [ ] **T16 ユーザの言葉を自分の語彙に翻訳して取り違えていないか**(過去2回)
  - 翻訳したなら、**翻訳したことを明示して確認**したか
- [ ] **T17 事後の層別・後付けの説明で救っていないか**(過去2回)
  - 事後なら「事後である」と書き、**事前登録どおりの判定を正式なものとして残した**か
- [ ] **T19 手元にある根拠に、設計が従っているか**(過去1回。**T14より危険**)
  - 根拠を引用した設計項目について、**引用した文がその設計を支持していると1文で言えるか**
  - 「持続する事象が4倍多い」を引いて「だから窓は5秒」と書いていないか
- [ ] **T21 反証条件が、公開情報だけで確かめられるか**(過去1回)
  - 「崩れる条件」を、**公開情報だけで確かめる手順を1文で言えるか**
  - 言えないなら、それは反証条件ではなく**内部情報の要求**である(1条)
  - **崩れる向きが正しいか。**その条件で本当に結論が反転するか
- [ ] **T18 自分の主張の強さを過大評価していないか**(過去2回)
  - その数値は**何の不確かさ**か。分解能・確度・再現性・個体差は別物である

  - **「答え」の節に、問いへの答えが書けているか。**自分の作業の話になっていないか

## 新しい失敗が出たら — 書き込みは自動である

**手で書き足す必要はない。**`scripts/sync_troubles.py` が pre-commit hook から走り、
訂正・撤回・不成立を宣言した文書を **[TROUBLES.md](../../../TROUBLES.md) の「未分類」節に自動で書き込み、stage する。**

**残っている仕事は1つだけ: その行を型に振り分けること。**
`check_repo.py` の `troubles classified` が、**未分類の行が残っている間はコミットを止める。**

- **既存の型に当てはまるなら、その型の表に移し、回数を増やす**
- **当てはまらないなら、新しい型を立てる**。型が増えたことは、この検査が働いた証拠である
- **事前登録どおりの不成立なら、「事前登録どおりの不成立」節へ移す。**トラブルと混ぜて数えない

## 参照も自動である

`scripts/troubles_digest.py` が SessionStart hook(`.claude/settings.local.json`)から走り、
**セッションの最初に型の一覧が文脈に入る。**この Skill を思い出す必要はない。

## この検査の限界

- **登録簿にあるのは、気づけた失敗だけである。**気づけていない型は、ここに無い
- **T1は、是正手順を守った上で4回目が起きた。**チェックリストは万能ではない
